## 준비

- 항목의 `어디로`는 어긋난 변이의 실패 출력 전체를 스크래치 파일로 남기는 것과, 선택 인자 하나로 표지 후보가 될 단언 풀이 줄을 모두 보여 주는 것 둘 가운데 하나다. 파일로 남기는 쪽을 골랐다. 단언 풀이 줄은 pytest만의 모양인데 파일은 vitest, playwright, tsc, exit 판정의 출력도 똑같이 읽히고, 새 선택 인자를 더하면 `_parse`, 사용 줄, 독스트링의 인자 설명이 모두 늘기 때문이다.
- `tools/mutate.py` 코드를 읽었다(손으로 본 것, 프로브 없음). 화면에 나오는 출력은 `_details`가 끝 10줄(`_TAIL_LINES`)과 끝 밖의 머리 줄 스무 줄(`_HEAD_LINES`)로 줄였고, 그것도 어긋난 변이나 오류, 표지 없음일 때만이다. 표지가 비어 기대대로 빨개지는 변이는 출력이 한 줄도 나오지 않는다. 그래서 어긋난 것만 파일로 남기면 자리표 표지로 한 바퀴를 더 도는 일이 남는다고 보고, 빨강·처리하지 않은 에러를 기대하는데 `expect_output`이 빈 변이도 같은 파일을 남기게 했다.

## 한 일

- `tests/tools/test_mutate.py` 끝에 시험을 더했다. 어긋난 변이의 전체 출력(화면 상한 밖의 줄, 색 코드 제거), 표지 있는 기대대로와 초록 기대는 파일 없음, 표지 없는 빨강은 기대대로여도 파일, 반복 셋(어긋난 첫 반복, 어긋난 마지막 반복, 어긋난 반복 없음), git 디렉터리 없음, 쓰기 실패, 기준선 빨강은 파일 없음, 덮어쓰기와 지난 파일 보존, 줄 끝 보존, 워크트리의 git 디렉터리, `--check`는 파일을 쓰지 않음이다.

- heredoc 상한, 파이프 뒤 종료 코드, 도구 호출 사이의 한국어 비율 알림(기각): 훅이 그 자리에서 알리거나 막았다.
- 전체 시험을 띄운 뒤 코드를 더 고쳐 멈추고 다시 돌린 것(기각): 약 2분의 낭비이고 데이터를 잃지 않았다. 리뷰를 병렬로 돌리려는 선택이었고 같은 실수의 반복이 아니라 승인의 사건 조건에 이르지 못한다.

- 부하에서만 지는 전체 pytest(기각): 첫 커밋 시도에서 시험 하나가 지고 작업자 하나가 `MemoryError`로 죽었다. 사용자가 부하 시간 시험 종류를 닫힌 채 두기로 했으므로(2026-11-15) 새 사례는 일지에만 적고 항목을 잇지 않는다.
