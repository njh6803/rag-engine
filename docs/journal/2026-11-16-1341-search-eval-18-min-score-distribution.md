# search-eval 18: 최소 점수의 리랭크 점수 분포 측정과 구현 승인 · 2026-11-16

티켓 `.scratch/search-eval/issues/18-min-score-distribution.md`를 구현한 기록이다. 브랜치는 `feature/18-min-score-distribution`이다. `next-session` 지시문이 연 새 세션(Sonnet 5.5 / high)이 `EnterWorktree`로 워크트리 `18-min-score-distribution`에 들어와 이어 갔다. 티켓이 멈추라고 한 지점에서 사용자에게 두 번 물었다. 첫 물음에서 사용자는 "답 없는 질의로 더 잰다"(번호 3)를 골랐고, 둘째 물음에서 "구현한다"를 골랐다.

## 한 것

- 첫 색인이 46분 넘게 멈췄다. `--records read`로 `index`를 돌렸는데 임베딩 TEI(18083)가 꺼져 있었고, 작업 46개가 `embedding_unavailable`로 재시도 대기에 들어 있었다(데이터베이스의 `jobs` 표를 손으로 봤다). 청킹이 토큰 세기를 TEI에 묻고 그 호출은 추론 기록에 없다는 것은 명세가 이미 적었다. 이 세션이 더한 것은 그 경우 `index`가 오류 문장 없이 재시도 대기로 보인다는 점이다. GPU TEI(임베딩)를 띄우고 데이터베이스를 새로 만들어 색인했다(조각 2,193개). 처음 GPU 컨테이너가 `ldconfig` 시그널 9로 한 번 못 떴고 다시 시도하니 떴다.
- 첫 측정. `run --through rerank --records read`를 리랭커 끝점 없이 돌렸다. 종료 코드 0, 새로 계산한 수 0이고 지표는 티켓 14 일지와 같았다(리랭크 뒤 적중률@1 0.774, MRR 0.861, nDCG@10 0.876). `score_distribution`은 후보 15,500개 가운데 닿음 380개, 닿지 않음 15,120개이고, 닿지 않은 조각의 78%(11,818개)가 0.05 미만, 0.95 이상 구간은 닿음 181개와 닿지 않음 156개가 섞였다. 보고서를 프로브 폴더에 옮겼다(`first_measurement_report.md`). 사용자에게 표로 보이고 멈췄다.
- 사용자가 "답 없는 질의로 더 잰다"를 골라, 색인에 답이 없는 질의 20개(소재가 먼 10개, 가까운 10개)를 만들고 핵심어를 `chunks.text`에 `LIKE`로 세어 답이 없음을 확인했다(손으로 봤다). 프로브 `.scratch/search-eval/probes/no-answer-scores/probe_no_answer.py`가 이 20개와 답 있는 질의 310개를 같은 길로 돌려 문턱표를 냈다. 사전 기준(답 없는 질의의 빈 결과 비율 0.80 이상, 답 있는 질의가 기대 근거를 잃는 비율 0.10 이하)이 문턱 0.10~0.40에서 채워졌다.
- 사용자가 "구현한다"를 골라 ADR 0017에 이력(2026-11-16)을 더하고 구현 티켓 `20-min-score-argument.md`를 썼다. 티켓 18은 `done`이다. 티켓 15의 Comments에는 데이터베이스마다 기록에 없는 쌍이 달랐다는 메모를 넘겼다.

## 정한 것

- 구현 티켓은 20번이다. 19번이 이미 있다. 사용자에게 보인 선택지 문장의 "구현 티켓 19"는 번호 착오였다.
- 기본 문턱은 정하지 않는다. 측정이 지지하는 범위는 0.10~0.30이다(0.30보다 높이면 막히는 질의는 그대로 95%인데 기대 근거를 잃는 비율만 8.1%에서 8.7%, 11.0%로 늘어난다). 0.10의 통과는 정확히 0.80이고 1등 점수 0.099인 질문 하나에 달렸다.
- 티켓 20이 이 세션이 정한 것을 둘 담았다. 명세는 침묵한 자리다. (1) `nan`과 `inf`는 SDK의 입력 검증을 통과해 범위 검사도 지나가므로 `invalid_argument`로 거른다(pydantic 검증을 이 저장소 환경에서 손으로 돌려 보았다). (2) 리랭커가 빈 채 기본값이 있는 행에 요청 인자까지 주면 요청 인자 쪽을 먼저 거부해 `invalid_argument`다. 구현 세션이 뒤집어도 되는 정함이다.
- 티켓 17이 아직 결정 전이면 티켓 20은 ADR 0017 이력의 전제(리랭커가 있는 지식베이스)로 진행하고, 17이 리랭커를 끄는 기본으로 결정됐으면 사용자에게 묻는다. `Blocked by`에는 17을 넣지 않았다.
- 명세의 `[거절]` 항목(색인에 답이 없는 질의의 목록)은 고치지 않았다. 그 항목이 "분포가 판정을 내리기에 모자라면 그때 사용자에게 묻는다"고 열어 둔 길을 이번에 갔기 때문에 문장이 거짓이 되지 않는다. 사실은 ADR 0017 이력이 적는다.
