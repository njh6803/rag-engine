# source-sync 05: 커넥터 호출 장치 · 2026-11-22

source-sync 티켓을 나눈 세션이 낸 지시문으로 연 세션의 기록이다(Sonnet 5.5 / high). 나란히 여는 네 세션 가운데 넷째이고, 시작 프롬프트는 `/implement .scratch/source-sync/issues/05-connector-call-guard.md`다. 브랜치는 `feature/05-connector-call-guard`, 작업은 워크트리 `05-connector-call-guard`에서 했다. 요청 범위는 PR과 병합까지다.

## 지은 것

**장치.** `adapters/connectors/guard.py`의 `ConnectorCallGuard`다. 서버와 작업자가 프로세스마다 하나씩 만들어 커넥터 호출이 모두 이것을 지나게 한다(06이 서버에, 07이 작업자에 연다).

- `call(connector, config, kind, start, timeout_seconds, source)`: 호출 하나를 따로 띄운 일(Task)로 내보내고 취소하지 않은 채 한도까지 기다린다. 한도를 넘기면 기다리던 쪽만 `ConnectorCallTimedOutError`로 돌아오고 호출은 그대로 남는다. `start`는 코루틴이 아니라 코루틴을 만드는 함수다. 막혀 있으면 부르지 않아야 하는데, 코루틴을 미리 만들어 두면 부르지 않은 채 버려져 `RuntimeWarning`(이 저장소 시험에서는 오류)이 나기 때문이다.
- `iterate(connector, config, items, timeout_seconds, source)`: 커넥터의 `list()`를 받는다. 항목 하나가 호출 하나이고 항목마다 이벤트 루프로 돌아간다. 막혔는지도 항목마다 다시 본다.
- 막힘은 커넥터 이름과 설정(정렬한 JSON 글)으로 기억한다. 원천은 열쇠에 없다. 남은 호출의 수에는 상한이 없다.
- 부르는 쪽 일이 취소되면(작업 담당 기록을 잃은 경우) 나가 있던 호출은 `loop.call_later`로 제 한도가 끝나는 때까지 지켜보고, 그때도 끝나지 않았으면 그제야 기억한다.
- 로그 한 줄(`connector_call_timed_out`): 원천 이름(없으면 비운다), 호출 종류, 장치에 남은 호출의 수. 설정과 문서의 키는 싣지 않고 막혀서 부르지 않은 호출은 줄을 남기지 않는다.

**도메인.** `domain/connectors.py`에 `ConnectorCallKind`(`list`, `fetch`, `check`, `folder_check`)와 예외 둘(`ConnectorCallTimedOutError`, `ConnectorCallBlockedError`)을 더했다. 부르는 쪽(06, 07)이 둘을 `source_unreadable`로 옮긴다. 커넥터 인터페이스 1.0은 바뀌지 않았다.

**시험.** `tests/adapters/test_connector_call_guard.py` 23개와 가짜 커넥터 `tests/support/holding_connectors.py`(`HoldingConnector`는 풀어 줄 때까지 붙잡고, `EndlessConnector`는 항목 사이에 기다리지 않는다). 끝없는 목록 시험은 같은 루프의 다른 일이 도는지를 본다. 항목마다 `asyncio.wait_for`로 받는 꼴로 바꾸면 그 시험이 빨개진다.

## 변이

변이 파일 `.scratch/source-sync/probes/call_guard_mutations.toml`에 17개를 두었다. 장치의 규칙마다 하나씩 깨고(취소한다, 기억하지 않는다, 막지 않는다, 설정을 안 본다, 종류를 열쇠에 넣는다, 키 순서를 가린다, 마지막 하나만 기억한다, 버린 호출을 바로 기억한다, 한도 뒤에도 기억하지 않는다, 항목을 곧바로 받는다, 설정을 로그에 싣는다, 막힌 호출도 로그를 남긴다, 남은 수를 설정마다 센다, 상한을 둔다, 예외를 바꾼다, 끝난 호출을 비우지 않는다, 목록을 기다리다 버린 호출을 기억하지 않는다) 모두 기대한 시험이 표지와 함께 빨개졌다.

- 변이 10(목록의 항목을 곧바로 받는다)을 처음에는 `await anext(items)`로 지었는데, 한도까지 함께 없어져 붙잡힌 목록 시험이 영원히 기다렸다. 600초 제한에 걸려서야 어긋남이 드러났다. 프로브가 견준 둘째 방식(항목마다 `asyncio.wait_for`)으로 바꾸고 `-k 끝없는`으로 그 시험만 겨누었다.
- 변이 14(남은 호출이 백을 넘으면 더 막는다)는 처음에 초록이었다. 시험이 300개를 한 번에 보내서 모두 남은 호출이 0일 때 나갔다. 두 번에 나눠 보내게 고쳤다.
- 표지로 고른 줄 가운데 pytest가 단언을 풀어 쓴 줄과 시험 원문에 글자 그대로 있는 메시지는 `tools/mutate.py`가 거부했다. 실제 실패에서만 찍히는 값(`f"취소된 호출 {n}개"`처럼 실행 때 정해지는 글)을 단언 메시지에 달아 표지로 삼았다.

## 셀프 리뷰

범위는 기준 `3c30d47`, 수정 파일 2개, 미추적 4개, 커밋 0개다. 표준 축과 명세 축을 병렬로 돌렸다.

**표준 축.** Critical·Major 없음, 문서화된 표준 위반 Minor 둘, 냄새와 Nit 몇.

- (Minor, 고쳤다) 시험의 로거 이름 비교(`record.name == "rag_engine.adapters"`)가 늘 거짓이라 "한도 안에 돌아오면 기억하지 않는다" 시험의 로그 단언이 비어 있었다. 코드로 로거 이름이 `rag_engine.adapters.connectors.guard`임을 확인했다. 한도를 넘길 때의 로그 줄만 모으는 도우미로 바꿨다. 이 시험이 "바로 기억하는" 변이를 직접 잡는다.
- (Minor, 고쳤다) 변이 표지 둘(`ConnectorCallGuard object at`, `<built-in function monotonic>`)이 단언을 풀어 쓴 repr 조각이라 다른 빨강에도 나올 수 있었다. 단언 메시지의 값으로 바꿨다. 세 변이가 함께 쓰는 `ConnectorCallTimedOutError: 커넥터 호출이 한도까지`는 남겼다. 그 변이들이 기대하는 실패가 정확히 "막혀야 할 호출이 막히지 않고 한도를 기다렸다"이므로 원인 문구다.
- (고쳤다) 로그 줄 걸러내기가 시험 파일에 다섯 번 되풀이되어 `_timed_out_records`로 모았다. `_stuck` 정리가 질의처럼 보이는 이름이라 독스트링에 적었다. `test_남은_수는_프로세스_전체에서_센다`는 실제로 장치 하나를 센다고 이름을 고쳤고, 머리 설명에 장치를 요청이나 작업마다 새로 만들면 기억이 갈린다고 적었다.
- (남겼다, Nit) 키 정리의 `(key, kind, source)` 묶음과 열쇠를 문자열로 짠 것은 작아서 둔다.

**명세 축.** (a) 빠진 것 없음. (b) 변이 파일은 이 저장소의 변이 규약이라 범위 넘침이 아니다. (c)(d)에서 아래가 나왔다.

- (고쳤다, Major에 가까움) 한도를 넘겨 기억된 호출이 나중에 끝나도, 같은 열쇠로 다시 부르거나 `outstanding_calls`를 읽을 때까지 `_stuck`이 호출을 쥐어 결과를 놓지 못했다. 서버 경로 커넥터의 `fetch` 결과는 크기 상한(100MB)까지 갈 수 있다. 기억할 때 완료 콜백을 달아 끝나는 순간 비운다. 약한 참조로 결과가 사라지는지 보는 시험을 먼저 썼고(빨강을 확인했다) 구현 뒤 초록이다.
- (고쳤다) 목록 항목을 기다리다 버려지는 길(`iterate`)은 시험이 없었다. 시험을 더했다.
- (고쳤다, 서술) `iterate`가 일찍 멈춰도 커넥터의 `list()`를 닫지 않는다는 것을 독스트링에 적었다. 닫는 일이 끊긴 폴더에서 돌아오지 않을 수 있어서 ADR 0023의 뜻에 맞게 닫지 않는다. 닫는 일은 부르는 쪽 몫이다. 참조를 놓으면 이벤트 루프가 닫는다(스크래치 스크립트로 확인했다).
- (남겼다) 설정을 JSON 글로 견주므로 `{"a":1}`, `{"a":1.0}`, `{"a":true}`가 다른 설정이다. 명세가 침묵하고, 부르는 쪽이 같은 설정을 같은 꼴로 넘기면 영향이 없다. `_identity`의 독스트링에 적었다.
- (남겼다) 커넥터가 스스로 `CancelledError`를 올리면 부르는 쪽 일의 취소와 구별되지 않는다. 티켓의 "커넥터가 낸 예외는 그대로 넘긴다"에 어긋나지 않고 명세가 침묵한다.

**PR 직전 리뷰에 밀 주장(이번 반영으로 새로 쓴 사실 문장).**

1. `guard.py` `_release` 주석: "서버 경로 커넥터는 크기 상한 100MB까지의 바이트"를 쥔다(명세 "동기화의 차례"의 상한 항목이 근거다).
2. `guard.py` `iterate` 독스트링: 닫는 일이 끊긴 폴더에서 돌아오지 않을 수 있다는 것과, 참조를 놓으면 이벤트 루프가 제너레이터를 닫는다는 것.
3. `guard.py` `_identity` 독스트링: `1`과 `1.0`과 `true`가 다른 값이다.
4. `guard.py` 클래스 독스트링: 요청이나 작업마다 새로 만들면 기억이 갈린다.

## 다음

- **06과 07이 이 장치를 지나 커넥터를 부른다.** 06은 서버에서 연결 확인과 폴더 확인을, 07은 작업자에서 동기화와 색인을 이 장치로 부른다. 둘 다 장치를 프로세스마다 하나만 만들어야 한다(요청이나 작업마다 만들면 기억이 갈린다). 한도 값은 06이 10초 상수, 07이 `RAG_SOURCE_READ_TIMEOUT_SECONDS`로 준다.
- **예외를 응답 코드와 실패 사유로 옮기는 일은 06과 07이 한다.** `ConnectorCallTimedOutError`와 `ConnectorCallBlockedError`는 둘 다 `source_unreadable`로 옮기되, 색인 작업에서는 일시 실패로 다시 예약한다.
- **작업이 거두어질 때 나가 있던 호출을 바로 기억하지 않는 길은 취소에 얹었다.** 07이 작업 담당 기록을 잃어 처리를 취소하면 그 취소가 `call` 안의 기다림에 닿아야 이 길을 탄다. 처리를 `asyncio.shield`나 다른 일로 감싸 취소가 닿지 않게 하면 장치가 바로 기억하지 않는 것이 아니라 기억할 길 자체가 사라진다. 07이 그 취소가 어떤 길로 닿는지 시험한다.
- **`iterate`로 받은 목록을 일찍 멈추는 쪽이 `list()`를 닫는다.** 닫기가 오래 걸릴 수 있어 부르는 쪽이 한도를 걸지 정한다.
