- **훅.** `tools/hook_ui_design.py`와 `tests/tools/test_hook_ui_design.py`, `tools/hook_payloads.toml`의 사례 셋(발동 하나, 침묵 둘), `.claude/settings.json`의 등록.
- **결정표.** `next-session` `SKILL.md`에 "화면 디자인" 줄을 "명세" 줄 바로 위에 더했다.
- **트래커 문서.** `docs/agents/issue-tracker.md`에 "화면 디자인" 절을 더했다.
- **계획.** `.scratch/plan-head.md`의 "하네스 기능" 절을 비웠고(`열린 하네스 기능이 없다`), `.scratch/admin/plan.md`의 "차례"를 옮긴 뒤의 사실로 고쳤고, `.scratch/plan.md`를 도구로 다시 만들었다.

### 명세 축 판정

범위는 같고, 명세는 티켓 `.scratch/harness/issues/ui-design-skill-port.md`다. 서브에이전트가 `run_hooks.py`(134건, 어긋남 0), 훅 시험, `check_instructions.py`, `plan_table.py --check`를 돌려 모두 초록임을 보았다. "명세 전에 화면을 그린다" 문장은 admin·group-kb·eval-screen 계획에 글자 그대로 있고 backup-upgrade·diag-bundle 계획에는 없다. 결정표에 손으로 대 보니 admin은 "화면 디자인" 줄로 가고, 다른 네 기능은 설계 줄이 없어 설계 인터뷰 줄로 간다.

1. **(a)1 그림 끝 판정이 막힌다.** 맞다. 사람이 그리지 않기로 한 화면은 README에 줄이 없어 결정표가 계속 "화면 디자인"으로 보낸다. 고쳤다: 그런 화면도 `(그리지 않음)`·`(옮기지 않음)` 줄을 두게 스킬 7단계와 트래커 문서에 적었다.
2. **(a)2 README를 만드는 단계와 "고른 안" 칸이 없다.** 맞다(표준 축 2와 같다). 고쳤다: 스킬 7단계에 README 만들기를 더했고 트래커 문서의 칸에 "비고"(고른 안, 그리지 않은 까닭)를 더했다.
3. **(a)3 Docker 갈래.** 맞다. `run_checks.is_doc_path`는 `.scratch/` 아래에서 `.md`와 프로브 출력만 문서로 본다. `.dc.html`을 옮기는 커밋에는 테스트 PostgreSQL이 든다. 고쳤다: 결정표 "화면 디자인" 줄의 "어디서"를 "새 세션(Docker가 켜진 로컬 …)"으로 적었다.
4. **(b) 디자인 시스템 판 칸과 `version` 기록은 새 결정이다.** 맞지만 agent-os의 같은 칸(`lastChange`로 적던 것)을 이 저장소에서 읽히는 값(`version`)으로 옮긴 것이고 티켓의 "이 저장소에 맞추는 것"에 든다. 남긴다. 원본의 선택지 수 출처가 빠진 것은 고쳤다: "`AskUserQuestion`의 도구 설명이 질문마다 선택지를 둘에서 넷으로 적는다"를 더했다.
5. **(c)1 "판"이 두 가지로 읽힌다.** 맞다. 고쳤다: "그린 화면 아티팩트의 판 id는 … 적지 않고"로 가렸다.
6. **(c)2 표지가 문장 부분 문자열이라 부정문도 맞는다.** 원본과 같은 약점이고 계획이 그 문장을 적는 곳은 사람이 쓴다. 남긴다(회차를 세는 대기열 후보로만 둔다).
7. **(c)3 훅의 넷째 못 보는 것(문장이 모델에 닿는지)은 시험이 없다.** 재지 못하는 항목이라 독스트링이 "재지 않았다"고 적은 것으로 충분하다고 본다. 남긴다.
8. **`.claude/rules/tools.md`의 "(harness 티켓 002)"와 `hook_web_edit_check`.** 두 보고가 함께 짚었다. 이전부터 있던 문장이고 티켓이 그 파일을 고치지 않기로 했다. 남긴다. 이 저장소의 티켓 이름으로 바꾸고 이 저장소에 없는 `hook_web_edit_check` 항목을 정리하는 일은 retro 후보로 올린다.
