# core 설계 인터뷰 일지 · 2026-11-09

킥오프 일지의 "다음"(9단계 1)대로 첫 기능 core(`.scratch/core/plan.md`)의 설계 인터뷰를 `/grill-with-docs`(grilling과 domain-modeling)로 돌린 기록. 브랜치는 `docs/core-design`(티켓 없는 면제 PR). 라운드마다 물은 것과 사용자의 답, 찾은 사실을 적고, 끝 절에 결정 요약, 추천과 결정이 갈린 곳, 에이전트가 번복하거나 고친 것, 사실의 출처, 산출물, 검증을 둔다.

기록 규칙: 결정을 내리거나 방향을 바꾸거나 설계를 되물은 사용자 프롬프트는 해당 라운드 아래에 `> 사용자:` 인용으로 원문 그대로(오타도 고치지 않는다) 남긴다. 선택 화면에서 고른 것은 질문과 함께 적되, `> 사용자:` 인용의 따옴표 안에는 사용자가 고른 라벨만 두고, 고른 선택지의 설명은 따옴표 뒤에 `— 설명:`으로 글자 그대로(설명의 오타도 그대로) 붙인다. 직접 입력란에 적은 답은 라벨 없이 원문만 둔다. 에이전트의 말은 옮기지 않고, 추천과 결정이 갈린 곳과 에이전트가 번복하거나 고친 것만 끝 절에 한 줄씩 남긴다. `/retro`의 입력이다.

## 준비

- 읽은 것: 기능 계획 `.scratch/core/plan.md`, 킥오프 입력(`.scratch/kickoff-input.md`) 2·3·4·7·8절, ADR 0001~0005, `docs/constitution/tech.md`, `docs/PRD.md`, `docs/agents/issue-tracker.md`의 프로브와 근거 절. 용어집은 아직 없었다(이 세션이 만든다).
- 사실 조사는 서브에이전트에 나눠 맡겼다. 벡터 저장소 후보 비교, 작업 대기열 라이브러리, 임베딩 서버와 모델, 파서 라이브러리의 라이선스와 py.typed, SQLAlchemy 비동기 조합, MCP SDK의 전송·인증 동작이다. 보고는 근거의 종류(스크립트로 쟀다, 코드를 읽었다, 어림, 웹 요약)로 갈라 받았고, 근거로 드는 스크립트는 `.scratch/core/probes/`에 이관했다(끝의 사실 출처 절).
- 라운드는 `AskUserQuestion`으로 올렸다. 아래 라운드 번호는 호출 순서다. 답이 같은 호출이 둘씩 남은 라운드(16·17, 22·23)는 하나로 적는다.

## 갈래 밟기

테스트 DB를 Docker로 통일한 결정(라운드 16)이 커밋 절차를 바꾼다. pre-commit의 검사 러너(`tools/run_checks.py`)가 pytest를 always_run으로 돌리므로, 문서만 고친 커밋에서도 테스트 DB가 있어야 한다. 갈래는 셋이다. 커밋하는 로컬 세션(DB를 누가 띄우나), Docker가 없는 클라우드 세션(커밋이 막힌다), CI(service container가 있다).

> 사용자: "검사 러너가 DB가 안 보이면 `compose.test.yml`을 띄우고(`docker compose up -d --wait`) pytest를 돈다 (Recommended)" — 설명: "`RAG_TEST_DATABASE_URL`이 있으면(CI의 service container, 직접 정한 DB) 그대로 쓰고, 없으면 러너(`tools/run_checks.py`)가 로컬 compose 테스트 DB를 띄우거나 이미 떠 있으면 그대로 씁니다(떠 있으면 1~2초, 어림). 컨테이너는 커밋 뒤에도 내리지 않고 남습니다. Docker가 없거나 꺼져 있는 기계에서는 띄우는 명령과 함께 빨강입니다(skip 아님, 원칙 I). 비용: 커밋 경로에 Docker 의존이 들어오고, 러너 코드와 그 테스트(`tests/tools/`)가 늘며, 기계마다 첫 커밋은 이미지 pull(164MB)로 길어집니다. 문서만 고치는 커밋도 DB가 필요한 것은 러너가 pytest를 always_run으로 돌리는 지금 규약 그대로입니다." (질문: 커밋 때 DB)

- 따라오는 것: 러너가 DB를 띄우는 변경은 하네스 티켓이다. core 뒤의 티켓은 Docker가 있는 로컬 세션에서 돌고, Docker가 없는 클라우드 세션은 core 티켓을 커밋할 수 없다(next-session 지시문의 "어디서"). `.scratch/plan-head.md` 순서 절에 적었다.

## 결정 요약

합의 요약 1~26을 ADR과 헌법 칸에 옮긴 자리다.

1. 두 층 모델(문서는 그룹 하나, 지식베이스는 그룹 집합 위의 색인), 첫 판은 기본 그룹·기본 지식베이스 하나씩 — ADR 0008.
2. 문서 식별은 (원천, 키), 내용 해시는 변경 감지에만, 업로드와 수집 API는 밀어 넣는 원천 종류 — ADR 0008.
3. 다섯 층 main > server·worker > adapters > app > domain, 포트 Protocol 열(Connector, Transform, Parser, Chunker, Embedder, Reranker, VectorIndex, JobQueue, DocumentStore, BlobStore) — ADR 0007. import-linter 계약과 `CLAUDE.md` 레이어 절은 첫 구현 티켓이 고친다.
4. 서버·작업자 이미지 둘(torch 없음), 단독 compose 다섯(서버, 작업자, PostgreSQL, 임베딩 TEI, 리랭커 TEI) — ADR 0007, tech.md 컨테이너 칸.
5. 데이터베이스는 compose 동봉 PostgreSQL 18 하나, CI도 18 하나, 고객사 DB 연동은 SQL 원천(db-source) — ADR 0002 이력 2026-11-09.
6. SQLAlchemy 2.1 Core 비동기(psycopg 3, greenlet) + alembic, `rag-engine migrate` — ADR 0011.
7. 벡터 저장소 C: pgvector 0.8.7 + PG 전문 검색(kiwipiepy → `to_tsvector('simple')`, GIN) + 한 SQL RRF, 이미지 `pgvector/pgvector:0.8.7-pg18-trixie`, 교체 조건 셋 — ADR 0006.
8. 작업 대기열은 PG 작업 표(SKIP LOCKED + LISTEN/NOTIFY + 폴링, 지수 백오프, 부분 유일 인덱스), `JobQueue` 포트 — ADR 0009.
9. 소프트 삭제 `deleted_at` → 조각을 보관 표로 → `RAG_DELETED_RETENTION_DAYS`(30) 뒤 물리 삭제와 묘비 — ADR 0013.
10. 원본은 `BlobStore` 포트 뒤 `RAG_DATA_DIR/blobs/<UUID>`, 서버 경로 원천은 복사 안 함, S3는 나중 어댑터 — ADR 0013.
11. 지식베이스마다 색인 판 레코드(스키마 판, 모델 ID·차원, 청킹 설정 해시, 토크나이저 판), 요소마다 재색인 범위 다름 — ADR 0008.
12. 문서 단위 원자 교체, 모델·청킹 교체는 지식베이스 판 전환 — ADR 0008.
13. TEI 1.9.4 컨테이너당 모델 하나, 개발·CI는 CPU 이미지, 호출은 `/v1/embeddings`·`/tokenize`·`/rerank` — ADR 0010.
14. 기본 모델 bge-m3, 리랭커 bge-reranker-v2-m3를 첫 판부터 켬 — ADR 0010, tech.md.
15. 청킹은 구조 우선 전략 하나, `Chunker` 포트와 지식베이스 설정의 전략 이름, 상한은 토큰 수(`/tokenize`), 기본 512/64 어림은 search-eval이 정함 — ADR 0010.
16. MCP 읽기 도구 `search`, `get_document`, `list_knowledge_bases`, 결과의 `format_version`과 outputSchema, 도구 이름 고정 — ADR 0008, ADR 0015.
17. 메모리 32GB 기준, 16GB 최소 — tech.md 컨테이너 칸.
18. MCP 전송은 설정 `RAG_MCP_STATELESS`(true)·`RAG_MCP_JSON_RESPONSE`(false), `RAG_ALLOWED_HOSTS` 필수 — ADR 0014, tech.md.
19. 토큰 표(해시, 이름, 역할, 만료, 지식베이스 범위), 관리 API 발급·회수, `bootstrap-token`, ASGI 미들웨어 401/403 — ADR 0014.
20. 공통 규약: `/api/v1/admin`·`/api/v1/ingest`, RFC 9457 + `code`, UTC timestamptz와 ISO 8601 Z, UUIDv7 파이썬 생성, pydantic-settings `RAG_*`, JSON Lines 로그 — ADR 0015.
21. 수집 API multipart(file + key/group/metadata), 202와 작업 ID, 같은 (원천, 키)면 갱신, DELETE, `RAG_MAX_UPLOAD_MB`, 방향은 다른 시스템 → 우리 — 명세로 넘긴다(tech.md HTTP 칸에 python-multipart).
22. 관리 명령 serve, worker, migrate, bootstrap-token, ingest <경로> [--wait], 명령은 app 층 유스케이스를 직접 부름, 나머지 쓰기는 관리 API — tech.md 관리 명령 칸.
23. 플러그인 Protocol + `interface_version` + entry points, major 불일치 거부, 커넥터 pull 넷(`interface_version`, `list()`, `fetch(key)`, `check()`), `changes_since`는 나중 — ADR 0012.
24. 파서 pdfplumber, python-docx, python-hwpx, PyMuPDF·pyhwp(AGPL) 제외, docling·kordoc은 플러그인 가능 — tech.md 파서 칸.
25. 테스트 DB Docker 통일, `RAG_TEST_DATABASE_URL`, skip 아닌 실패, 러너가 DB를 띄움(하네스 티켓), core 티켓은 Docker 있는 로컬 세션 — tech.md 테스트 칸, `.scratch/plan-head.md`.

## 에이전트가 번복하거나 고친 것

- 라운드 1·2 지식베이스 단위: 추천 "서버 하나가 지식베이스 하나"를 사용자의 되물음(청킹·임베딩 설정이 내용마다 달라야 한다) 뒤 거두고, 라운드 3의 되물음대로 라운드 4에서 두 층 모델을 추천으로 올렸다.
- 라운드 2 수집 입구의 "명령은 그 클라이언트"(`ingest`가 관리 API를 부르는 얕은 클라이언트)를 라운드 19의 관리 명령 결정이 "명령은 REST와 같은 app 층 유스케이스를 부르고 같은 연결 문자열로 DB에 직접 붙습니다"로 바꿨다. 사용자가 고른 둘 가운데 뒤의 것이 결정이다(tech.md 관리 명령 칸에 옮겼다).
- 라운드 5 "임베딩 호출은 OpenAI 호환 형식 하나로 고정"을 라운드 18의 상한 재기가 TEI 고유 끝점 `/tokenize`를 더해 바꿨다(Embedder 포트에 토큰화 메서드).
- 라운드 16 최소 PG 판의 선택지 설명에 적은 "2026년 설치처의 PostgreSQL이 18일 가능성은 낮음"은 PostgreSQL이 우리 제품의 데이터베이스라는 전제를 놓친 표현이었다. 라운드 17에서 ADR 0002의 두 길(동봉 PostgreSQL, 설치처의 PostgreSQL)을 원문으로 다시 설명하고 사용자의 전제를 결정으로 받았다.
- 라운드 17 조각 크기 질문이 전략(시멘틱 청킹)과 상한 재기를 한 질문에 섞고 있어서, 사용자의 되물음 뒤 라운드 18에서 청킹 전략과 상한 재기 둘로 갈라 다시 물었다. 전략 비교의 근거는 arXiv 2410.13070(웹 요약)이다.
- 라운드 18 MCP 전송의 추천 "세션 없음 + JSON 응답"을 진행률 프로브 뒤 라운드 19에서 "세션 없음 + SSE 응답"으로 바꿨다.
- Bash에서 `cd`로 스크래치패드에 들어가려다 훅(`hook_bash_gate_cwd`)에 막혀 경로를 인자로 넘기는 것으로 고쳤다.
- TEI OpenAPI 문서를 한 줄 JSON으로 보고 grep한 것이 비어, `uv run python -I` 스크립트로 파싱해 대조했다. 그 스크립트가 프로브 `facts/tei_openapi_fields.py`다.
- 일지 인용을 뽑는 스크립트의 첫 판이 직접 입력 답을 호출 전체의 답으로 붙여, 질문 문장 위치로 답 구간을 자르는 둘째 판으로 고쳤다(거부된 호출은 뺐다).
- 산출물 단계에서 ADR 0008 본문에 라운드 2의 `get_document` 도구가 빠진 것을 일지를 쓰며 봤고 본문에 더했다.

## 사실의 출처

프로브는 `.scratch/core/probes/`에 있고 README의 표가 무엇을 재는지, 어디가 근거로 드는지, 다시 돌 때 필요한 것, 잰 판을 적는다. 웹 요약은 원문을 받아 대 보지 않은 것이다.

- TEI 1.9.4 OpenAPI 원문 대조(`facts/tei_openapi_fields.py`): `/tokenize`가 토큰마다 `start`·`stop`을 돌려주고, `/v1/embeddings`에는 `truncate` 칸이 없고, `/rerank`가 있다. 임베딩 HTTP 왕복은 `embedding/http_overhead.py`(가짜 서버 `embedding/fake_server.py`). 옮긴 뒤 재실행 출력은 `facts/tei_openapi_fields_out.txt`와 `embedding/http_overhead_out.txt`(p50 2.96ms. 첫 실행은 2.69ms)다.
- MCP SDK 2.3.0 프로브(`mcp-sdk/`): `probe_sdk.py`가 허용 호스트 밖 Host의 421과 403, 순수 ASGI 미들웨어의 401, outputSchema와 structuredContent, 프로토콜 판 2026-07-28을, `probe_sessions.py`가 세션 유지 모드에서 세션 ID를 모르는 워커의 404 "Session not found"와 세션 없음 모드의 200을, `probe_progress.py`가 전송 모드 셋의 진행률 전달 횟수(3, 3, 0)를 쟀다. 타입을 고쳐 옮긴 뒤 셋을 다시 돌려 저장된 출력과 무작위 세션 ID만 다름을 봤다.
- SQLAlchemy 2.1 비동기 + psycopg 3 + alembic 조합(`sqlalchemy-async/probe.py`): 타입 검사(pyright strict 0 오류. 저장소 설정의 기본 exclude가 `.scratch`를 건너뛰므로 exclude를 비운 설정으로 다시 검사해 filesAnalyzed 1을 확인했다)와 실행(출력 `sqlalchemy-async/probe_out.txt`)까지 지났다. `uv run --with`가 Windows에서 os error 32로 실패해 별도 가상 환경에서 돌렸고, Windows에서는 Selector 이벤트 루프가 필요했다.
- 벡터 저장소 비교(`vector-store/`, `facts/qdrant_facts.py`, 비교 문서 `.scratch/core/design/vector-store-comparison.md`): Docker Hub 이미지 크기와 받기 수, PyPI 다운로드, GitHub 별, 휠의 py.typed를 스크립트로 쟀고 무료판 제한과 한국어 토큰화는 공식 문서 원문이다. `facts/qdrant_facts.py`는 Qdrant v1.20.0 태그의 charabia 피처 다섯(`korean` 없음)을 찍는다(첫 실행은 여러 줄 피처 목록의 첫 줄만 찍어, 옮기며 블록 전체를 찍게 고쳐 다시 돌렸다. 출력 `qdrant_facts_out.txt`).
- 작업 대기열 라이브러리(`db-queue/`): procrastinate, pgqueuer, SAQ의 PyPI 메타데이터와 휠(py.typed, 의존성)을 스크립트로 봤다. RabbitMQ 이미지 크기는 `facts/rabbitmq_facts.py`(재실행 출력 `rabbitmq_facts_out.txt`).
- 파서 라이브러리(`parsers/`): PyPI·GitHub·sdist에서 라이선스, py.typed, 의존성을 스크립트로 봤다.
- 웹 요약: 청킹 전략 비교 arXiv 2410.13070, FastAPI의 request-files 문서(python-multipart, File과 Form 함께 선언), Hugging Face tokenizers 0.23.3.

> - **일지 `## 다음`이 낡았다.** "열린 항목은 gate-pipe-read-status(1회차)"라고 하지만 실제로는 열린 항목 일곱 개이고 gate-pipe는 2회차다.
> - **tech.md가 없는 동작을 현재형으로 적는다.** "검사 러너가 … compose를 띄운다"는 하네스 티켓 전에는 거짓이다.
> - **헌법 판 1.0.1.** 설정 행을 더하고 미정 칸을 결정으로 채웠다. 절 추가(minor)로 볼 여지가 있다.
> - **용어집.** "묘비 … 이력이 이어진다"는 어느 ADR에도 없는 규칙이다(ADR 0013은 되살림을 명세에 미룸). 보관 표, 해시로 두고 같은 구현 세부가 정의에 들어 있다(GLOSSARY-FORMAT "what it IS"). 수집의 피할 말 "인제스트"인데 `/api/v1/ingest`와 `ingest <경로>`가 결정되어 있다. 포트 이름 `BlobStore`·`VectorIndex`·`JobQueue`는 피할 말(블롭·인덱스·큐)과 겹치지만 용어집은 `Embedder`만 예외로 적었다.
> - **ADR 0013.** "벡터 색인에 죽은 행이 남지 않는다"는 근거 없는 닫힌 주장이다. HNSW는 vacuum 전까지 죽은 튜플을 갖는다.
> - **ADR 0006 대 ADR 0013.** 0006은 "백업이 하나"라 하고 0013은 백업이 둘(덤프와 볼륨)이다.
> - **테스트 DB 태그 불일치.** tech.md와 plan-head는 `pg18-trixie`(부동)이고 ADR 0006은 `0.8.7-pg18-trixie`로 고정한다. 운영과 같은 판으로 잰다는 취지와 어긋날 수 있다.
> - **파일 수.** 일지의 59개 + 재실행 출력 5개 + README = 65인데 프로브 폴더는 66개다. `embedding/fake_server.py`가 셈에 없다.

> #### 갈래 밟기
>
> - **하네스 티켓 선행이 일지에만 있다.** `plan-head`는 "러너 변경은 하네스 티켓이다"까지만 적고 먼저 닫혀야 한다는 말이 없다. next-session 결정표에도 없어서, 티켓에 Blocked by가 안 붙으면 core 첫 구현 티켓이 먼저 돌아 DB 테스트가 빨개진다. 러너에 `SKIP=pytest` 우회도 열려 있다.

### 반영

- **고친 것.**
  - ADR 0010: 서버가 잘라 주지 않고 거부한다는 문장은 TEI 1.9.4 소스와 달랐다. `router/src/main.rs`의 `--auto-truncate`가 `default_value = "true"`이고 `router/src/http/server.rs`의 `/v1/embeddings` 처리기가 `let truncate = info.auto_truncate;`로 그 값을 그대로 써서, 상한을 넘는 조각은 거부가 아니라 조용히 잘린다. 본문과 글자 수 선택지를 그렇게 고치고 토큰 셈의 까닭을 내용 유실 방지로 바꿨다. 근거는 새 프로브 `facts/tei_images_and_models.py`(출력 `tei_images_and_models_out.txt`)이고, 같은 프로브로 CPU 이미지 239MB, Ollama 3.39GB, Qwen3-Reranker 미지원(README 표의 리랭커 행은 XLM-RoBERTa·GTE·ModernBert)에 근거를 달았다. vLLM 9.74GB는 어느 태그인지 남지 않아 태그를 밝힌 7.7GB(`v0.33.0-x86_64-zstd`, efa 판 10.5GB)로 바꿨고, compute capability 7.5는 vLLM 문서의 CUDA 설치 절, Ollama에 리랭크 끝점이 없는 것은 API 문서 `docs/api.md`를 읽어 표기했다. p50 머리 수치는 재실행 값 2.96ms로 하고 첫 실행 2.69ms를 괄호로 옮겼다.
  - ADR 0002 이력: 요약을 따옴표에 쌌던 사용자 인용을 라운드 16·17의 원문 둘로 바꾸고, Consequences 인용은 항목 머리 "설치 환경의 PostgreSQL에 붙일 때는"만 따옴표에 남겼다. 일지 75행은 고른 라벨 "SQLAlchemy 2.1 Core(+psycopg) 와 alembic" 원문으로, 249행은 설명 원문("붙습니다")으로 고치고 그 문장을 tech.md 관리 명령 칸에 옮겨 포인터가 참이 되게 했다.
  - ADR 0006: 관리형 11곳은 받은 HTML 열한 개를 곳으로 센 것이라 비교 문서 N-3 표대로 아홉 곳으로 고치고, 그 수가 스크립트가 아니라 비교 문서의 읽음임을 갈랐다. 채택도가 가장 높다는 말에 비교한 벡터 저장소 가운데라는 한정을 붙이고 Elasticsearch·OpenSearch를 같은 줄로 견주지 않은 까닭을 적었다. 컨테이너와 백업이 하나라는 문장은 ADR 0013(덤프와 볼륨 둘)과 어긋나 색인이 데이터베이스 안에 있어 덤프 하나에 든다는 문장으로 바꿨다. PGroonga 인용은 비교 문서의 원문으로, Milvus 8GB는 Milvus 문서의 단독 구성 요구 사양 읽음으로 표기했다. 비교 문서의 "열한 곳", 0절의 기존 PostgreSQL 전제, 3단계 머리말(사용자 허락 뒤 실측한다던 것)을 지금 상태로 고쳤다.
  - ADR 0007: 이 ADR과 함께 계약을 고친다는 문장은 `pyproject.toml`이 그대로라 거짓이었다. 계약을 고치는 시점을 core의 첫 구현 티켓으로 적었다. 트랜잭션 경계는 ADR 0006·0008·0009가 기대는 조건(DocumentStore·VectorIndex·JobQueue의 PostgreSQL 어댑터가 한 트랜잭션을 공유할 수 있어야 한다)을 본문에 적고, 유스케이스가 그 경계를 여는 작업 단위 포트의 모양은 명세로 넘겼다. 받는 쪽은 이 일지의 `## 다음` 명세 줄과 `.scratch/core/plan.md` 본문이다.
  - ADR 0014: `probe_sessions_out.txt`의 포트 없는 Host 421과 대문자 Host 421을 반영해, 적힌 값마다 그대로와 `값:*` 두 꼴로 등록하고 설정 값은 소문자로 적는다고 했다. SDK 2.3.0 `transport_security.py`가 정확 일치 뒤 `host:` 접두만 보는 것을 읽었다. `AuthSettings`는 `issuer_url`만이 아니라 `resource_server_url`도 필수 칸(`Field(...)`)이라 둘로 고쳤다.
  - ADR 0011: greenlet 판·라이선스를 프로브 마지막 줄로 더해 임시 가상환경에서 다시 돌렸고(`probe_out.txt`), pyright 결과는 `pyright_out.json`(filesAnalyzed 1, 오류 0)으로 남겼다. Windows 이벤트 루프 문장은 psycopg 3 문서 비동기 절의 경고(ProactorEventLoop과 호환되지 않음)를 읽은 것으로 표기하고 프로브가 재지 않았다고 적었다.
  - ADR 0009의 마이그레이션 38개에 새 프로브 `facts/procrastinate_migrations.py`(출력 `procrastinate_migrations_out.txt`, 3.10.0의 `.sql` 38개). ADR 0012에 "내장 파서도 같은 그룹에 등록해 로드하는 길이 하나다", ADR 0015에 "예외는 스택을 필드로 싣는다", ADR 0008의 `list_knowledge_bases`에 칸 셋(이름, 설명, 문서 수). ADR 0013의 벡터 색인에 죽은 행이 남지 않는다는 문장은 vacuum 뒤에 빠진다로.   - tech.md: 테스트 이미지를 운영과 같은 `pgvector/pgvector:0.8.7-pg18-trixie`로 고정하고, 러너가 compose를 띄운다는 현재형을 하네스 티켓의 일로, MCP 전송 설정 이름 둘(`RAG_MCP_STATELESS`, `RAG_MCP_JSON_RESPONSE`)과 관리 명령이 app 층 유스케이스를 부르는 문장을 더했다. 헌법 판은 두 축의 지적대로 1.0.1에서 1.1.0으로(절 추가, minor). `.scratch/plan-head.md`의 이미지 판과 Docker 문단(첫 구현 티켓의 Blocked by, 모든 커밋에 Docker, 결정표에 분기 없음), `.scratch/core/plan.md` 본문(설계가 정한 것, 명세 몫, 첫 티켓의 Blocked by와 계약 수정)을 고쳤다.
  - GLOSSARY: 묘비 항목의 같은 키가 다시 와도 이력이 이어진다는 규칙은 어느 ADR에도 없어 명세가 정한다로, 소프트 삭제와 토큰(인증)의 구현 세부(보관 표로 옮김, 해시로 둠)를 뺐다. 영어 식별자(`ingest`, 포트 이름)는 피할 말의 대상이 아니라는 머리말 한 줄을 더했다.

## 다음

- **명세.** 기능 core의 명세를 `/to-spec`으로 쓴다(새 세션, Fable 5.1 / xhigh). 입력은 `.scratch/core/plan.md`의 설계 줄이 가리키는 ADR 0006~0015와 ADR 0002 이력, `GLOSSARY.md`, `docs/constitution/tech.md`, 이 일지의 "결정 요약"(1~26)과 "추천과 결정이 갈린 곳"이다. 결정 요약은 ADR이 다루지 않은 세부(수집 API의 multipart 칸, 관리 명령 다섯의 인자, 파서 셋, 청킹 규칙, 메모리 상한 32GB/16GB)도 들고 있으므로 명세가 그것을 옮긴다. 명세가 더 정할 것 셋: MCP 전송 설정 `RAG_MCP_STATELESS`(기본 true)·`RAG_MCP_JSON_RESPONSE`(기본 false)의 조립 자리(이름은 tech.md HTTP와 MCP 칸에 적었다), DocumentStore·VectorIndex·JobQueue가 한 트랜잭션을 공유하게 유스케이스가 여는 작업 단위 포트의 모양(ADR 0007), 테스트 이미지 판은 운영과 같은 `pgvector/pgvector:0.8.7-pg18-trixie`로 고정(tech.md와 plan-head에 적었다).
- **하네스 티켓이 먼저다.** core의 테스트는 Docker로 띄운 PostgreSQL(pgvector)이 있어야 돌고 없으면 실패하므로(`docs/constitution/tech.md` 테스트 칸), 검사 러너(`tools/run_checks.py`)가 `compose.test.yml`로 테스트 DB를 띄우고 내리는 변경은 하네스 티켓으로 낸다. core의 첫 구현 티켓은 그 티켓에 Blocked by를 건다(`.scratch/core/plan.md`, `.scratch/plan-head.md`). 러너가 pytest를 always_run으로 돌리므로 변경 뒤에는 문서 PR과 하네스 chore를 포함한 모든 커밋에 Docker가 필요하다. 문서만 바뀐 커밋에서 pytest를 건너뛸지와 `SKIP=pytest` 우회를 막을지는 그 하네스 티켓이 정한다.
- **CLAUDE.md 레이어 절과 import-linter 계약.** 다섯 층(ADR 0007)으로 고치는 일은 core의 첫 구현 티켓이 패키지를 만들 때 같이 한다. 이 PR은 CLAUDE.md를 건드리지 않았다(`tools/check_ticket.py` 면제 밖).
- **어디서.** core 티켓은 Docker가 있는 로컬 세션에서 돈다. 명세와 티켓 쪼개기는 Docker 없이 된다. next-session 결정표에는 Docker 분기가 없어 지시문의 '어디서' 본문에 적고, 결정표에 더하는 일은 위 하네스 티켓이 함께 한다.
