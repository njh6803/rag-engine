# glossary-ask-remaining-names: 이 저장소에만 있는 이름 넷을 사용자에게 묻고 고른 것만 바꾼다 · 2026-11-19

앞 세션(일지 `2026-11-18-2230-glossary-root-branch-merge-back.md`)이 PR 70을 병합하고 낸 지시문으로 연 세션의 기록이다(Sonnet 5.5, high). 티켓은 `.scratch/harness/issues/glossary-ask-remaining-names.md`, 브랜치는 `chore/glossary-ask-remaining-names`이고, 새 워크트리 `glossary-ask-remaining-names`에서 `origin/dev`(7be8642)로 브랜치를 따서 했다. 용어집의 이름을 agent-os의 결정에 맞추는 일(받은 지시문의 원문 `.scratch/glossary-names-input.md`. 아래에서 "받은 지시문"은 이 글이다)의 다섯째 PR이고, 받은 지시문 5-2의 차례 4다. 계기, 세션을 열며 한 정리, 조사한 것, 물은 것과 사용자의 답, 한 것, 바꾸지 않고 남긴 것, 옛 이름의 잔존, 검증, 다음을 차례로 둔다.

## 계기

사용자가 아래 지시문을 첫 메시지로 넣어 이 세션을 열었다. 지시문의 핵심 줄이다.

```
받은 지시문 5-2의 차례 4(3절의 이름을 사용자에게 묻고 고른 이름을 바꾼다)를 티켓 .scratch/harness/issues/glossary-ask-remaining-names.md로 쓰고 한다

다음 작업: … 3절의 이름들(색인 판 계열, 임대, MCP 전송 설정, 상한, 변경 표지)을 선택 화면으로 묻고, 판 계열이 아닌 이름 가운데 고른 것을 바꾼다
이어받을 상태: … 색인 판 계열은 답만 일지에 받고 바꾸지 않는다(차례 5). 헌법이나 PRD에 고를 이름이 있으면 바꿀지를 물어 헌법 버전 규칙을 따른다. 워크플로 claude-code-review.yml 13·16행의 옛 이름 두 곳은 PR 70에서 뺐다 … 그 파일에 바꿀 이름이 더 생기는지 보고 따로 PR로 모은다. 옛 이름은 Grep multiline으로 줄바꿈 꼴까지 훑고 빈 출력을 일치 없음으로 읽지 않는다(대기열 rename-sweep-misses-forms 2회차)

```

이 일은 retro가 승인한 대기열 항목이 아니라 사용자의 직접 지시다. 티켓의 대기열 줄에는 `glossary-plain-names-left`(이름을 바꾸는 일 전체)와 `rename-sweep-misses-forms`를 적었다.

## 세션을 열며 한 정리

지시문대로 이 세션의 제목을 브랜치 이름으로 바꾸고(`set_session_title`) `tidy-checkouts` 스킬을 먼저 돌렸다. 이 세션은 주 체크아웃(`C:\project\rag-engine`)에서 열렸다.

- 주 체크아웃은 깨끗했고(`git status --porcelain`의 stdout과 stderr가 비었다) 원격에 없는 로컬 커밋이 0개였다. dev를 6957194에서 7be8642(`origin/dev`)로 당겼다. 앞 일지가 말한 추적하지 않는 파일 둘은 이번에는 없었다.
- 당긴 커밋이 `tidy-checkouts` 스킬 파일을 바꿨다(앞 PR의 "루트 브랜치" 이름 바꾸기). 스킬 지침대로 `git diff`로 바뀐 곳을 읽었고, 절차는 그대로이고 낱말만 바뀌어 같은 순서로 이었다.
- 지운 것은 병합된 로컬 브랜치 `worktree-glossary-root-branch-merge-back` 하나다(`judge`가 커밋이 모두 `origin/dev`에 있다고 냈고, 직전 `list_sessions`를 읽은 뒤 `remove-branch`로 하나씩 쳤다). 지운 워크트리는 없다.
- 남긴 워크트리와 이유는 다음과 같다. `05-full-run-rerank`는 폴더를 쥔 프로세스(tail.exe, grep.exe, cut.exe), `10-public-docs-questions`는 바뀐 파일, `13-first-judge-run`은 세션 `local_a6780d9a…`의 python.exe 열둘, `16-search-latency-probe-f30c20`과 `relaxed-grothendieck-e892b9`는 앱의 표지, `glossary-harness-small-names`와 `glossary-principal-to-requester`와 `glossary-release-names`와 `release-image`는 쥔 프로세스, `glossary-root-branch-merge-back`은 그 제목의 세션이 도는 중, `release-image-tickets`와 `release-search-eval`은 병합된 PR이 없다.
- 사람에게 넘긴 것은 워크트리 `14-reindex-version-switch` 하나다. 병합된 PR의 머리와 브랜치 끝이 다르다. 앞 세션들과 같은 것이고, 지시문대로 보고만 하고 답을 기다리지 않았다.
- 휴지통은 비우지 못했다. `empty-trash`를 쳤고 `.venv` 폴더 여덟이 남았다. 모두 `.pyd` 파일 하나에서 접근이 거부됐다(WinError 5). 다음 정리가 다시 본다.

그 뒤 `EnterWorktree`(name `glossary-ask-remaining-names`)로 새 워크트리에 들어갔고, 앱이 붙인 브랜치 `worktree-glossary-ask-remaining-names`에서 `git switch -c chore/glossary-ask-remaining-names`로 브랜치를 바꿨다(시작 커밋이 이미 `origin/dev`인 7be8642였다).

## 조사한 것

선택 화면을 올리기 전에 이름마다 살아 있는 글에서 쓰인 곳을 읽었다. 스크래치패드의 스크립트로 추적 파일과 미추적 파일을 훑고 범주(일지, 평가 자료, ADR 본문, 끝난 기능의 명세·티켓·프로브, 열린 개선 항목, 코드와 시험, 하네스, 헌법과 PRD)로 갈랐다. 아래 수는 모두 "살아 있는 글"만 센 어림이다. 지시문이 어림으로 준 수(임대 23개 파일 102곳, 상한 80개 파일 233곳)와 달라진 까닭은 기록과 평가 자료를 뺐기 때문이다.

- **변경 표지.** 이미 바뀌어 있었다. 2026-11-18에 `plain-words-in-written-artifacts` 티켓(PR 65, 커밋 e7eeab6)이 "변경 확인값"으로 바꾸고 `GLOSSARY.md`의 피할 말에 "변경 표지(옛 이름. 2026-11-18에 바꿨다)"를 넣었으며, ADR 0012의 이력에 "2026-11-18 용어집이 변경 표지의 이름을 변경 확인값으로 바꿨다" 항목을 달았다. 살아 있는 글에는 옛 이름이 용어집의 피할 말 줄과 그 이력뿐이라(`git grep`으로 읽었다) 사용자에게 묻지 않았다.
- **색인 판 계열**(색인 판, 현재 판, 건설 중인 판, 물러난 판, 살아 있는 판, 판 전환): 살아 있는 글 약 66개 파일 265곳. 이 PR은 바꾸지 않는다.
- **임대:** 코드와 시험의 주석·독스트링·시험 이름 18개 파일 86곳, README 1곳, `code-review` 스킬 1곳, 열린 개선 항목 둘 2곳(셋째 항목 `spec-review-transition-crossing`은 닫힌 항목이라 기록이다). 코드 식별자(`lease_seconds`, `leased_until`, `extend_lease`)는 그대로다. 평가 자료 `evals/public-docs/`의 "임대차"는 법령 이름의 일부라 다른 뜻이다. 시험 이름에 든 곳은 21개 함수다.
- **MCP 전송 설정:** README 1곳, 시험 `tests/server/test_mcp_assembly.py` 설명 1곳, 헌법 `docs/constitution/tech.md`의 "전송은 설정 …로 고르고" 한 문장. 헌법에 걸려서 같은 화면에서 헌법도 바꿀지 물었다. `src/rag_engine/server/auth.py`의 "MCP SDK의 전송 보안"은 SDK 기능 이름(`transport_security`)을 옮긴 말이라 이 이름이 아니다.
- **상한:** 살아 있는 글 약 81개 파일 248곳(코드와 시험 56개 파일 185곳, 하네스 8개 파일, 도구 8개 파일, 살아 있는 명세와 계획 5개 파일, 열린 개선 항목 4개 파일). 용어집 항목이 아니고 보통 낱말로 쓰였다. 비교하려고 같은 범위에서 "한도" 42개 파일 156곳, "제한" 50개 파일 207곳을 셌다.
- 워크플로 `.github/workflows/claude-code-review.yml`에는 "임대"와 "전송"이 없다. "상한"만 두 곳 있으나(81행 `턴 상한 초과`, 82행 `턴 상한 80`) 상한을 그대로 두기로 해서 그 파일은 바꾸지 않았고 따로 낼 PR도 없다.
- 헌법과 PRD에는 "임대"와 "상한"이 없다. "전송"은 `tech.md` 한 곳뿐이다.

## 물은 것과 사용자의 답

받은 지시문 3절은 이름마다 "지금 이름 → 후보 이름", 가리키는 것 한 줄, 바뀌는 파일 수를 선택 화면으로 보이고 고른 것만 하라고 했다. 변경 표지는 위 까닭으로 묻지 않았고, 나머지 넷을 한 화면에 올렸다. 아래의 질문과 선택지의 이름과 설명은 이 세션에서 올린 글자 그대로이고(대화 기록의 `AskUserQuestion` 입력에서 옮겼다), `> 사용자:` 줄이 답이다.

1. 질문(머리 `색인 판 계열`)

   ```
   지식베이스의 색인을 무엇으로 만들었는지 적어 둔 기록을 '색인 판'이라 부르고, 거기서 갈라진 이름이 여섯입니다(색인 판, 현재 판, 건설 중인 판, 물러난 판, 살아 있는 판, 판 전환). 이 여섯 이름의 '판'을 어떻게 할까요? 이번 PR은 답만 일지에 받고 아무것도 바꾸지 않으며, 바꾸는 일은 다음 차례에서 합니다.
   ```

   > 사용자: "버전으로 바꾼다 (Recommended)"

   - 첫째 선택지 `버전으로 바꾼다 (Recommended)`: 색인 판 → 색인 버전, 현재 판 → 현재 버전, 건설 중인 판 → 만드는 중인 버전, 물러난 판 → 물러난 버전, 살아 있는 판 → 살아 있는 버전, 판 전환 → 버전 전환. agent-os에서 고른 '앞말 없이 쓰인 판도 모두 바꾼다'와 같은 방향입니다. 쓰인 곳은 살아 있는 글 약 66개 파일 265곳(여섯 이름을 합쳐 센 어림)입니다. 걸리는 점: 계약에 붙이는 번호도 '버전'이 되므로 '계약 버전'과 '색인 버전'처럼 앞말을 붙여 가르는 규칙이 필요하고, 용어집이 피할 말로 적은 '인덱스 버전'·'스키마 버전' 줄도 고쳐야 합니다.
   - 둘째 선택지 `이 여섯은 '판'으로 남긴다`: 계약에 붙이는 번호만 '버전'으로 바꾸고 색인 쪽 여섯 이름은 지금 그대로 둡니다. 바꿀 곳이 없어 가장 가볍습니다. 걸리는 점: 같은 저장소에서 '버전'(계약)과 '판'(색인)이 비슷한 번호처럼 나란히 남아, 처음 보는 사람이 둘을 같은 종류로 읽을 수 있습니다.

2. 질문(머리 `임대`)

   ```
   작업을 어느 작업자가 언제까지 맡는지 작업 행에 적어 두는 기록을 지금 '임대'라고 부릅니다("임대가 끝나 다른 작업자가 가져간다", "임대를 늘린다", "임대 기간"). agent-os는 같은 종류의 기록을 '실행 담당 기록'으로 바꿨습니다. 이 저장소에서는 어떻게 할까요?
   ```

   > 사용자: "작업 담당 기록으로 (Recommended)"

   - 첫째 선택지 `작업 담당 기록으로 (Recommended)`: 임대 → 작업 담당 기록. agent-os의 이름과 같은 방향입니다. 바뀌는 곳은 코드·시험의 주석과 독스트링 18개 파일 86곳(시험 이름 21개 포함), README, 코드 리뷰 스킬, 열린 개선 항목 셋으로 약 23개 파일 92곳이고, ADR 0009에는 이력 한 항목을 답니다. 코드 식별자(`lease_seconds` 등)는 그대로입니다. 걸리는 점: '임대 기간', '임대를 늘린다'는 그대로 치환하면 어색해서("담당 기록 기간") 문장마다 읽고 풀어 써야 합니다.
   - 둘째 선택지 `작업 담당 기한으로`: 임대 → 작업 담당 기한. 실제 문장에 넣으면 "담당 기한이 끝나 다른 작업자가 가져간다", "담당 기한을 늘린다"로 자연스럽습니다. 바뀌는 곳은 위와 같은 약 23개 파일입니다. 걸리는 점: 기록 자체가 아니라 시간 제한만 가리켜서, "임대를 잃은 시도"는 "담당을 잃은 시도"처럼 문장마다 달리 써야 합니다.
   - 셋째 선택지 `그대로 둔다`: '임대'는 분산 시스템에서 쓰는 lease의 번역어이고 코드 식별자(`lease_seconds`, `leased_until`)와 짝이 맞습니다. 바꿀 곳이 없습니다. 걸리는 점: 처음 보는 사람이 집이나 사무실을 빌려주는 일로 읽을 수 있고, agent-os와 이름이 달라집니다.

3. 질문(머리 `MCP 전송`)

   ```
   MCP 서버가 클라이언트와 메시지를 주고받는 방법을 고르는 설정(`RAG_MCP_STATELESS`, `RAG_MCP_JSON_RESPONSE`)을 지금 'MCP 전송 설정'이라고 부릅니다. agent-os는 '전송'을 '연결 방식'으로 바꿨습니다. 이 저장소에서는 어떻게 할까요? 헌법 `docs/constitution/tech.md`에 "전송은 설정 … 로 고르고"라는 문장이 하나 있어서, 바꾸면 헌법 문구도 고치는지 함께 정해야 합니다.
   ```

   > 사용자: "연결 방식으로, 헌법도 (Recommended)"

   - 첫째 선택지 `연결 방식으로, 헌법도 (Recommended)`: MCP 전송 설정 → MCP 연결 방식 설정. 바뀌는 곳은 README, 시험 설명 한 곳, 헌법 `tech.md`의 한 문장으로 3개 파일입니다. 헌법을 바꾸므로 헌법 버전을 1.3.8에서 1.3.9(문구 수정)로 올리고, 그 까닭을 ADR 0014와 ADR 0016의 이력에 남깁니다. 열려 있는 형제 브랜치가 같은 버전을 쓰면 번호를 비켜 가야 합니다(지금은 겹침 검사로 확인합니다).
   - 둘째 선택지 `연결 방식으로, 헌법은 그대로`: README와 시험 설명 두 파일만 바꾸고 헌법 `tech.md`는 옛 말('전송')로 둡니다. 헌법 버전은 1.3.8 그대로입니다. 걸리는 점: 헌법과 README의 말이 어긋난 채 남습니다.
   - 셋째 선택지 `그대로 둔다`: '전송'은 MCP 규격이 쓰는 transport의 번역어이고 SDK 문서와 맞습니다. 바꿀 곳이 없습니다. 걸리는 점: agent-os와 이름이 달라집니다.

### 답을 읽은 방식

- 색인 판 계열은 "버전으로 바꾼다"이므로 답만 여기에 받았다. 이 PR은 이 계열의 어떤 글도 바꾸지 않았다. 바꾸는 일은 받은 지시문 5-2의 차례 5(판 → 버전)에서 하고, 그때 "계약 버전"과 "색인 버전"처럼 앞말로 가르는 규칙과 용어집의 피할 말 줄 고침이 함께 따라온다.
- 임대는 "작업 담당 기록"으로 바꿨다.
- MCP 전송 설정은 "MCP 연결 방식 설정"으로 바꾸고 헌법 `tech.md`도 고쳤다. 헌법 버전은 문구 수정(patch)으로 1.3.8에서 1.3.9로 올렸다.
- 상한은 사용자가 그대로 두라고 했으므로 아무것도 바꾸지 않았다.
- 사용자가 자기 후보를 적지 않아, 사용자 후보를 조사가 붙는 실제 문장에 넣어 다시 보이는 단계(받은 지시문 3절)는 없었다. 다만 선택지를 올리기 전에 후보를 실제 문장에 넣어 읽었고(임대 둘째 선택지의 "담당 기한이 끝나 …"), 그 읽은 결과가 선택지 설명에 들어 있다.
