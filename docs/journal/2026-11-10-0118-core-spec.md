## 이음매 확인

to-spec 2단계(테스트 이음매의 확인)와, 설계가 정하지 않은 범위 하나를 한 화면(질문 둘)으로 물었다. 둘 다 추천안을 골랐다.

- 질문(이 세션이 AskUserQuestion으로 물은 글 그대로): 명세의 테스트 이음매(테스트를 어디에 대고 밀지)를 어떻게 잡을까요? (선택지 셋: HTTP 표면 + 실제 PG + TEI 스텁, 유스케이스 단위 + 가짜 포트, 전부 실물(PG + 실제 TEI 컨테이너)).

> 사용자: "HTTP 표면 + 실제 PG + TEI 스텁 (Recommended)" — 설명: 주 이음매는 서버의 HTTP 표면입니다. REST는 httpx로, MCP는 공식 SDK 클라이언트로 접속하고, 뒤에는 Docker의 실제 PostgreSQL 테스트 DB와 우리가 만든 가짜 임베딩 서버(TEI의 /info·/v1/embeddings·/tokenize·/rerank를 흉내)를 붙입니다. 작업자는 테스트 안에서 '한 번 돌기' 입구로 돌립니다. 보조로 PostgreSQL 어댑터의 SQL(원자 교체, SKIP LOCKED, RRF)과 파서(픽스처 문서)는 좁게 따로 시험합니다. 장점: 검색 형식·인증·수집→검색 흐름을 클라이언트가 보는 그대로 검증하고, 구현을 바꿔도 테스트가 덜 깨집니다. 단점: 테스트마다 DB가 필요해 느립니다(템플릿 DB 복제로 완화).

- 질문(같은 화면의 둘째, 글 그대로): core v0의 범위에 최소 관리 API(토큰 발급·회수, 지식베이스 조회와 재색인 시작, 작업·문서 조회)를 넣을까요? (선택지 셋: 최소 관리 API를 core에 넣는다, 수집·검색만. 관리는 전부 admin으로, 관리 API를 넓게 core에(그룹·지식베이스 CRUD까지)).

> 사용자: "최소 관리 API를 core에 넣는다 (Recommended)" — 설명: 수락 기준(표본 폴더를 관리 API로 수집, 수집 중 검색)을 core 혼자 만족하려면 토큰 발급과 작업 상태 조회가 있어야 하고, 색인 판 전환(ADR 0008)을 검증하려면 재색인 시작이 필요합니다. 그룹·지식베이스·원천의 만들기·고치기·지우기(CRUD)는 admin 기능으로 넘기고, 기본 그룹·지식베이스는 migrate 명령이 설정값으로 만듭니다.

## 명세가 정한 것

명세는 `.scratch/core/spec.md`다. 결정 문단마다 표시를 하나 달았고, 서두의 수는 본문을 `grep -o`로 세어 맞춘다(아래 검증). 설계가 넘긴 넷과 PR #2의 Minor에 답한 자리는 다음과 같다.

- MCP 전송 설정 둘의 조립 자리: `server`의 `create_app`이 설정 객체의 값을 `streamable_http_app(stateless_http=…, json_response=…)`의 인자로 그대로 넘긴다(명세 "층, 패키지, 조립". 처음 `MCPServer`의 생성 인자라 적은 것은 셀프 리뷰가 잡아 프로브 `mcp-sdk/probe_progress.py` 101행대로 고쳤다).
- 작업 단위 포트 `UnitOfWork`의 모양: `begin()`이 비동기 컨텍스트 관리자를 내고 그 안의 객체가 `documents`·`index`·`jobs` 셋을 한 연결·한 트랜잭션 위에서 낸다. 블록을 예외 없이 나가면 커밋, 예외로 나가면 롤백이고 명시적 `commit()`은 두지 않는다. ADR 0007 이력으로 포트 열에 더했다.
- 테스트 이미지 판: 설계가 tech.md에 고정한 `pgvector/pgvector:0.8.7-pg18-trixie`를 그대로 옮기고, 격리는 템플릿 데이터베이스에서 테스트마다 복제하는 것으로 정했다.
- 파싱의 자원 한도와 영구 실패의 종결: 파싱은 spawn한 자식 프로세스에서 하고 시간(300초)·메모리(리눅스 `RLIMIT_AS` 2GiB)·쪽 수(1000)·압축 해제 합계(512MiB)·압축비(100, 1MiB 넘는 항목)·ZIP 항목 수(4096, 상수)·뽑은 글(64MiB)의 한도를 설정으로 둔다. 표 칸 수 한도는 거절했다. 파싱의 모든 실패와 임베딩 서버의 400·413·422, 차원 불일치는 영구 실패라 재시도 없이 `failed`이고, 일시 실패(연결 실패, 시간 초과, 424·429·5xx, 데이터베이스·파일 입출력 오류)만 30초×4ⁿ(상한 한 시간)으로 여섯 번까지 재시도한다.
- PR #2의 Minor(포트마다의 값): Connector·Transform은 플러그인 자리(core 구현 없음), Parser는 플러그인 자리이자 실패 분류 시험의 가짜 자리, Chunker는 전략 자리(교체 경계도 가짜 자리도 아님), Embedder·Reranker는 외부 서비스 경계이자 가짜 자리, VectorIndex·DocumentStore·JobQueue는 PostgreSQL 어댑터 하나씩으로 작업 단위 안에서만, BlobStore는 교체 경계(S3는 나중). ADR 0007 이력에 같은 내용을 적었다.

그 밖에 정한 것은 설정 이름과 기본값, 표 열둘의 칸, 수집 API의 칸과 `action` 다섯, 작업 `index_document`의 처리 순서 넷과 실패 분류, 재색인 시작과 판 전환, 청킹 규칙 여섯과 `/tokenize` 바이트 오프셋의 글자 인덱스 변환, TEI 어댑터의 `/info` 확인과 오류 코드 매핑, 키워드 품사 집합과 전처리, 검색 일곱 단계(RRF k=60, 후보 50, `SET LOCAL hnsw.ef_search`와 `iterative_scan`), MCP 도구 셋의 입력·출력 형식(`format_version` "1.0")과 오류 코드, 토큰 역할 둘과 미들웨어의 401·403, 관리 API 열, 관리 명령 다섯의 인자, 삭제·되살림·묘비의 규칙, 로그 이벤트와 요청 ID, 테스트의 격리와 TEI 스텁의 모양이다. 거절은 여섯(표 칸 수 한도, 리랭크 실패 때 RRF 대체 응답, 정확 스캔 분기, core의 정리 작업, 설계가 거부한 것 다섯의 되살림, 준비 확인·마지막 사용 시각·들어오는 요청 ID 신뢰·문서 단위 묶기)이다.

ADR 본문을 거짓으로 만든 결정 둘에는 같은 작업에서 이력과 포인터를 달았다. ADR 0006(부분 HNSW 색인은 색인 판 단위이고 벡터 열은 차원 없는 `vector`에 캐스트 표현식으로 색인한다. ADR 본문은 임베딩 모델마다의 부분 색인과 고정 차원을 전제했다), ADR 0007(포트 열에 `UnitOfWork`를 더하고 포트마다의 값을 밝힌다). 새 ADR은 없다.

두 이력은 셀프 리뷰 반영 뒤 2026-11-10에 AskUserQuestion으로 승인받았다. 질문(글 그대로): 명세가 ADR 둘의 본문을 바꾸어 이력을 더했습니다. 헌법 거버넌스대로 사용자 승인이 필요합니다. ADR 0006 이력(HNSW 부분 색인을 지식베이스 단위가 아니라 색인 판 단위로 걸고, 벡터 열을 차원 없는 vector로 두어 판마다 캐스트 표현식으로 색인한다)과 ADR 0007 이력(포트 열에 작업 단위 포트 UnitOfWork를 더하고, 포트마다 교체 경계인지 테스트 가짜 자리인지를 밝힌다. 주 이음매는 사용자가 고른 HTTP 표면 + 실제 PG + TEI 스텁)을 승인하시겠습니까? 선택지 넷: 둘 다 승인, 0006만 승인, 0007만 승인, 둘 다 보류.

> 사용자: "둘 다 승인 (Recommended)" — 설명: 두 이력을 그대로 두고 커밋으로 갑니다. 0006 이력은 재색인 동안 옛 판과 새 판이 나란히 있어야 하고 모델이 바뀌면 차원도 바뀔 수 있다는 ADR 0008의 결과를 색인 구조에 옮긴 것이고, 0007 이력은 셋(문서 저장소, 벡터 색인, 작업 대기열)을 한 트랜잭션으로 묶는 자리를 포트로 만든 것입니다. 둘 다 새 결정이 아니라 앞선 결정을 끝까지 적용한 것이라 추천합니다.

## 사실의 출처

명세가 잰 것 다섯은 `.scratch/core/probes/`에 두고 README 표에 행을 더했다(2026-11-10 추가분). 실행은 `uv run python -I -X utf8 <파일>`이고 출력은 옆의 `*_out.txt`다. 넷은 exclude를 비운 pyrightconfig로 strict 0 오류이고 그 JSON 출력을 폴더마다 `pyright_out.json`으로 남겼으며, Kiwi 프로브는 kiwipiepy에 py.typed가 없어 스텁 없음 오류 하나가 남는다(ADR 0006이 우리 스텁을 두기로 한 사정).

- UUIDv7 라이브러리(`uuid/probe.py`, 출력 `probe_out.txt`, pyright `pyright_out.json`): uuid6 2025.0.1은 순수 파이썬이고 값이 표준 라이브러리 `uuid.UUID`의 하위 타입(MRO에 있음)이며, uuid-utils 1.2.0은 바이너리이고 하위 타입이 아니다(`uuid_utils.compat`가 따로 있다). 10만 개 생성은 uuid6 0.232초, uuid-utils 0.046초이고 둘 다 단조 증가였다. 명세는 uuid6을 골랐다.
- pgvector README 원문(`facts/pgvector_readme_facts.py`, 태그 v0.8.7의 README를 받아 줄 번호와 함께 찍음): 차원 없는 열에 `(embedding::vector(3))` 표현식으로 색인을 거는 예와 `WHERE`가 붙은 부분 HNSW 색인(842행. 836~850행을 통째로 찍었다), `hnsw.ef_search` 기본 40과 결과가 그 수로 잘린다는 문단(935행. 930~937행을 통째로 찍었다), `hnsw.iterative_scan`의 두 모드와 `max_scan_tuples`·`scan_mem_multiplier`.
- TEI OpenAPI 원문(`facts/tei_info_and_rerank_fields.py`, 태그 v1.9.4의 `docs/openapi.json`): `Info` 스키마의 필수 칸, `RerankRequest`의 칸(`query`, `texts`, `raw_scores`, `return_text`, `truncate`, `truncation_direction`)과 `TruncationDirection`의 열거 값(`Left`, `Right`. 기본 `Right`), `Rank`의 칸, `TokenizeInput`이 문자열 또는 문자열 배열인 것, `/v1/embeddings`·`/rerank`·`/tokenize`의 응답 코드.
- 파서 셋의 내장 한도(`parsers/limits_probe.py`): PyPI 메타데이터로 판을 고정해(pdfplumber 0.11.10이 요구하는 pdfminer.six 20260107, python-docx 1.2.0, python-hwpx 6.11.0) 휠을 받아 XML 파서 옵션, ZIP 한도, 재귀, 쪽 수·시간 제한 관련 코드를 정규식으로 셌다. pdfplumber와 pdfminer.six에는 `maxpages` 말고 한도가 없고, python-docx는 `remove_blank_text=True, resolve_entities=False`만 있으며, python-hwpx는 `opc/xml_utils.py`의 XML 옵션과 `opc/security.py`의 ZIP 한도 상수(재실행에서 `zip_limit_values` 절로 값까지 찍었다. 설계 일지 `## 다음`이 적은 값과 같다)를 가지지만 기본 파서를 부르는 자리도 25곳 있다.
- Kiwi 토큰 출력(`kiwi/probe.py`): kiwipiepy 0.24.1, 모델 0.24.0으로 표본 다섯의 토큰·품사·위치와 문장 분리를 찍었다. "지식베이스"가 `지식/NNG 베이스/NNG`로 갈리고, 영어 문장 끝의 `search.`가 `s/SL earch./SL`로 갈려 명세가 라틴 어절 뒤 구두점 분리 전처리를 두었다. 셀프 리뷰 뒤 마침표를 공백으로 뗀 다섯째 표본을 더해 다시 돌렸고 `search/SL ./SF`로 바로 섰다(전처리의 효과를 잰 것).

- 프로브 README 두 행(pgvector, TEI)의 회차를 봇 1회차로 고쳤다(표준 판단 항목).
- 기록 정정. 첫 반영 뒤 이 일지의 5번 항목과 회고 줄, 대기열 본문, PR 코멘트와 커밋 메시지 초안에 1회차 규칙의 문서 행 `FOR UPDATE`가 재색인 시작과 교착한다고 썼다. 명세 축의 교착 짝 지적을 따지다 틀린 것을 알았다. 1회차 규칙에서는 재색인 시작이 지식베이스 행을 잠그지 않는다. 커밋 전에 모두 고쳤다.

**남긴 것과 이유.**
- X5 [Minor]. 일시 실패로 다시 `queued`가 되는 작업이 같은 문서의 새 대기 작업과 부분 유일 색인에서 부딪힌다. 합치는 규칙은 재색인 시작의 대기 작업 잠금과도 얽히는 작업 대기열의 결정이라 다음 세션이 명세에 정한다.
- X6 [Minor]. `migrate`가 잠금 규칙 밖이다. 판 행을 고치는 순서를 잠금 규칙에 넣을지 다음 세션이 정한다.
- X7 [Minor]. 재색인 시작이 `CREATE INDEX`의 SHARE 표 잠금을 커밋까지 쥐어 조각 쓰기가 멈춘다. 판마다 HNSW 부분 색인을 만드는 것은 ADR 0006 이력의 결정이라, 바꾸려면 그 이력을 다시 열어야 한다.
- X8 [Minor]. 검색의 둘째 단계와 넷째 단계 사이에 옛 판이 정리되면 빈 결과가 난다. 다음 세션이 명세에 정한다.
- 용어 표류(표준 판단). 명세 용어 넷을 용어집에 올릴지는 domain-modeling의 승인 몫이라, 다음 세션이 spec-reviewer 지적과 함께 가른다.
- 산문의 중복(표준 판단). 잠금 규칙 문단이 원천이고 다른 자리는 그 문단을 가리킨다. 셋째 단계 문단의 중복 문장만 지웠다.
- 프로브 `fetch`의 모양 겹침(표준 판단). 프로브는 저마다 혼자 도는 스크립트라 공유 모듈을 두지 않는다. 재시도는 이 프로브가 받는 문서의 연결이 끊긴 일 때문에 두었다.
- 근거의 종류(표준 판단). 명세는 교착 결론을 측정이라 적지 않았다. 실제 PostgreSQL에서 교착하지 않는지는 명세의 어댑터 잠금 시험이 잰다.
- 대기열 본문의 중복(표준 판단). 앞 회차 항목들의 선례를 따랐다.

새로 쓴 사실 문장(다음 회차가 겨냥할 주장): PostgreSQL 18에서 `SKIP LOCKED`는 바로 잠글 수 없는 행을 건너뛰고, 행 잠금은 트랜잭션 끝에 풀린다(프로브 `facts/pg_row_lock_facts.py`). 새 규칙: 재색인 시작의 대기 작업 잠금, 수집의 잠금 시점과 범위(`FOR SHARE`와 `FOR UPDATE`), 잠금 순서의 작업 행, 그룹을 바꾸는 수집의 삭제와 전환 검사, 조각을 만든 원본의 내용 해시와 되살림의 조건, v0에서 검색의 그룹 집합 조건이 거르는 조각이 없다는 주장.

**다시 돌린 명령과 결과.** 프로브 `pg_row_lock_facts.py`를 다시 돌려 출력과 `facts/` pyright JSON을 LF로 정규화했다(pyright strict 파일 9, 오류 0). 손으로 친 것은 모두 0이거나 경고 0이다. `check_md_tables.py`, `check_line_separators.py`, `check_quotes.py --all-lines`(바뀐 md 스물셋, 인용 23건), `check_adr_pointers.py`, `plan_table.py --check`, ruff check·format, `sibling_overlap.py`(겹침 없음), `queue_open_rows.py`(열린 항목 14, 회차 5 이상 없음), 바뀐 파일의 CR 0이다. 표시 수는 본문의 `grep -o`로 `[넘겨받음]` 21, `[사용자 선택]` 2, `[정함]` 93, `[이력]` 2, `[거절]` 7 그대로다. 테스트·타입체크·경계 검사는 커밋의 pre-commit으로 갈음한다.

- **이어받을 것.** PR #3 봇 1·2회차가 고친 자리(동시성 교차의 잠금과 2회차의 잠금 규칙, 실패·재시도 소진·삭제 뒤의 전환 검사, 색인 판의 끝점과 청킹 설정, 상한을 임베딩 입력 전체로, 저장 단계의 재확인, 검색의 그룹 집합 조건, 되살림의 대상 판)는 명세 본문에 있고 지적마다의 판정은 위 `## PR 봇 회차`다. 셀프 리뷰에서 보류한 넷(`include_text` 불리언, `kind`·`effective_date`·`access_groups` 칸, 같은 판의 칸 추가, ADR 0008 이력 요구)은 `### 반영`에 이유가 있고 티켓으로 가지 않는다. core의 첫 구현 티켓은 검사 러너가 테스트 DB를 띄우는 하네스 티켓에 Blocked by를 건다(`.scratch/core/plan.md`, 앞 일지 `## 다음`).
- **봇 2회차와 그 셀프 리뷰에서 넘긴 것.** 이 PR에서 고치지 않았다. 다음 세션이 spec-reviewer의 지적과 함께 명세에 반영한다. 봇 2회차의 Minor 둘은 절 경로만으로 상한을 넘는 조각의 처리(청킹 절, CodeRabbit)와, 어댑터가 HTTP 상태와 데이터베이스 오류를 `domain`의 영구·일시 예외로 옮긴다는 문장(실패 분류, claude-review. 첫 구현 티켓의 수용 기준이 받는다)이다. 셀프 리뷰의 Minor 넷은 다시 예약한 작업과 새 대기 작업의 부분 유일 색인 충돌(X5), `migrate`와 잠금 규칙(X6), 재색인 시작의 `CREATE INDEX`가 쥔 표 잠금(X7, ADR 0006 이력), 검색 도중의 옛 판 정리(X8)다. 명세 용어 넷(대상 판, 저장 단계, 복사 칸, 건설 중인 판)을 용어집에 올릴지도 가른다. 판정과 이유는 위 `## PR 봇 회차`의 2회차와 그 셀프 리뷰다.
