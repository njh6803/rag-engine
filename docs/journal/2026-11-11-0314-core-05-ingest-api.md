티켓 `.scratch/core/issues/05-ingest-api.md`를 구현한 기록이다. next-session 지시문이 연 새 세션(Sonnet 5.5 / high)이고 브랜치는 `feature/05-ingest-api`, 작업은 워크트리 `ingest-api`에서 했다. 지시문의 이번 요청 범위는 PR과 병합까지다. 준비, 정한 것, 손으로 본 것, 코드 리뷰, PR 직전 리뷰, 회고, 다음을 차례로 둔다. 셀프 리뷰(코드 리뷰 절)의 보고는 받은 턴에 옮기지 못했다. 그 사이에 컨텍스트가 압축되어 지적별 원문은 잃었고 압축 요약에 남은 판정(고친 것, 남긴 것)만 옮겼다(04 일지의 `review-report-journal-lag`가 둘째로 난 것이고 회고 절에 적었다). ## 준비

- 읽은 것: 구현 스킬, 티켓, 명세(`.scratch/core/spec.md`)의 수집 API·수집 파이프라인과 작업·데이터 모델 절, 직전 일지(`2026-11-11-0225-core-04-app-auth-logging.md`)의 "다음".
- 주 체크아웃이 `origin/main`보다 뒤라 지시문대로 `tidy-checkouts`를 먼저 돌고 워크트리 `ingest-api`에 들어가 브랜치를 땄다. 06(TEI·Kiwi·청킹)은 다른 세션이 PR #8로 돌고 있다.
- 새 환경 변수를 더하지 않았다(`RAG_MAX_UPLOAD_MB`와 `RAG_DATA_DIR`은 04까지 있던 설정이다). 그래서 `.env.example`은 만들지 않았고 그 결정은 계속 사용자에게 남는다.

## 정한 것

- **원본은 작업 단위 밖에서 먼저 쓰고 새 경로에 둔다.** 저장 키는 `blobs/<문서 UUID>/<원본 UUID>`이고 `LocalBlobStore`(`adapters/blob_store.py`)가 `RAG_DATA_DIR` 아래에 쓴다. 롤백되면 그 요청이 쓴 새 원본만 지우고, 커밋된 뒤에는 문서 행이 더는 가리키지 않는 원본(옛 원본, 또는 `unchanged`가 쓴 새 원본)을 지운다. 지우기는 최선 노력이고 못 지우면 로그 `orphan_blob_left`를 남긴다. 오류 메시지에는 운영체제 문구를 싣지 않는다(원칙 V).
- **같은 키의 동시 수집은 (원천, 키) 유일 제약이 직렬화한다.** 진 쪽은 `DocumentAlreadyExistsError`를 받고, 원본을 이긴 문서의 UUID 아래 새 경로로 다시 써서 한 번 더 처리한다(`_MAX_ATTEMPTS = 2`). 이 예외는 `RagEngineError`가 아니다. 요청 오류가 아니라 유스케이스 안의 신호다.
- **`unchanged`만 200이고 나머지는 202다.** 같은 내용이면 작업을 넣지 않고 제목, 메타데이터, 호출자가 준 갱신일만 문서 행에 반영한다. 갱신일이 바뀌면 같은 트랜잭션에서 그 문서의 모든 조각 행의 복사 칸을 고친다(`VectorIndex.update_chunk_copies`).
- **대기 중인 작업은 재사용한다.** 같은 문서의 `queued` 작업이 있으면 `run_after`와 `request_id`만 고친다(부분 유일 인덱스 `uq_jobs_document_id_queued`와 `ON CONFLICT`). 작업을 넣으면 같은 트랜잭션에서 `pg_notify('rag_jobs')`를 부르고, 알림은 커밋될 때 간다.
- **잠금 순서는 문서 행, 지식베이스 행, 작업 행이다.** 문서 행은 `FOR NO KEY UPDATE`, 지식베이스 행은 `FOR SHARE`(문서가 드는 그룹의 것, ID 순서)다.
- **형식 판정은 확장자를 먼저 믿고, 모르는 확장자면 내용을 본다**(`domain/media_types.py`). `%PDF-`로 시작하면 PDF, ZIP이면 항목(`word/document.xml`, `Contents/header.xml`)으로 DOCX와 HWPX를 가른다. 셋이 아니면 415이다.
- **크기 상한은 본문을 읽기 전에 업로드가 알린 크기로 먼저 본다**(`file.size`). 다만 멀티파트 파서가 상한을 넘는 업로드도 임시 파일로 받은 뒤에 거절하므로 디스크는 쓴다. 이 한계는 `server/ingest_api.py` 독스트링에 적었다.
- **`IngestAction`을 `domain/entities.py`로 옮겼다.** 유스케이스(`app`)와 응답 모델(`server`)이 함께 쓰는데 `app`은 `server`를 import할 수 없어서다.
- **라우터는 `token_api.py`와 같은 모양**(`build_ingest_router`)이고 `create_app`이 그 `routes`를 요청 문맥 미들웨어에 넘기는 목록에 더한다(`.claude/rules/server.md`). 폼은 Pydantic 모델(`IngestFields`)과 `UploadFile`을 한 라우트에 함께 받는다(FastAPI 0.162.2에서 된다).
- **그룹을 바꾸는 수집과 지운 문서를 되살리는 수집은 `NotImplementedError`로 멈춘다.** 각각 티켓 10과 11이 처리한다. 티켓 07·10·11에 05가 넘기는 것을 적었다.
- **시험 하네스.** `tests/conftest.py`에 스키마만 올린 빈 DB의 `engine` 픽스처를 올렸다(처음에는 `tests/adapters/conftest.py`에 있었으나 `tests/app`도 쓴다). 문서 행 공장과 원천·그룹 심기는 `tests/records.py`다.

- **변이.** 시험이 구현과 함께 자랐으므로 `tools/mutate.py`의 TOML 표(`.scratch/core/probes/ingest_mutations.toml`)로 변이 스무 개를 돌렸다(1~16번은 구현과 셀프 리뷰, 17~20번은 PR 직전 리뷰의 반영이고 아래 그 절에 있다). 스무 개 모두 기대한 표지와 함께 빨강이다. 첫 실행에서 두 개가 초록으로 살아남았다.
  - 4번(키도 파일 이름도 없는 요청을 받는다): HTTP 시험이 `filename=""`을 422로 읽는 다른 길이 있어 유스케이스의 검사를 지워도 빨개지지 않았다. `tests/app/test_ingest.py`에 유스케이스를 직접 부르는 시험을 더해 그 검사를 겨누게 했다.
  - 7번(건너뛴 수집이 갱신일의 조각 복사 칸을 고치지 않는다): 조각 행을 두고 갱신일을 바꿔 본 시험이 없었다. 조각을 심는 도우미(`tests/records.py`의 `insert_chunk`)와 시험을 더했다.
- 표지를 고르다 틀린 것이 있다. 호출 한 토막 표지(7번)와 틀린 HTTP 이유 문구(1번), 숨은 원인(12번)을 실제 실패 출력으로 바꿨다. `--check ... --since origin/main`이 표지 품질을 통과한다.
- 16번은 코드 리뷰가 낸 지적을 겨눈다(이긴 문서 아래로 옮기다 쓰기가 실패해도 처음 쓴 원본을 지운다). 같은 지적으로 더한 시험 `test_이긴_문서_아래로_옮기다_쓰기가_실패하면_처음_쓴_원본을_지우고_오류를_올린다`가 그 변이를 잡는다.

## 코드 리뷰

`/code-review`로 두 축을 돌렸다(범위: `origin/main` 이후 작업 트리의 수정과 미추적 파일 전부). 표준 축과 명세 축 모두 Critical은 없었고, Major가 하나(로그 사유가 포매터에 실리지 않음), 나머지는 Minor와 Nit이다. 서브에이전트가 만든 임시 프로브 파일(`tests/server/test_zz_probe_tmp.py`)은 지운 것을 확인했다.

고친 것:
- **Major. `orphan_blob_left` 사유가 로그에 실리지 않았다.** 로그 포매터는 `event_fields`와 `exc_info`만 내보낸다. `extra`로 넣은 이유가 버려져 있었다. `exc_info=error`로 바꿔 예외 타입과 이 저장소가 정의한 예외의 메시지만 싣는다(원본 경로와 문서 키는 싣지 않는다). 시험은 `JsonLinesFormatter`를 거쳐 실제 출력 줄을 단언하도록 고쳤다.
- 큰 크기 검사의 독스트링이 `Content-Length` 사전 검사를 한다고 읽혔다. 멀티파트 파서가 임시 파일로 받은 뒤 `file.size`로 본다는 사실대로 고쳤다.
- 이긴 문서 아래로 옮기다 두 번째 쓰기가 실패하는 길의 시험이 없었다. `_SecondWriteFailsBlobStore`와 시험을 더했다(변이 16).
- 작업 단위 시험이 "네 속성의 쓰기가 한 트랜잭션"이라 하면서 `catalog`와 `index`는 밟지 않았다. 롤백 시험과 커밋 시험이 `catalog`(지식베이스, 색인 판), `index`(판 색인), `documents`, `jobs`를 한 블록에 쓰고 데이터베이스에서 직접 읽어 확인하도록 늘렸다.
- 시험 이름이 본문보다 넓은 것(`키도_파일_이름도_없으면_422다`는 이름이 빈 경우만 본다, `서로_다른_키는...`은 같은 원천 안만 본다)을 본문에 맞게 바꿨다.
- 티켓 05의 보류 문장(07·10·11에 넘기는 것)을 사실대로 고쳤다.

남긴 것과 이유(PR 본문 "남긴 위험"에도 적는다):
- **확장자와 내용이 어긋날 때의 해석.** 명세는 "확장자를 먼저 보고, 없거나 맞지 않으면 바이트 머리로"라고 쓴다. 지금은 아는 확장자면 그대로 믿으므로 `a.pdf`라는 이름의 ZIP 바이트는 PDF로 저장된다(파서가 실패하면 그때 `parse_failed`). "맞지 않으면"을 내용 검증으로 읽을지는 명세 해석이라 사용자에게 넘긴다.
- `%PDF-`로 시작해야 PDF로 본다. 명세는 `%PDF`다. 실제 PDF 머리는 `%PDF-`로 시작하므로 영향이 없다고 보고 두었다.
- 내용이 바뀐 `updated`는 조각 행의 복사 칸을 고치지 않는다. 작업자가 조각을 통째로 바꾸므로 필요 없다고 판단했다(티켓 07·10이 확인).
- 크기 상한을 넘는 업로드는 멀티파트 파서가 임시 파일로 받은 뒤에 413이 된다. `Content-Length` 사전 검사를 하지 않았다(독스트링에 적었다).
- 두 번째 경합에서도 지는 분기와 반복문은 현재 도달하지 않는다(Speculative Generality 지적). 경합이 끝나지 않는 일은 없다는 보장이 없어 방어로 둔다.
- 스멜 기준선의 Minor·Nit: 정리와 재발생 코드가 두 곳에 비슷하게 있다, `request_id`와 `now`가 함께 다닌다(Data Clumps), `_Upload`가 `IngestRequest`의 칸을 일부 되풀이한다, `_locate`의 이름, `_BYTES_PER_MB`의 자리. 판단 항목이고 동작에 영향이 없다.
- 색인 실패 상태의 문서를 같은 내용으로 다시 올리면 `unchanged`(200)가 된다. 티켓 10이 `requeued`로 바꾼다.

다시 돌린 명령: `ruff format`, `ruff check .`, `ruff format --check .`, `pyright`(0 오류), `lint-imports`, `tools/check_type_escapes.py`, 손댄 시험 파일 pytest(`test_unit_of_work.py`, `test_document_store.py` 초록), 변이 13·16과 `--check --since origin/main`(통과).

## PR 직전 리뷰

CodeRabbit CLI(0.7.5, `Seat: not assigned`)는 돌지 못했다. `coderabbit-review` 에이전트가 코드가 외부 서비스로 나간다는 이유로 권한 분류기에 거부당했고, 우회하지 않았다. 그래서 운영 문서(리뷰 파이프라인 2)대로 같은 축을 `bug-perf-review` 에이전트와 내장 `/security-review` 절차가 맡았다. 그 전에 `coderabbit-review` 에이전트가 CLI 없이 직접 읽은 보고(Minor 7, Nit 7)도 있다.

**`bug-perf-review`가 Critical을 하나 냈고 재현해서 맞았다.**
- **Critical. `job_queue.py`의 `ON CONFLICT` 술어가 바인드 파라미터로 나갔다.** 부분 유일 색인의 술어(`status = 'queued'`)를 값 바인딩으로 보내면, psycopg가 같은 문장을 다섯 번 돌린 뒤 서버에 준비시키고 일반 계획이 파라미터를 상수로 접지 못해 색인을 찾지 못한다(`InvalidColumnReference`, 42P10). 한 연결에서 수집이 열 번쯤 성공한 뒤부터 모든 수집이 500이 된다. 유닛 시험은 연결을 새로 만들어 써서 못 잡았다. 내가 같은 연결로 열다섯 번 커밋하며 넣는 시험을 먼저 써서 빨강을 확인했다(`no unique or exclusion constraint matching the ON CONFLICT specification`). 술어를 리터럴(`sa.literal_column`)로 렌더링해 고쳤고 변이 18번이 그 원문을 겨눈다.
- **Minor(고침). 머리만 ZIP인 입력이 415가 아니라 500이 됐다.** `_sniff_zip`이 `BadZipFile`만 잡아 지원하지 않는 버전(`NotImplementedError`)과 UTF-8 표지가 선 잘못된 항목 이름(`UnicodeDecodeError`)이 새 나갔다. 중앙 디렉터리 바이트를 직접 고쳐 두 입력을 만들어 빨강을 확인하고 예외 범위를 넓혔다. 변이 19번.
- **Minor(고침). 커밋이 됐는지 모르는 실패가 문서 행이 가리키는 원본을 지웠다.** `coderabbit-review`와 `bug-perf-review`가 같은 경로를 짚었다. 커밋 응답을 받지 못한 연결이나 취소 뒤에 `except BaseException`이 새 원본을 지우면 문서 행은 사라진 원본을 가리키고, 같은 내용을 다시 보내도 `unchanged`라 복구되지 않는다. 시험은 커밋 뒤 블록을 나가며 예외를 내는 작업 단위로 빨강을 확인했다. 지우기 전에 문서 행이 그 원본을 가리키는지 읽고(`_discard_unless_recorded`), 행을 읽지 못하면 고아로 남긴다. 변이 20번.
- **Minor(고침). 파일 이름에 든 NUL이 DB 오류로 500이 됐다**(`coderabbit-review`). 시험으로 재현(`PostgreSQL text fields cannot contain NUL`)한 뒤 원본을 쓰기 전에 `InvalidInput`(loc `("file",)`)으로 거른다. 변이 17번.
- Nit(고침). 티켓 05가 `done`인데 수용 기준 체크박스가 모두 비어 있었다. 04 티켓의 관례대로 모두 `[x]`로 닫았다.
- 밀어 본 주장 셋(NUL 거르기, 작업 단위 시험이 네 속성을 증명함, `orphan_blob_left`가 경로를 싣지 않음)은 성립했다. 다만 로그 시험은 고정 문구만 보므로 실제 `OSError` 경로에서 메시지가 새지 않는지는 시험이 닿지 않는다.

**내장 보안 리뷰: 후보 없음.** 경로 조작(원본 경로는 서버가 만든 UUID 두 조각뿐이고 `_path`가 `is_relative_to`로 한 번 더 막는다), SQL 주입(Core 바인딩, DDL은 정수와 UUID뿐), ZIP 파싱(항목 이름만 읽고 풀지 않는다), 인증(`reader`는 `/mcp` 밖 403, MCP로 쓰기가 열리지 않는다), 로그(예외 타입과 이 저장소 예외의 메시지만)를 확인했다. 신뢰도 0.8 이상 후보가 없어 거짓 양성 검증 단계는 생략했다.

남긴 것과 이유:
- `unchanged`가 `mime`을 고치지 않는다(`a.pdf` 이름의 DOCX 바이트를 `a.docx`로 다시 올려도 PDF로 남는다). 명세가 `unchanged`가 고치는 칸을 제목·메타데이터·갱신일로 정했고, 확장자와 내용이 어긋날 때의 해석(위 "남긴 것")과 같은 뿌리라 사용자 판단으로 넘긴다.
- `sha256`과 `zipfile`이 이벤트 루프 스레드에서 돈다. 100MB 근처에서 수백 밀리초쯤 걸린다는 어림이고 재지 않았다. `asyncio.to_thread`로 넘기는 일은 검색·수집이 한 프로세스에서 부하를 받는 시점(07 이후)에 잰 뒤 정한다.
- 매우 긴 키(btree 색인 항목 약 2.7KB 초과)는 DB 오류로 500이 될 수 있다(추측, 재현하지 않았다). 키 길이 상한은 수집 API 계약의 칸이라 명세 판단이다.
- `Content-Length` 사전 검사 없음, `_remove_quietly`가 `TransientFailure`만 잡는 것(`LocalBlobStore`가 `OSError`를 `TransientFailure`로 올리므로 어댑터 계약으로 닫혀 있다), `key`·`group`·`metadata`의 NUL을 API 모델에서만 거르는 것(CLI가 유스케이스를 직접 부르게 되는 때 같이 본다), `update_chunk_copies`가 모든 판의 조각 행을 갱신하는 것(조각이 많은 문서로 잰 값이 필요하다), `fsync` 없음, 빈 문서 폴더가 남는 것, `OpenAPI` 응답 목록에 200과 422가 빠진 것, `group=""`와 `key=""`의 처리가 다른 것: 판단 항목이고 지금 동작에 영향이 없다.
- 그룹이 바뀐 재수집과 지운 문서의 재수집은 `NotImplementedError`로 500이다(티켓 10·11이 처리한다). 이 PR 단독으로는 클라이언트가 재시도할 오류처럼 보이므로 PR 본문 "남긴 위험"에 적는다.

다시 돌린 명령: `ruff format`, `ruff check .`, `pyright`(0 오류), `lint-imports`, `tools/check_type_escapes.py`(모두 0), 손댄 시험(`test_job_queue.py`, `test_media_types.py`, `test_ingest.py`, `test_ingest_api.py`) 초록, 변이 17~20 기대대로. 전체 pytest(3065개 통과)는 이 반영 전에 한 번 돌았고 반영 뒤 전체는 커밋의 pre-commit 러너가 다시 돈다.
