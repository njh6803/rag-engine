# dev-base-tools: 기준 브랜치 규칙과 도구의 dev 인식 · 2026-11-12

`next-session` 지시문으로 연 새 세션의 기록이다(Sonnet 5.5 / high). 시작 프롬프트는 `/implement .scratch/dev-branch/issues/01-dev-base-tools.md`이고, 브랜치는 `feature/01-dev-base-tools`, 작업은 워크트리 `01-dev-base-tools`에서 했다. 나란히 여는 3 중 1이고 02(`dev-review-bot-off`, PR #24, 병합됨)와 03(`dev-base-skills-docs`)이 다른 세션에서 돌았다. 준비, 확인한 것과 정한 것, 셀프 리뷰, PR 직전 리뷰, 검증, 회고, 다음을 차례로 둔다.

## 준비

- 묶음의 첫 세션이라 지시문대로 `tidy-checkouts`를 먼저 돌고, 주 체크아웃에서 브랜치를 따지 않고 `EnterWorktree`로 워크트리에 들어가 거기서 브랜치를 `feature/01-dev-base-tools`로 바꿨다.
- agent-os는 읽기만 했다(`git -C C:/project/agent …`). 작업 폴더를 옮기는 `cd`는 훅이 거부해서 `-C`와 경로 인자로 풀었다.
- agent-os의 전환 구간(`d7fdb250e`에서 `4b02bbe29`)의 파일을 blob 해시로 견주어 가른 결과가 설계 세션의 셈과 같았다: 그대로 얹을 파일, 이 저장소 파일과 3-way로 합칠 파일, agent-os가 새로 만든 파일 둘(`tools/base_rule.py`, `tests/tools/test_base_rule.py`). 같은 파일은 `git apply`로, 다른 파일은 `git merge-file`(이 저장소 파일, 전환 직전 판, 직후 판)로 얹었다. 파일마다 들인 길은 티켓 끝의 "얹은 길" 표에 있다.

## 확인한 것과 정한 것

- **세 구현이 같은 기준을 낸다.** 기준 브랜치 규칙은 `tools/base_rule.py`, `tools/check_ticket.py`의 `base_ref`, `tools/hook_push_behind_main.py`의 `base_branch` 세 곳에 있다. 뒤의 둘은 CI(표준 라이브러리만 쓴다)와 단독 실행 훅이라 서로 import하지 않는다(`.claude/rules/tools.md`). 셋이 같은 입력에서 같은 기준을 내는지는 `test_base_rule.py`가 브랜치 이름 아홉과 `origin/dev` 유무 둘로 묶는다.
- **`origin/dev`가 없는 지금은 모든 도구가 이전과 같은 기준(main)을 낸다.** 이 클론에 `origin/dev`가 없는 것은 `git ls-remote origin refs/heads/dev`의 빈 출력으로 봤다. 도구별 전용 시험은 `check_ticket`, `hook_push_behind_main`, `sibling_overlap`에 있고 `tidy_checkouts`는 기존 시험이 `origin/dev` 없는 임시 저장소에서 돌아 간접으로만 덮는다.
- **이 저장소에서 새로 찾은 시험 공백이 하나 있었다.** 변이 표를 돌리자 `tidy_checkouts`의 `casefold`를 빼도 시험이 초록이었다. 윈도에서 `Dev`·`DEV` 이름으로 체크아웃한 워크트리를 지우지 않는다는 시험을 더해 닫았다(`test_반박_대소문자가_다른_보호_브랜치를_체크아웃한_워크트리도_지우지_않는다`). agent-os 쪽 시험에는 없는 시험이다.
- **독스트링의 출처 표기를 이 저장소 기준으로 고쳤다.** agent-os의 ADR 0043을 ADR 0016이 따른다는 구조로 맞췄고(`base_rule.py`, `test_base_rule.py`, 푸시·커밋 훅), `check_ticket`의 핫픽스 티켓 자리는 근거를 ADR 0016으로 옮기면서 `docs/agents/issue-tracker.md`의 "기능 밖에서 제품 코드를 고치는 일" 항목이 기능 디렉터리의 티켓을 말해 핫픽스와 다르다는 점을 적었다.
- 사용자에게 묻지 않고 정했다. 이 티켓이 얹기로 한 것이고 아키텍처 결정은 ADR 0016이 이미 정했다.

## PR 직전 리뷰

`coderabbit review --agent --include-untracked --base origin/main`(CLI 0.7.5, `Seat: not assigned`, `Plan: Free`)이 종료 코드 0, `review_completed`로 끝까지 돌았다. 파일 25개를 봤고 지적은 4건이다. CLI는 모두 major로 냈고 서브에이전트가 Minor로 트리아지했다. 이 판정은 내가 읽은 코드로 한 번 대 봤다.

- `tools/check_constitution_version.py:113`: `rev-parse origin/dev^{commit}`의 짧은 이름이라, 로컬 브랜치 `origin/dev`가 있으면 git이 `refs/heads`를 먼저 풀어 다른 커밋을 기준으로 삼는다. → 보류. `origin/main`의 같은 파일도 `MAIN = "origin/main"`을 `{MAIN}^{{commit}}`으로 풀었다(손으로 `git show origin/main:tools/check_constitution_version.py`를 읽었다). 이번 변경은 그 방식을 dev까지 넓혔을 뿐이고, 갈리려면 `origin/dev`라는 이름의 로컬 브랜치를 일부러 만들어야 한다. 서브에이전트는 `tools/sibling_overlap.py`의 세 자리도 같은 모양이라고 보고했다(내가 열어 보지 않았다). 고치려면 네 자리를 전체 ref(`refs/remotes/origin/<이름>`)로 바꾸고 시험을 더해야 해서 이 티켓의 범위(agent-os diff를 얹는다) 밖이다. 일지의 "다음"에 적었다.
- `tools/check_ticket.py:651`: 포크 PR의 머리 브랜치 이름이 `dev`이면 `judge_pr`가 티켓 검사를 건너뛴다. → 보류. `main`은 이전부터 같았다고 서브에이전트가 보고했고, 이번 변경은 같은 면제를 `dev`로 넓혔다. 포크 PR을 받는 저장소가 되면 머리 저장소 확인을 더한다.
- `tools/sibling_overlap.py:1321`(비조상 둘째 브랜치에 같은 번호가 남는 경우), `:1354`(상속한 판 줄을 이 브랜치가 올린 판으로 오인하는 경우): → 보류. 서브에이전트가 재현하지 못했고 재현하려면 squash로 복사된 ADR이나 hotfix 기준에서 상속한 판이 있어야 한다. 시험을 만들어 보지 않았다.

특히 봐 달라고 한 넷의 결과는 다음과 같다. (1) 일반 입력에서 세 구현이 같다. 서브에이전트가 짚은 Nit은 `hook_push_behind_main.py`의 `ref_state`가 `^{commit}`을 붙이지 않아 커밋이 아닌 객체를 가리키는 ref에서 갈린다는 것으로, 실제로 날 일이 거의 없다. (2) `origin/dev`가 없을 때 모든 도구가 main을 낸다는 것은 서브에이전트가 코드를 읽어 낸 판단이다. (3) `casefold`는 두 군데(`judge`의 체크아웃 가드, `_judge_branch_merged`)에 일관되게 들어 있다. (4) 훅의 git 호출은 시간 제한이 있고 출력을 버린다. 입력 반박 시험은 서브에이전트가 돌려 보지 않았다.

- 변이 표 `.scratch/harness/probes/dev_base_tools_mutations.toml`의 10개를 실행해 모두 기대한 표지로 빨갰다. `--check`도 통과했다.
- 이 세션의 마지막 전체 러너(`tools/run_checks.py`) 한 번이 `tests/adapters/test_parse_runner.py::test_메시지를_보내다_멈춘_자식이_있어도_수신이_영영_막히지_않는다` 하나로 빨갰다(3823 통과, 1 실패, 약 13분). 서브에이전트 둘이 같은 때 pytest를 돌리던 부하에서 났고, 윈도에서 `parse_failed`를 기대했으나 `parse_timeout`을 받았다. 그 시험을 따로 돌리면 3.06초에 통과했고 커밋의 pre-commit(`pytest` 통과)에서도 초록이었다. 이 코드를 이번 변경은 건드리지 않았다.
- `origin/main`이 02(PR #24)로 한 커밋 앞서 푸시 훅이 막았다. 겹치는 파일 없이 `git merge origin/main`으로 합쳤고 `sibling_overlap`은 종료 0이다.
- `uv run python tools/plan_table.py`는 이 기능에 `**슬라이스:**` 줄이 없어 출력도 변경도 없었다.
- 실제 `origin/dev`에서의 동작은 dev가 서야 본다. 이 티켓은 `origin/dev`가 없는 채로 병합한다.
