# 플러그인 인터페이스는 Protocol과 `interface_version`과 entry points로 열고, 커넥터는 열거와 받기로 동작한다

ADR 0003이 둔 플러그인 자리 셋(커넥터, 변환, 파서)의 모양이다. 자리마다 `typing.Protocol`이 인터페이스이고 구현은 `interface_version: str`(semver) 속성을 가진다. 설치는 entry point 그룹 `rag_engine.connectors`, `rag_engine.transforms`, `rag_engine.parsers`로 등록하고, 서버와 작업자는 로드할 때 major가 다르면 그 플러그인을 거부하고 기록한다. 내장 파서도 같은 그룹에 등록해 로드하는 길이 하나다. 설치처의 비공개 패키지(ADR 0003)가 우리 코드를 고치지 않고 끼워지는 길이 entry points이고, Protocol은 상속 없이 strict 타입 검사와 맞는다.

커넥터 인터페이스 1.0은 열거와 받기(pull)다. `interface_version`, `list()`가 원천 안의 (키, 변경 표지)를 전부 내고, `fetch(key)`가 바이트·MIME·갱신 시각·메타데이터를 내며, `check()`가 연결을 확인한다. 서버가 열거 결과를 데이터베이스와 대 봐 추가·변경·삭제를 판정하므로 삭제는 열거에 없는 키이고, 커넥터는 상태를 들지 않는다. 변경 표지(수정 시각과 크기, etag 같은 것)가 같으면 받기를 건너뛰고, 다르면 받아 내용 해시로 다시 확인한다(바뀜: 이력 2026-11-21 "모두 다시 읽기로 돌린 동기화는 변경 확인값이 같아도 받는다"). 원칙 VI(원천이 진실)을 구조로 지키는 모양이다. 변경 로그가 있는 시스템을 위한 선택 메서드 `changes_since(cursor)`는 나중에 칸 추가로 같은 판(minor)에서 더한다. 업로드와 수집 API는 커넥터가 아니라 밀어 넣는 원천 종류이고, 우리가 남의 시스템의 API를 불러 가져오는 일은 그 시스템의 커넥터가 `list()`와 `fetch()` 안에서 한다(바뀜: ADR 0021). 제품이 동봉하는 커넥터는 서버 경로(0.1)와 SQL 원천(1.0)이다.

## Considered Options

- ABC 상속: 플러그인이 우리 패키지의 기반 클래스에 의존해 판이 엇갈릴 때 import부터 깨진다.
- 설정 파일의 모듈 경로: 설치 검증이 없고 잘못된 경로가 기동 때야 드러난다.
- 변경 이벤트(push) 인터페이스: 증분이 빠르지만 커넥터가 커서 상태를 들어야 하고 이벤트를 놓치면 원천과 색인이 어긋나 전체 대조를 따로 만들어야 한다. 첫 판 커넥터인 서버 경로는 폴더 감시가 플랫폼마다 달라 구현이 무겁다.
- 열거와 이벤트 둘 다 필수: 플러그인 작성 부담이 두 배이고 이벤트가 없는 원천은 빈 구현을 강요받는다.

## Consequences

- 파일이 수십만인 원천은 동기화마다 전체 열거가 돌아 길어진다. 주기와 병렬은 source-sync가 정한다.
- 서버 경로 원천의 키는 상대 경로라 파일을 옮기면 삭제와 추가로 보인다.
- 범용 REST 커넥터를 제품에 미리 넣지 않는다. ADR 0003이 원천마다 커넥터를 미리 많이 만드는 안을 거부한 까닭과 같다.
- 변환과 파서의 메서드 모양은 명세가 정하되 같은 규약(Protocol, `interface_version`, entry point)을 따른다. 청킹 전략은 플러그인 자리가 아니다(ADR 0010).

## 이력

### 2026-11-18 용어집이 변경 표지의 이름을 변경 확인값으로 바꿨다

`GLOSSARY.md`가 "변경 표지"를 "변경 확인값"으로 바꿨다. 본문의 "(키, 변경 표지)"와 "변경 표지(수정 시각과 크기, etag 같은 것)"는 "변경 확인값"으로 읽는다. 이름만 바뀌었고 커넥터 인터페이스의 결정은 그대로다. 변경 확인값은 커넥터가 열거할 때 키와 함께 내는 값이고, 원본 바이트에서 계산하는 내용 해시와는 다른 것이다. 본문대로 변경 확인값이 다를 때 문서를 받아 내용 해시로 다시 확인한다. "표지"가 낯선 한자어여서 사용자가 2026-11-18에 골랐다(일지 `docs/journal/2026-11-18-1008-plain-words-in-written-artifacts.md`의 "보인 후보와 사용자의 답").

### 2026-11-19 용어집이 계약에 붙이는 번호의 이름을 판에서 버전으로 바꿨다

계약에 붙이는 번호를 가리키는 말이 "판"에서 "버전"으로 바뀌었다. 본문에서 플러그인 인터페이스에 붙이는 번호를 뜻하는 "판"은 "버전"으로 읽는다. 패키지가 서로 맞지 않는 상황을 가리키는 "판이 엇갈릴 때"와 처음 나온 모습을 가리키는 "첫 판 커넥터"는 계약 번호가 아니라서 이번에 건드리지 않았다. 이름만 바뀌었고 이 ADR의 결정은 그대로다. 같은 낱말을 바꾼 일의 까닭과 헌법 버전을 올린 까닭은 ADR 0016의 이력 2026-11-19 "계약에 붙이는 번호의 이름을 버전으로 바꿔 헌법 버전을 1.5.3으로 올렸다"에 있다(티켓 `.scratch/harness/issues/glossary-contract-version-names.md`).

### 2026-11-21 모두 다시 읽기로 돌린 동기화는 변경 확인값이 같아도 받는다

명세(`.scratch/source-sync/spec.md`)가 정했다. 본문은 변경 확인값이 같으면 받기를 건너뛴다고 적는다. ADR 0022가 변경 확인값이 같아도 원천의 파일을 모두 다시 읽게 하는 길을 둘지를 명세에 넘겼고, 사용자가 2026-11-21 명세 세션에서 관리 API의 "지금 동기화"에 "모두 다시 읽기" 옵션을 두는 쪽을 골랐다. 그 옵션을 켜고 돌린 동기화는 변경 확인값이 같아도 후보의 파일을 모두 받아 내용 해시를 비교한다. 수정 시각과 크기가 그대로인 채 내용만 바뀐 파일과, 실패했거나 건너뛴 문서를 다시 처리하는 길이다. 일정이 시작한 동기화와 옵션을 켜지 않은 동기화는 본문 그대로다(명세의 "동기화의 차례").

본문을 거짓으로 만들지 않고 더한 것도 여기에 적어 둔다. `list()`가 내는 항목에 크기(바이트. 모르면 비운다) 칸을 더했고, 서버가 파일을 받지 않고 크기 상한을 적용하는 데 쓴다. 커넥터는 원천의 설정(JSON 객체) 하나를 받아 만들어진다. 인터페이스가 정하는 예외는 하나이고 닫힌 사유 값 넷을 든다. 서버 경로 커넥터가 적는 `interface_version`의 값은 `1.0.0`이다(명세의 "커넥터 인터페이스 1.0"). 열거와 받기라는 결정은 바뀌지 않는다.
