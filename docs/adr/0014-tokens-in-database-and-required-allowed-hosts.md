# 인증 토큰은 데이터베이스에 두고 관리 API로 발급·회수하며, MCP 허용 호스트 설정은 필수다

원칙 V(기본 닫힘)를 서버가 어떻게 지키는지 정한다. 처음 추천은 설정 파일의 고정 토큰이었으나 회수, 만료, 범위가 없어 사용자가 데이터베이스 토큰을 골랐다. 토큰 표에 해시, 이름, 역할, 만료, 선택적 지식베이스 범위를 두고, 발급과 회수는 관리 API가 한다. 원문은 발급 응답에 한 번만 나오고 저장은 해시다. 첫 관리 토큰은 관리 명령 `bootstrap-token`이 낸다. 판정은 FastAPI 앱 바깥의 ASGI 미들웨어가 REST와 `/mcp` 둘 다에서 베어러 토큰을 보고 401(없음·틀림)과 403(범위 밖)을 낸다. MCP SDK 2.3.0 프로브(`.scratch/core/probes/mcp-sdk/probe_sdk.py` 2절)에서 순수 ASGI 미들웨어가 `/mcp` 앞에서 401을 내는 것을 확인했다. SDK의 `AuthSettings`는 OAuth 발급자 주소(`issuer_url`)와 리소스 서버 주소(`resource_server_url`)가 필수 칸이라(SDK 2.3.0 `auth/settings.py` 읽음. 발급자 주소만 주면 ValidationError인 것은 같은 프로브 2절) 폐쇄망의 내부 토큰에 맞지 않는다.

MCP 전송의 DNS 리바인딩 보호는 켠 채로 두고 설정 `RAG_ALLOWED_HOSTS`를 필수로 한다. 비어 있으면 기동을 거부하고, 적힌 값마다 그대로와 `값:*`의 두 꼴로 등록하며(`localhost`와 `127.0.0.1`도 같은 두 꼴로 자동으로 더한다), 불일치는 421이다. 두 꼴인 까닭은 SDK의 `host:*`가 포트가 붙은 Host만 받아 기본 포트로 오는 프록시·클라이언트의 포트 없는 `Host: host`가 421이 되기 때문이고, 비교가 대소문자를 가리므로 설정 값은 소문자로 적는다(SDK 2.3.0 `transport_security.py`의 정확 일치 뒤 `host:` 접두 비교를 읽음, 프로브 `.scratch/core/probes/mcp-sdk/probe_sessions.py` 1절). SDK는 `0.0.0.0`에 바인딩하고 보호 설정이 없으면 보호를 끄므로(SDK 2.3.0 `transport_security` 읽음, 프로브 1절), 비워 두면 조용히 열리는 자리를 설정 필수로 막는다.

## Considered Options

- 설정 파일의 고정 토큰(처음 추천): 설치가 단순하지만 회수와 만료가 없고 여러 클라이언트를 가르지 못한다.
- SDK `AuthSettings`와 OAuth: 표준이지만 공개 발급자가 필요해 폐쇄망 단독 compose(PRD 0.1)와 맞지 않는다.
- 허용 호스트를 자동으로만: `0.0.0.0`에 설정이 없으면 보호가 꺼진 채 뜬다.

## Consequences

- 토큰 표는 alembic 마이그레이션에 들고 로그에 토큰을 남기지 않는다(원칙 V).
- 1.0의 관리 변경 기록이 발급과 회수를 적는다.
- 주체(접근 그룹을 쓰는 설치에서 요청한 쪽의 신원)는 토큰과 별개로 MCP `_meta`의 범용 형식으로 받으며 그 모양은 1.0 기능의 설계가 정한다. 1.0 전에는 조각 표의 그룹 칸만 둔다.
