# 수집 파이프라인에 플러그인 자리 셋을 두고, 설치처별 변환 플러그인은 설치처의 비공개 저장소에 둔다

수집은 원천마다 같은 순서(원천의 커넥터 → 변환(선택) → 파싱 → 청킹 → 색인)를 따르고, 플러그인을 끼우는 자리는 커넥터, 변환, 파서 셋이다. 세 자리의 인터페이스에는 판을 붙인다(원칙 VII). 원천은 설치 환경마다 다르고 계속 늘어나므로, 제품은 범용 단계와 인터페이스를 내고 설치 환경마다 다른 규칙은 플러그인이 맡는다. 설치처별 변환 플러그인(본문 HTML 정리, 문서관리시스템 API로만 내려받는 첨부, 암호화된 첨부의 복호화 등)은 이 공개 저장소가 아니라 설치처의 비공개 저장소에 두고, 제품은 인터페이스와 예시 하나만 낸다. 그래야 설치처의 정보가 공개 저장소에 들어가지 않고 제품이 범용으로 남는다. 커넥터가 없는 원천은 설치 환경이 수집 API로 문서를 보내는 작은 스크립트로 붙인다.

## Considered Options

- 원천마다 커넥터를 제품에 미리 많이 만든다: 설치처마다 다른 규칙이 제품 코드로 들어오고, 수집 API가 마지막 통로가 되어 주므로 필요가 적다.
- 조각 단계(청킹 뒤)의 보강 자리도 처음부터 둔다: 지금은 쓸 곳이 없다. 필요해질 때 더하고 인터페이스의 판을 올린다.
