# MCP로는 읽기 도구만 열고, 쓰기는 관리 API와 수집 API로 나눈다

MCP 클라이언트는 대개 LLM 에이전트이고, 에이전트는 자기가 읽은 문서 속 지시에 속을 수 있다. 그래서 MCP에는 검색과 문서 정보 조회 같은 읽기 도구만 등록하고, 수집, 삭제, 재색인 같은 쓰기는 관리 API(REST)와 관리 명령, 다른 시스템을 위한 수집 API로만 연다. 도구의 `read_only_hint`는 클라이언트용 힌트라 보안 장치가 아니고(SDK v2.3.0 `docs/servers/tools.md`를 읽었다), 쓰기 도구를 등록하지 않는 것만이 구조로 막는 길이다. 계약 시험이 MCP 도구 목록에 쓰기 도구가 없음을 본다.

## Considered Options

- MCP에 쓰기 도구도 열고 토큰의 범위나 확인 단계로 막는다: 토큰을 가진 에이전트가 속으면 그대로 뚫리고, 확인 단계는 클라이언트마다 다르다(원칙 III).
- 쓰기는 MCP의 별도 서버로 연다: 통로가 하나 더 늘 뿐 같은 문제가 남는다.
