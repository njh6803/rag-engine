# 도메인 문서

엔지니어링 스킬이 코드베이스를 탐색하기 전에 이 저장소의 도메인 문서를 어떻게 읽어야 하는지 정한다.

## 탐색 전에 읽을 것

- 루트 `GLOSSARY.md`: 용어집
- `docs/adr/`: 지금 다룰 영역에 걸리는 ADR

이 파일들이 없으면 조용히 진행한다. 없다고 지적하거나 미리 만들자고 제안하지 않는다. `/domain-modeling`(`/grill-with-docs`가 호출)이 용어나 결정이 실제로 확정될 때 그때 만든다.

## 배치 (단일 컨텍스트)

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-….md
│   └── 0002-….md
└── src/
```

멀티 컨텍스트(루트 `GLOSSARY-MAP.md`가 컨텍스트마다의 `GLOSSARY.md`를 가리키는 배치)는 쓰지 않는다. 바꾸려면 ADR을 남긴다.

## 용어집의 말을 쓴다

출력이 도메인 개념(원천, 문서 묶음, 조각, 색인 등)을 부를 때(이슈 제목, 리팩터링 제안, 가설, 테스트 이름) `GLOSSARY.md`에 정의된 말을 쓴다. 용어집이 피하라고 적은 동의어로 흐르지 않는다.

필요한 개념이 용어집에 아직 없으면 신호다. 프로젝트가 쓰지 않는 말을 지어내는 중이거나(다시 생각한다), 진짜 빈 곳이다(`/domain-modeling`에 넘길 거리로 적는다).

## ADR과 부딪치면 드러낸다

출력이 기존 ADR과 어긋나면 조용히 덮어쓰지 않고 드러낸다.
