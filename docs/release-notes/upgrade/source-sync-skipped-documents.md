업그레이드 전에 PostgreSQL 볼륨을 백업한다. 이 판을 올리면 `rag-engine migrate`가 데이터베이스 판을 0005로 올리고, 이미 들어 있는 문서 가운데 암호가 걸렸거나 글이 없는 것을 실패가 아니라 건너뜀(`skipped`)으로 옮긴다. 암호가 걸려 `failed`와 `encrypted_document`로 남아 있던 문서는 `skipped`와 사유 `encrypted`가 되고 오류 코드가 비워진다. 파싱은 됐지만 글자가 하나도 없는 문서(스캔본 PDF 등)는 `parsed`에서 `skipped`와 사유 `no_text`가 된다. 옮긴 문서의 색인 상태는 조각 0개인 `indexed`로 맞춘다. 표의 모양은 바뀌지 않고 문서는 지워지지 않으며 색인은 다시 만들지 않는다. 옛 작업 기록은 그대로 남아서 이전에 실패한 작업 행에는 `encrypted_document`가 계속 보인다. 올린 뒤에는 관리 API의 문서 목록에서 `status=failed`로 세던 암호 문서가 `status=skipped`로 옮겨 가므로, 실패 수를 보던 점검이나 알림이 있으면 그 기준을 확인한다. 문서 응답에는 `skip_reason` 칸이 더해진다. 이 판의 0005만 내리면(`0004`로) 건너뜀 문서는 옛 모양(`encrypted`는 `failed`와 `encrypted_document`, `no_text`는 `parsed`)으로 돌아가고 건너뜀 사유가 비워진다. 다만 올릴 때 바뀐 색인 상태(`pending`이나 `failed`였던 것)는 되돌리지 않는다. 이 판 이전으로 완전히 돌아가야 하면 `source-sync-schema` 원고의 설명대로 백업에서 복원한다.
