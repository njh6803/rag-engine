# 09: 검색의 완성: 리랭크, 필터, 시간 제한, `get_document`, `list_knowledge_bases`

**What to build:** MCP 클라이언트가 그룹과 갱신일 기간으로 결과를 거르고, 리랭커가 순서를 고친 결과를 받는다. 조각만으로 모자라면 `get_document`로 문서 정보와 전문을 읽고, `list_knowledge_bases`로 어디에서 찾을지 고른다. 도구 셋의 출력과 오류가 계약 시험으로 고정되고, 검색은 지연만 로그에 남긴다.

**Blocked by:** 07 (첫 왕복)

**Status:** done

**06이 넘긴 것:** 리랭크의 `texts`는 후보 조각의 `compose_index_text(location.section, text)`다(`rag_engine.domain.index_text`). 검색 결과에는 조각 글과 `location.section`이 따로 있어 두 값에서 그대로 지을 수 있다. 다만 06의 청킹은 절 경로가 상한의 4분의 1을 넘으면 바깥 제목부터 뺀 경로로 `index_text`를 짓는데 `location.section`에는 전체 경로를 싣는다. 그래서 리랭크 글은 색인 때의 글과 제목 몇 개가 다를 수 있고, 같아야 하면 이 티켓이 그 어긋남을 닫는다. **닫지 않았다.** 리랭크 요청이 `truncate: true`로 보내 입력 상한을 넘는 글은 서버가 오른쪽을 자르므로, 어긋난 제목 몇 개가 순위를 해치는지는 재지 않았고 색인 때의 글을 저장하는 일(칼럼 추가)도 하지 않았다. 리랭크 글은 `compose_index_text(location.section, text)`이고, 순위 품질에서 어긋남이 문제로 보이면 14의 키워드 재생성과 함께 `index_text` 저장을 다시 판단한다. TEI 스텁(`tests/support/tei_stub.py`)에는 `/rerank`가 이미 있다.

**07이 넘긴 것:** `search` 도구와 유스케이스의 뼈대는 07이 세웠다(`server/search_tool.py`의 `register_search_tool`, `app/search.py`의 `search_documents`). 07의 `search`는 `query`·`top_k`·`knowledge_base`만 받고 빈 `query`와 범위 밖 `top_k`를 검증하지 않으며(이 티켓의 `invalid_argument`), 전체 시간 제한과 리랭크 단계가 없다. 점수는 RRF 점수다. 도구 오류는 예외가 아니라 `CallToolResult(is_error=True, content=[TextContent(Problem Details JSON)])`를 직접 돌려 낸다. SDK가 도구 예외의 메시지에 `Error executing tool …` 접두를 붙여 JSON이 깨지기 때문이다(`tool_error(code, scope)`, `detail` 없음). 새 도구(`get_document`, `list_knowledge_bases`)도 같은 함수를 쓴다. 판이 전환되는 사이의 재시도와 임베딩 실패의 `search_unavailable`은 07이 `tests/app/test_search_documents.py`에서 실제 PostgreSQL 위에 이미 시험했다(아래 시험 항목의 가짜 포트 시험 가운데 판 전환 갈래는 거기 있다). 후보 `SearchHit`에는 `text`와 `location.section`이 들어 있어 리랭크 글은 `compose_index_text(location.section, text)`로 지을 수 있고, 07의 청킹이 낸 `index_text`는 `chunks`에 저장되지 않는다(칼럼이 없다). 위 06이 넘긴 어긋남(절 경로가 상한의 4분의 1을 넘어 줄어든 조각)이 그대로 남는다. `search` 로그 이벤트는 07이 `embedding_ms`·`sql_ms`·`duration_ms`로 이미 남긴다.

- [x] TEI 리랭커 어댑터(`Reranker`): 끝점마다 `/info` 확인(지식베이스 설정의 리랭커 모델, `max_input_length`가 조각 상한 이상인지, `auto_truncate`는 로그), 요청 칸(`query`, `texts`, `truncate: true`, `truncation_direction: "Right"`, `raw_scores: false`, `return_text: false`), `RAG_TEI_BATCH_SIZE`개씩 나눈 묶음(`max_client_batch_size`가 더 작으면 그 값)과 점수 합치기(명세 "임베딩 서버와 리랭커 어댑터" 절). `texts`는 06의 글 짓기 함수가 지은 글이다.
- [x] `search`의 다섯째 단계: 지식베이스에 리랭커가 있으면 후보 전부를 리랭크해 점수 순으로 바꾸고, 없으면 RRF 점수를 쓴다. 리랭커가 실패하거나 설정 불일치면 RRF로 대체하지 않고 `search_unavailable`이다.
- [x] 필터: `groups`(없는 그룹 이름은 오류가 아니고 아무 문서에도 맞지 않는다), `updated_after`(포함)·`updated_before`(제외), 오프셋이 없거나 읽을 수 없는 시각과 빈 `query`·범위 밖 `top_k`는 `invalid_argument`. 필터는 벡터·키워드 두 쪽의 `WHERE`에 같이 들고, 필터가 있으면 `SET LOCAL hnsw.iterative_scan = relaxed_order`를 더한다. 지식베이스 그룹 집합의 방어 조건은 필터로 세지 않는다(명세 "검색 흐름" 절).
- [x] 전체 시간 제한 `RAG_SEARCH_TIMEOUT_SECONDS`를 넘으면 `search_unavailable`. 로그 이벤트 `search`는 임베딩·SQL·리랭크 지연과 전체 지연만 싣는다(질의 글, 지식베이스 이름, `top_k`, 후보 수, 결과 수를 싣지 않는다. ADR 0004).
- [x] `get_document`(명세 "MCP 도구" 절, 전문 창 모양): 입력 `document_id`, `include_text`(기본 false), `offset`(0 이상, 기본 0), `max_chars`(1 이상 `RAG_DOCUMENT_TEXT_MAX_CHARS` 이하, 기본 그 설정값. 설정 기본 20000). 출력 칸 전부와 토큰 범위 안 지식베이스만의 `chunk_counts`, 전문의 길이 `text_length`(코드 포인트 수, `include_text`와 상관없이), `include_text`면 전문의 `offset`부터 시작하는 창 `text`와 다음 창의 `next_offset`(전문이 여기서 끝나면 null). 전문은 블록 글을 빈 줄로 이은 글이고 제목 블록은 수준만큼 `#`을 앞에 붙인 한 줄이다. 창은 `offset`보다 크고 `offset + max_chars` 이하인 마지막 블록 경계에서 자르고, 경계가 없으면 `offset + max_chars`에서 자른다. 파싱 결과가 없거나 그 내용 해시가 문서의 것과 다르면 `text_length`, `text`, `next_offset`이 모두 null이다. `max_chars`와 음수 `offset`은 문서와 상관없이 `invalid_argument`이고, 길이를 넘는 `offset`은 문서를 찾고 범위를 확인한 뒤에만 `invalid_argument`다(같으면 빈 글과 null). 지워진 문서와 범위 밖 지식베이스에만 든 문서는 `offset`이 어떻든 `document_not_found`다. 판은 1.0.0 그대로다. 내용 해시 칸은 두지 않았다(미정, 사용자 판단).
- [x] `list_knowledge_bases`: `name`, `description`, `document_count`(그 지식베이스 그룹 집합의 지워지지 않은 문서 수. 색인 상태와 상관없다), `is_default`, 토큰 범위 밖은 목록에서 뺀다.
- [x] 도구 오류는 `isError` 결과의 JSON 글 하나(`type`, `title`, `status`, `code`, `request_id`)이고 코드는 `knowledge_base_not_found`, `document_not_found`, `invalid_argument`, `search_unavailable`, `internal_error` 다섯이다. `detail`에 질의나 문서 내용을 넣지 않는다.
- [x] 계약 시험(`tests/contract/`): 도구 목록이 셋이고 모두 읽기 전용 표지(읽기 전용, 파괴적이지 않음, 멱등, 열린 세계 아님)가 있으며 outputSchema에 `format_version`이 있다(스토리 23, 42). 세 도구의 결과가 스키마와 `"1.0.0"`에 맞는다.

HWPX 제목 `## `와 PDF 전문에 `#` 줄이 없음은 그 파서를 만드는 08의 시험이다(이 티켓에는 DOCX 파서뿐이다). 임베딩 끝점 `/info`의 모델 불일치가 검색의 `search_unavailable`을 낸다. 판이 전환되는 사이의 검색이 둘째 단계부터 한 번 다시 하고, 다시 해도 아니면 `search_unavailable`이다(가짜 포트). 지운 문서의 갈래(`get_document`의 `document_not_found`, `document_count`에서 빠짐)는 삭제가 생기는 11이 시험한다.
