# core 설계 인터뷰 프로브

core 설계 인터뷰(2026-11-09)에서 라이브러리·이미지·API 의 사정을 재거나 받아 온 스크립트와 그 출력이다. ADR·명세·`design/vector-store-comparison.md` 가 "스크립트"·"쟀다"로 드는 근거는 이 폴더의 파일을 가리키고, 실행 명령과 결과 요약은 각 스크립트의 독스트링에 있다. 내려받은 원문(`dl/`, `dl2/`, 휠, sdist)은 저장소 밖 세션 스크래치패드에 있어 세션이 끝나면 사라지며, 각 스크립트가 다시 받는다(비교 문서의 원문은 `vector-store/fetch_raw*.py`·`fetch_list.py`).

저장소로 옮기며(2026-11-09) ruff 와 원칙 II(`Any`, `cast`, `type: ignore`, `pyright: ignore` 금지)에 맞춰 서식과 타입만 고쳤다. 어느 파일을 어떻게 고쳤는지는 그 독스트링에 있다. 타입을 고친 프로브는 옮긴 뒤 다시 돌렸다. `mcp-sdk/` 셋은 저장된 `*_out.txt` 와 무작위 세션 ID 만 다르고, `embedding/http_overhead.py` 와 `facts/` 셋은 재실행 출력을 `*_out.txt` 로 남겼다(http_overhead 는 첫 실행 p50 2.69ms, 재실행 2.96ms). 셀프 리뷰가 근거 파일이 없다고 짚은 수(ADR 0009 의 마이그레이션 수, ADR 0010 의 이미지 크기·Qwen3·auto_truncate)는 `facts/` 둘을 새로 써 출력과 함께 더했고, `sqlalchemy-async/` 는 greenlet 줄을 더해 다시 돌리고 pyright 의 JSON 출력을 `pyright_out.json` 으로 남겼다. 라이브러리 조합을 재는 `mcp-sdk/`, `embedding/`, `facts/`, `sqlalchemy-async/` 는 pyright strict 를 0 오류로 지난다(`sqlalchemy-async/` 는 네 패키지를 설치한 가상환경의 python 을 `--pythonpath` 로 줘야 하며, 저장소 `.venv` 로 보면 import 를 못 찾는 오류가 난다). 단 `uv run pyright <이 폴더>` 는 저장소 설정의 기본 exclude(`**/.*`) 때문에 `.scratch` 아래를 0개 파일로 지나가므로, exclude 를 비운 임시 pyrightconfig 로 `uv run pyright -p <그 설정> <폴더>` 를 돌려야 실제로 검사한다. `parsers/`, `db-queue/`, `vector-store/` 는 그 방식의 strict 검사에서 오류가 남아 있다(수집 스크립트라 그대로 두었다).

티켓 core 16 세션(2026-11-13)이 더한 `search-latency/` 셋은 `-X utf8` 로 돌려 출력 `probe_out.txt` 를 남겼다. 이 프로브가 재지 않아 어림으로 남는 것: 재시도 백오프 밑수 30초(`RAG_JOB_BACKOFF_BASE_SECONDS`)는 재지 않았다. 파싱 한도 중 메모리 2GiB 는 리눅스 `RLIMIT_AS`(가상 메모리)와 같은 값이 아닌 Windows 작업 집합만 재어 한도 안인지 확인하지 못했고, 시간 300초·글 64MiB·쪽 1000 은 표본과 1000쪽 PDF 한 개로만 비교했다. 후보 수와 TEI 배치의 기본값은 바꾸지 않았다(까닭은 일지 `docs/journal/2026-11-13-0615-search-latency-probe.md` 와 `search-latency/probe.py` 독스트링). 이 프로브는 pyright 검사 대상이 아니다(저장소 설정이 `.scratch` 를 뺀다).
