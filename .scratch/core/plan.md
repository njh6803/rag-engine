# core: 수집, 색인, 검색의 본체 v0. 관리 API로 넣은 문서를 MCP 읽기 도구로 근거 위치와 갱신일이 붙은 조각으로 찾는다
**슬라이스:** 1
**Blocked by:** 없음

문서를 수집하고 색인을 관리하고 검색하는 HTTP 서버이고, 같은 서버의 `/mcp` 경로(Streamable HTTP)로 MCP를 연다. 임베딩 모델과 색인을 한 번 올려 여러 요청을 받는다. 문서를 파싱, 청킹, 임베딩해 색인을 만들고, 검색 도구가 질의에 맞는 조각을 킥오프 입력 2절의 형식으로 돌려준다. MCP로는 읽기 도구(검색, 필요하면 문서 정보 조회)만 열고, 수집, 삭제, 재색인 같은 쓰기는 관리 API(REST)와 관리 명령으로만 연다. 문서 속 지시에 속은 에이전트가 문서를 지우는 일을 구조로 막기 위해서다. 문서 형식은 텍스트가 든 PDF, DOCX, HWPX 셋으로 시작하고, 스캔본 OCR과 HWP 5.0 바이너리는 다음 판이다(HWP 바이너리는 hwp-binary).

설계 인터뷰가 가장 먼저 정할 것은 셋이다. 동시 검색과 수집 도중에 들어오는 검색(색인을 바꾸는 시점), 수집 작업자를 검색 서버와 다른 프로세스로 나누는 방식(작업 대기열), 수집 파이프라인의 세 플러그인 자리(커넥터, 변환, 파서)의 인터페이스와 문서 식별(킥오프 입력 4절)이다. 벡터 저장소는 pgvector(자기 PostgreSQL)와 별도 벡터 DB를 함께 후보로 놓고, 접근 그룹과 날짜로 거르는 필터, 한국어 키워드 검색과의 결합을 기준으로 고른다. 그 밖에 정할 것은 로컬 임베딩 모델, 파서 라이브러리의 재배포 라이선스, 새 용어(원천, 문서 묶음, 조각, 색인)의 용어집 항목이다. 용어집에서는 업계 용어(지식베이스, 데이터 소스, chunk, index, retrieval)와의 대응과, 서버 전체를 지식베이스 하나로 볼지 문서 묶음마다 하나로 볼지도 정한다. 서버는 내부 네트워크에만 열고 토큰으로 인증한다. 설계 인터뷰의 입력은 킥오프 입력 2·3·4·7·8절이다.

수락: 표본 문서 폴더를 관리 API로 수집한 뒤 MCP 클라이언트로 HTTP 접속하면 검색 결과에 근거 위치와 갱신일이 실리고, MCP 도구 목록에 쓰기 도구가 없으며, 수집 중에도 검색이 응답하고, 동시 요청 여러 개의 검색 지연을 대상 사양에서 재서 프로브로 남긴다.
