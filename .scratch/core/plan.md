# core: 수집, 색인, 검색의 본체 v0. 관리 API로 넣은 문서를 MCP 읽기 도구로 근거 위치와 갱신일이 붙은 조각으로 찾는다
**슬라이스:** 1
**Blocked by:** 없음
**설계:** ADR 0006, 0007, 0008, 0009, 0010, 0011, 0012, 0013, 0014, 0015와 ADR 0002 이력 2026-11-09. 일지 `docs/journal/2026-11-09-2125-core-design.md`

문서를 수집하고 색인을 관리하고 검색하는 HTTP 서버이고, 같은 서버의 `/mcp` 경로(Streamable HTTP)로 MCP를 연다. 색인은 자기 PostgreSQL(pgvector)에, 임베딩과 리랭커는 별도 TEI 컨테이너에 두고 여러 요청을 받는다(ADR 0006, 0010). 문서를 파싱, 청킹, 임베딩해 색인을 만들고, 검색 도구가 질의에 맞는 조각을 킥오프 입력 2절의 형식으로 돌려준다. MCP로는 읽기 도구(검색, 필요하면 문서 정보 조회)만 열고, 수집, 삭제, 재색인 같은 쓰기는 관리 API(REST)와 관리 명령으로만 연다. 문서 속 지시에 속은 에이전트가 문서를 지우는 일을 구조로 막기 위해서다. 문서 형식은 텍스트가 든 PDF, DOCX, HWPX 셋으로 시작하고, 스캔본 OCR과 HWP 5.0 바이너리는 다음 판이다(HWP 바이너리는 hwp-binary).

설계 인터뷰(2026-11-09, 설계 줄의 ADR과 일지)가 정했다. 수집 도중의 검색은 문서 단위 원자 교체와 지식베이스 색인 판 전환으로(ADR 0008), 작업자는 PostgreSQL 작업 대기열 위의 별도 프로세스로(ADR 0009), 플러그인 자리 셋의 인터페이스는 ADR 0012로, 문서 식별은 (원천, 키)로(ADR 0008), 벡터 저장소는 pgvector와 PostgreSQL 전문 검색(ADR 0006), 임베딩·리랭커는 TEI 컨테이너(ADR 0010), 용어는 `GLOSSARY.md`(지식베이스는 그룹 집합 위의 색인 하나)로 정해졌다. 서버는 내부 네트워크에만 열고 토큰으로 인증한다(ADR 0014). 명세 `.scratch/core/spec.md`(2026-11-10)가 일지의 '다음' 절이 명세에 맡긴 넷(MCP 전송 설정 둘의 조립 자리, 세 포트가 한 트랜잭션을 공유하게 유스케이스가 여는 작업 단위 포트 `UnitOfWork`, 테스트 이미지 판 고정, 파서의 자원 한도와 영구 실패의 종결)을 정했고, ADR 0006·0007에 이력을 더했다. 티켓 세션(2026-11-10)이 spec-reviewer의 검토를 명세에 반영하고 ADR 0008에 이력을 더한 뒤 티켓을 쪼갰다(`.scratch/core/issues/`). 사용자는 명세 세션에서 이음매(HTTP 표면에 실제 테스트 PostgreSQL과 TEI 스텁을 붙인다)와 범위(토큰 발급·회수, 지식베이스 조회와 재색인 시작, 작업·문서 조회의 최소 관리 API를 core에 둔다)를 골랐다. 다른 기능에 넘긴 것은 명세의 Out of Scope와 받는 기능(source-sync, admin, release-image, search-eval)의 계획 본문에 있다. 첫 티켓(core 01)은 검사 러너가 테스트 DB를 띄우는 변경이고, 그다음 계약 티켓이 import-linter 계약과 `CLAUDE.md` 레이어 절을 다섯 층으로 고친다(ADR 0007).

수락: 표본 문서 폴더를 관리 API로 수집한 뒤 MCP 클라이언트로 HTTP 접속하면 검색 결과에 근거 위치와 갱신일이 실리고, MCP 도구 목록에 쓰기 도구가 없으며, 수집 중에도 검색이 응답하고, 동시 요청 여러 개의 검색 지연을 대상 사양에서 재서 프로브로 남긴다.
