# check-quotes-verbatim-paste: 그대로 옮기라고 한 사용자 글의 인용을 check_quotes 경고를 피하려 고쳐 적었다

**상태:** 열림
**어디로:** `tools/check_quotes.py`의 경고 문구에 한 갈래(사용자나 다른 문서의 글을 그대로 옮기는 자리면 `>` 인용 줄로 둔다. 그 줄은 이 검사가 보지 않는다)
**승인:** 자체 승인 2026-11-10, 3회차(경고 문구에 갈래를 더하는 것이라 다섯 번째에 반영한다), 일지 2026-11-10-1828-core-tickets.md, 2026-11-11-0929-core-get-document-text-window.md(2회차: 내려받은 문서의 두 문장이 산문 줄의 따옴표에 있어 경고 둘을 둔 채 지나갔다가 회고에서 `>` 줄로 옮겼다), 2026-11-13-0453-search-eval-spec.md(3회차), ADR 불필요

경고는 원문을 다시 열어 그대로 옮기거나 따옴표를 떼라고만 알린다. 사용자 글 안의 인용이 저장소의 원문을 줄인 것이면 두 길 모두 사용자 글을 바꾼다. search-eval 계획의 평가 항목 1·2·4가 그렇게 바뀌어 명세 축 Minor 9가 잡았고, 반영에서 `>` 인용으로 다시 옮겼다.

3회차는 search-eval 명세 세션이다. 내려받은 GitHub 문서의 두 문장을 일지의 산문 줄 따옴표에 두어 경고 둘이 났고, 커밋은 그대로 지나갔으며 회고에서 `>` 줄로 옮겼다. 같은 커밋의 경고는 48건이었고 모두 저장소 밖의 글을 옮긴 줄이라 하나씩 보아야 했다. 대부분은 `AskUserQuestion`의 질문과 선택지를 글자 그대로 옮긴 목록 줄이다. 처방의 갈래가 목록 항목 안의 인용에도 닿게 할지는 이 항목을 반영하는 chore가 정한다.
