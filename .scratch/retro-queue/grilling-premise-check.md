# grilling-premise-check: 선택지 설명의 전제를 제품 그림(ADR·PRD)에 대 보지 않아 사용자가 바로잡았다

**상태:** 열림
**어디로:** `.claude/skills/grilling/SKILL.md`의 "올리기 전" 문단에 한 줄(설명에 넣는 사실을 코드·판정자뿐 아니라 ADR과 `docs/PRD.md`가 그린 제품의 자리에도 대 본다. 내부 부품을 설치처의 기존 것에 붙이는 장면을 전제로 두지 않는다)
**승인:** 자체 승인 2026-11-09, 10회차(더하는 것이라 다섯 번째에 반영한다), 일지 2026-11-10-1828-core-tickets.md, 2026-11-12-1419-dev-branch-model.md(3회차), 2026-11-12-2108-search-eval-design.md(4회차), 2026-11-17-1716-release-image-design.md(5회차), 2026-11-18-1008-plain-words-in-written-artifacts.md(6회차), 2026-11-23-1422-ci-pytest-parallel.md(7회차), 2026-11-23-2323-docs-only-commit-narrow-pytest.md(8회차), 2026-11-26-1534-admin-design.md(9회차), 2026-11-26-1938-admin-screens.md(10회차), ADR 불필요

core 설계 인터뷰 라운드 16의 최소 PostgreSQL 판 질문에서 선택지 설명에 "2026년 설치처의 PostgreSQL이 18일 가능성은 낮음"이라고 적었다. PostgreSQL은 이 제품이 동봉하는 데이터베이스(ADR 0002)라 그 장면이 없었고, 사용자가 라운드 17에서 바로잡았다. 일지의 "에이전트가 번복하거나 고친 것" 절.

2회차는 core 티켓 세션의 선택 화면이다(grilling 밖이라 반영할 때 자리를 넓힐지 본다). 최소 점수 질문의 설명이 ADR 0015의 칸 추가 minor 규칙을 입력 인자에도 맞는다고 적었는데, 그 규칙은 결과 객체의 칸이다. 명세 축 Minor 9와 표준 축 Nit 13이 잡았다.

3회차는 dev-branch 설계 세션의 합의 요약이다. 갈래 13이 CodeRabbit 자동 리뷰가 기본 브랜치 PR만 본다는 어림을 전제로 티켓을 실었는데, 저장소의 운영 문서 "리뷰 파이프라인"에 자동 리뷰가 아예 돌지 않는다는 실측이 있었다. 갈래 12는 일지가 재지 않은 추론이라고 적은 것을 사실의 꼴로 적었다. 셀프 리뷰 두 축(표준 축 Minor 4, 명세 축 Minor 11·12)이 잡았다. 대 볼 자리가 ADR·PRD만이 아니라 헌법 운영 문서까지라, 반영할 때 "올리기 전" 문단의 대 볼 자리를 저장소의 규약 문서로 넓힐지 본다.

4회차는 search-eval 설계 세션의 합의 요약과 ADR 초안이다. 셋이 났다. 최소 점수를 측정, 승인, 구현의 순서로 둔 결정을 계약을 바꾸는 티켓이 기능의 첫 티켓이라는 트래커 규약에 대 보지 않았다(표준 축 Major 1). ADR 0015 이력이 계약 시험이 inputSchema를 본다고 적었는데 `tests/`에는 그런 시험이 없었다(명세 축 Minor). 샘플링 인자의 거부를 스킬 문서가 적은 것보다 넓게, 고친 뒤에는 좁게 적었다(표준 축 Minor, 명세 축 Nit). 대 볼 자리가 규약 문서에 더해 지금 시험 코드와 근거로 든 바깥 문서의 그 줄까지다.

5회차는 release-image 설계 세션의 선택 화면이다. 느린 시험을 어느 PR에서 돌릴지 묻는 질문에서 추천 선택지의 설명이 그 조건을 agent-os와 같다고 적었는데, 그 호출 앞에 읽은 agent-os의 `ci.yml`은 main 푸시에서도 시험하고 수동 실행의 계기가 없었다. 대 본 사실을 설명에 되돌려 맞추지 않은 것이다. 셀프 리뷰의 명세 축이 잡았고, 승인 화면에서 그 질문을 다시 물어 사용자가 다른 선택지를 골랐다. 대 볼 자리가 다른 저장소의 파일인 경우이고, 대 본 뒤에 설명을 다시 읽어 맞추는 것까지가 처방의 범위인지 반영할 때 본다.

7회차는 CI의 pytest를 나눠 돌린 harness 세션의 선택 화면이다. 병렬로 돌릴지 묻는 질문의 설명이 "시험은 이미 병렬을 전제로 짜여 있다"고 적었는데, 그 호출 앞에 읽지 않은 `tools/run_checks.py`의 독스트링이 "CI는 한 프로세스로 둔다는 결정(ADR 0035)"을 적고 있었다. 사용자가 병렬로 돌리기를 고른 뒤 셀프 리뷰 두 축이 옛 결정을 뒤집는다는 것을 짚어 같은 질문을 한 번 더 했다. 대 볼 자리가 코드 안의 독스트링에 적힌 결정까지다.

8회차는 문서만 바꾼 커밋의 pre-commit을 좁힌 harness 세션의 선택 화면이다. 남길 시험의 목록을 사용자에게 보이고 승인받았는데, 목록은 `tests/`를 경로 문자열로 grep한 것이라 파일을 헬퍼나 상수로 여는 시험을 놓쳤다. 티켓은 grep이었다고 적었지만 "넷"이라는 닫힌 수가 선택지의 전제였다. 셀프 리뷰 두 축이 두 시험을 더 찾았고, 파일을 열 때마다 기록하는 훅을 붙여 전체 pytest를 돌려(1시간 16분) 문서 범위를 읽는 시험의 모습을 확인했다. 사용자가 승인한 목록은 그대로 두고 둘을 독스트링의 못 보는 것에 적었다. 6회차와 같은 모양이다(센 방법이 놓치는 꼴까지 대 보아야 한다). 대 볼 방법이 grep이 아니라 실행 기록이라는 점이 다르다.

9회차는 admin 설계 세션의 질문 글, 선택지 설명, ADR 초안이다. 셋이 났다. 질문 10의 글은 agent-os에도 운영자 계정 로그인의 코드가 없다고 적었는데, 그 저장소는 그 결정의 티켓 열넷 가운데 셋을 지어 두었다. 질문 15에서 고른 선택지의 설명은 화면 부품을 복사할 때 새로 드는 바깥 패키지가 둘뿐이라고 적었는데, 그 저장소의 `web/packages/ui/package.json`은 여섯을 적는다. 셀프 리뷰 두 축이 둘을 Major로 냈고, 뒤의 것은 승인 화면에서 다시 물었다. ADR 0025 초안은 agent-os ADR 0062의 본문 문장을 옮기며 그 문장 바로 뒤에 달린 `(바뀜: 이력 …)` 포인터를 따라가지 않아 이력이 바꾼 옛 문장을 옮겼고, PR 직전 리뷰의 주장 대조가 잡았다. 5회차처럼 대 볼 자리가 다른 저장소의 파일이고, 옮기는 ADR 문장의 포인터가 가리키는 이력까지다.

6회차는 쉬운 말 규칙을 맞춘 harness 세션의 선택 화면이다. 이름을 바꾸면 고칠 파일의 수를 설명에 적었는데 하나는 틀렸고(8개라고 적은 것이 9개였다. 띄어 쓴 꼴로만 세어 밑줄로 이은 시험 이름이 빠졌다), 다른 셋은 어느 범위를 센 수인지 적지 않았다. 셀프 리뷰 두 축이 잡았다. 설명에 넣는 수는 센 방법이 놓치는 꼴과 센 범위까지 대 보아야 한다.
