# grilling-premise-check: 선택지 설명의 전제를 제품 그림(ADR·PRD)에 대 보지 않아 사용자가 바로잡았다

**상태:** 열림
**어디로:** `.claude/skills/grilling/SKILL.md`의 "올리기 전" 문단에 한 줄(설명에 넣는 사실을 코드·판정자뿐 아니라 ADR과 `docs/PRD.md`가 그린 제품의 자리에도 대 본다. 내부 부품을 설치처의 기존 것에 붙이는 장면을 전제로 두지 않는다)
**승인:** 자체 승인 2026-11-09, 4회차(더하는 것이라 다섯 번째에 반영한다), 일지 2026-11-10-1828-core-tickets.md, 2026-11-12-1419-dev-branch-model.md(3회차), 2026-11-12-2108-search-eval-design.md(4회차), ADR 불필요

core 설계 인터뷰 라운드 16의 최소 PostgreSQL 판 질문에서 선택지 설명에 "2026년 설치처의 PostgreSQL이 18일 가능성은 낮음"이라고 적었다. PostgreSQL은 이 제품이 동봉하는 데이터베이스(ADR 0002)라 그 장면이 없었고, 사용자가 라운드 17에서 바로잡았다. 일지의 "에이전트가 번복하거나 고친 것" 절.

2회차는 core 티켓 세션의 선택 화면이다(grilling 밖이라 반영할 때 자리를 넓힐지 본다). 최소 점수 질문의 설명이 ADR 0015의 칸 추가 minor 규칙을 입력 인자에도 맞는다고 적었는데, 그 규칙은 결과 객체의 칸이다. 명세 축 Minor 9와 표준 축 Nit 13이 잡았다.

3회차는 dev-branch 설계 세션의 합의 요약이다. 갈래 13이 CodeRabbit 자동 리뷰가 기본 브랜치 PR만 본다는 어림을 전제로 티켓을 실었는데, 저장소의 운영 문서 "리뷰 파이프라인"에 자동 리뷰가 아예 돌지 않는다는 실측이 있었다. 갈래 12는 일지가 재지 않은 추론이라고 적은 것을 사실의 꼴로 적었다. 셀프 리뷰 두 축(표준 축 Minor 4, 명세 축 Minor 11·12)이 잡았다. 대 볼 자리가 ADR·PRD만이 아니라 헌법 운영 문서까지라, 반영할 때 "올리기 전" 문단의 대 볼 자리를 저장소의 규약 문서로 넓힐지 본다.

4회차는 search-eval 설계 세션의 합의 요약과 ADR 초안이다. 셋이 났다. 최소 점수를 측정, 승인, 구현의 순서로 둔 결정을 계약을 바꾸는 티켓이 기능의 첫 티켓이라는 트래커 규약에 대 보지 않았다(표준 축 Major 1). ADR 0015 이력이 계약 시험이 inputSchema를 본다고 적었는데 `tests/`에는 그런 시험이 없었다(명세 축 Minor). 샘플링 인자의 거부를 스킬 문서가 적은 것보다 넓게, 고친 뒤에는 좁게 적었다(표준 축 Minor, 명세 축 Nit). 대 볼 자리가 규약 문서에 더해 지금 시험 코드와 근거로 든 바깥 문서의 그 줄까지다.
