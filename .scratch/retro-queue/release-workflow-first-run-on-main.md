# release-workflow-first-run-on-main: 릴리스 워크플로의 환경 변수 경로가 병합 전에는 한 번도 돌지 않아 첫 릴리스가 단독 시험에서 멈췄다

**상태:** 열림
**어디로:** `.github/workflows/ci.yml`의 `standalone` 잡(묶음 이름공간과 시험용 이미지 이름공간이 다른 환경 변수 경로로도 돈다)이나 `.github/workflows/release.yml`(풀 리퀘스트에서 올리기 없이 `build`까지만 도는 모드)
**승인:** 자체 승인 2026-11-20, 1회차(더하는 것이라 다섯 번째에 반영한다. 첫 릴리스 실행이 main에서 빨갛게 끝났으나 레지스트리와 릴리스에 올라간 것이 없어 손상으로 세지 않는다), 일지 2026-11-20-2016-standalone-test-fills-image-namespace.md, ADR 불필요

release-image 08을 병합하자 첫 릴리스 실행이 `build` 잡의 `단독 compose 시험`에서 약 20초 만에 멈췄다. 원인은 시험이 `.env`에서 이미지 이름공간을 시험이 받은 값으로 덮어쓰지 않은 것이었다. `ci.yml`의 단독 잡은 환경 변수를 주지 않아 시험이 자기 이름공간으로 묶음을 직접 짓고, 묶음과 이미지의 이름이 같아 이 틈이 드러나지 않았다. 환경 변수를 주는 길은 릴리스 워크플로가 처음 부르는 길이어서, 그 워크플로가 main에서 처음 돌 때까지 아무 검사도 이 길을 밟지 않았다. 같은 구조로 `build` 뒤쪽 단계(`점검`, `노트 짓기`, Docker 로그인, `이미지 올리기`, 시험한 이미지와 올린 이미지 대조, `publish`)도 main에서 처음 돈다. 이 항목은 그 길을 병합 전에 밟는 검사를 둔다. 비용은 단독 잡의 시간(이 PC에서 200~760초)이라 반영할 때 CI 시간과 맞대어 고른다.
