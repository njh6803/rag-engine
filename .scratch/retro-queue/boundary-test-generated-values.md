# boundary-test-generated-values: 하락폭 경계 시험이 손으로 쓴 짧은 소수만 써서, 실제 보고서의 `맞힌 수 / 질의 수` 값에서 깨지는 판정을 놓쳤다

**상태:** 열림
**어디로:** `CODING_STANDARDS.md`(다섯 번째 반복에서 retro가 더할 때. 숫자의 경계를 판정하는 코드의 시험은 경계 값을 손으로 쓴 소수만이 아니라 그 값을 실제로 내는 계산(나눗셈, 합)의 결과로도 만든다는 판단 기준 한 줄)
**승인:** 자체 승인 2026-11-15, 1회차(더하는 것이라 다섯 번째에 반영한다. 자동 검사로 옮길 수 없는 판단이다. 리뷰가 잡도록 둔 기준이 `CODING_STANDARDS.md`에 아직 없어 회차를 센다), 일지 2026-11-15-0631-search-eval-08-compare-gate.md, ADR 불필요

search-eval 08의 `compare`가 하락폭의 경계(정확히 2%p는 통과)를 `0.82`와 `0.80` 같은 짧은 소수로만 시험했다. 보고서의 `hit_at_5`는 `맞힌 수 / 질의 수`인 부동소수점이라, 질의 수가 150이나 300인 보고서에서는 끝자리 오차로 정확히 2%p 떨어진 쌍이 실패로 읽혔다. 명세 축 리뷰가 질의 수 50~1000에서 10310쌍 가운데 1712쌍이 그렇게 읽히는 것을 재서 Critical로 잡았다. 판정을 차의 소수 아홉째 자리 반올림으로 고치고, 질의 수마다 모든 맞힌 수의 경계 쌍을 훑는 시험을 더했다. 같은 실수의 첫 사례다. 잃은 것은 없다(커밋 전에 잡혔다).
