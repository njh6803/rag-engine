# mutate-stale-test-selector: 변이 표의 `tests` 선택자가 이름을 바꾼 시험을 가리켜도 `--check`가 알리지 않아 낡은 이름이 PR 봇의 지적으로 드러난다

**상태:** 열림
**어디로:** `tools/mutate.py`의 `--check`(변이 표의 `tests` 항목에서 `::`로 이어진 시험 이름이 해당 파일에 정말 있는지 확인한다. 파라미터 꼴(`[...]`)은 떼고 함수 이름만 대조한다)
**승인:** 자체 승인 2026-11-15, 1회차(더하는 것이라 다섯 번째에 반영한다), 일지 2026-11-14-2147-search-eval-12-relevance-judge-claude.md, ADR 불필요

티켓 12가 시험 이름을 `test_시간_초과와_요청_한도와_서버_오류는_일시_실패이고_…`로 바꿨는데 변이 표(`eval_judge_mutations.toml`)의 "SDK의 자체 재시도를 켠다" 변이는 옛 이름을 그대로 가리켰다. `tools/mutate.py --check`는 소스의 `old` 원문이 한 번씩 있는지만 보므로 이 낡은 선택자를 알리지 않았고, PR을 연 뒤 CodeRabbit의 첫 회차가 지적했다. 이 변이를 낡은 선택자로 돌리면 어떻게 알려지는지는 재지 않았다. 잃은 것은 없지만 변이 표를 한 번 더 고쳤다. `--check`에 시험 이름 존재 확인을 더하면 PR 전에 잡힌다. 표지(`expect_output`)의 줄 번호가 시험 편집으로 밀리는 일은 다른 사건이라 `mutate-marker-discovery`가 다룬다.
