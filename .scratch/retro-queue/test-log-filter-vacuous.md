# test-log-filter-vacuous: 시험이 로그 줄을 걸러내는 조건이 늘 거짓이어서 "로그가 없다"는 단언이 아무것도 보지 않은 채 초록이었다

**상태:** 열림
**어디로:** `CODING_STANDARDS.md`(다섯 번째 반복에서 retro가 더할 때. 로그나 호출 기록을 걸러 "없다"로 단언하는 시험은 같은 걸러내기가 줄을 하나라도 잡는 반대 시험을 함께 둔다는 판단 기준 한 줄)
**승인:** 자체 승인 2026-11-22, 1회차(더하는 것이라 다섯 번째에 반영한다. 걸러내기 조건이 맞는지는 코드가 쓰는 로거 이름에 달려 있어 정적 검사가 닿지 않는다), 일지 2026-11-22-0912-source-sync-05-connector-call-guard.md, ADR 불필요

source-sync 05 구현 세션의 시험이 `caplog` 줄을 `record.name == "rag_engine.adapters"`로 걸렀다. 장치의 실제 로거 이름은 `rag_engine.adapters.connectors.guard`라서 걸러낸 목록이 늘 비어 있었고, "한도 안에 돌아오면 기억하지 않는다" 시험의 "로그가 없다" 단언은 어떤 구현에서도 초록이었다. 셀프 리뷰의 표준 축이 코드로 로거 이름을 확인해 잡았다. 걸러내기를 한 도우미로 모으고 줄이 실제로 잡히는 시험을 함께 두어 고쳤다. 잃은 데이터는 없다.
