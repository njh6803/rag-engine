# renamed-term-reintroduced-by-parallel-pr: 이름 바꾸기 PR이 병합된 뒤에 같은 때 열려 있던 다른 PR이 옛 이름을 새 글에 다시 쓴다

**상태:** 열림
**어디로:** 살아 있는 파일에서 이미 버린 구절(예: "계약의 판")을 찾는 저장소 상태 시험(`tests/tools/`의 `test_이_저장소의_…`와 위반을 잡는 변이 시험 한 쌍, 기록과 agent-os 결정 이름 인용은 허용 위치로 뺀다). 구절 목록은 이름 바꾸기 티켓이 더한다
**승인:** 자체 승인 2026-11-20, 2회차(더하는 것이라 다섯 번째에 반영한다), 일지 2026-11-20-1854-glossary-release-number-names.md, 2026-11-20-2034-source-sync-design.md(2회차: PR 87이 릴리스의 뜻으로 쓰던 "판"을 버린 뒤에도, 그 전에 쓴 source-sync 설계 브랜치의 ADR 0022 초안 두 곳이 그 낱말을 쓰고 있었다. 승인 뒤 기준 브랜치를 받아 온 세션이 스스로 훑어 바꿨고 dev에는 들어가지 않았다. 검사가 잡은 것이 아니다), ADR 불필요

PR 78이 계약 번호의 "판"을 "계약 버전"으로 바꿔 병합한 뒤에, 같은 때 열려 있던 PR 80(노트 검사)이 PR 서식 36행과 `tools/check_notes.py` 84행에 "계약의 판"을 새로 써서 병합되었다. 그 PR은 PR 78의 훑기에 걸리지 않는 새 글이었고, 병합 시점에도 어떤 검사도 옛 이름을 막지 않았다. 이번 영역(`glossary-release-number-names`)의 훑기가 비로소 찾아 함께 바꿨다. 판 이름 바꾸기는 영역이 아직 둘 남아(홀로 쓰인 판, 색인 판 계열) 같은 일이 되풀이될 수 있다. 낱말 "판" 하나는 판정, 판단, 라이브러리 판처럼 뜻이 섞여 거짓 양성이 많으므로 검사는 낱말이 아니라 영역마다 버린 구체 구절만 목록에 둔다.
