# review-report-journal-lag: 셀프 리뷰와 PR 직전 리뷰의 보고를 받은 턴에 일지로 옮기지 않아 컨텍스트 압축 뒤 요약에서 일지를 다시 지어야 했다

**상태:** 열림
**어디로:** `.claude/skills/implement/SKILL.md`의 "Once done, use /code-review" 줄에 한 문장(리뷰를 부르기 전에 이 브랜치의 일지가 없으면 머리 한 줄 파일로 먼저 만들고, 두 리뷰의 보고는 받은 턴에 옮긴다. 이 지침은 `.claude/skills/code-review/SKILL.md` 6단계 끝과 `.claude/skills/next-session/merge.md` 3에 이미 있어, 구현 때 실리는 자리인 implement에는 포인터가 없다)
**승인:** 자체 승인 2026-11-11, 4회차(이미 있는 지침을 어긴 사건이라 회차를 센다. 더하는 것이라 다섯 번째에 반영한다), 일지 2026-11-11-0314-core-05-ingest-api.md, 2026-11-12-2108-search-eval-design.md(3회차), 2026-11-13-0453-search-eval-spec.md(4회차), ADR 불필요

core 04 구현 세션이 셀프 리뷰(두 축)와 PR 직전 리뷰의 보고를 받고도 일지 파일을 만들지 않았다. 일지는 PR을 연 뒤 병합 절차에서야 처음 쓰였고, 그 사이에 컨텍스트가 한 번 압축되어 리뷰의 지적별 판정과 이유를 압축 요약과 PR 본문에서 다시 모았다. `code-review` 6단계 끝이 정한 비용(대기열 244 상당)이 그대로 났다. 잃은 데이터는 없다(PR 본문과 요약이 판정을 담고 있었다).

3회차는 search-eval 설계 세션이다. 일지 파일은 리뷰 전에 있었지만, 셀프 리뷰 두 축의 보고와 지적별 판정을 받은 턴에 일지로 옮기지 않고 ADR과 프로브를 먼저 고쳤다. 그 사이에 컨텍스트가 압축되어 셀프 리뷰 절을 압축 요약에서 다시 지었다. 잃은 판정은 없다(요약이 지적마다 처리를 담고 있었다). 이번은 implement가 아니라 설계 산출물 단계(`grill-with-docs`)라, 처방의 포인터를 둘 자리가 implement만이 아니다.

4회차는 search-eval 명세 세션이다. 셀프 리뷰 두 축의 보고를 받은 뒤 컨텍스트가 압축되어, 지적을 축별이 아니라 합친 요지로 일지에 옮겼다. 잃은 판정은 없다. 이번 단계는 `to-spec`이라 3회차와 마찬가지로 implement에 둔 포인터가 닿지 않는다.
