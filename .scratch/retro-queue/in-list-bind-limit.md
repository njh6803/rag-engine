# in-list-bind-limit: 문서 수만큼 ID를 넣는 `IN` 목록이 psycopg의 바인드 파라미터 한도(65535)를 넘으면 문장이 실패한다

**상태:** 열림
**어디로:** `CODING_STANDARDS.md`(다섯 번째 반복에서 retro가 더할 때. 판단 기준 한 줄: 길이가 데이터 양에 비례하는 ID 목록은 `IN`에 통째로 넣지 않고 묶음으로 나눠 보낸다)
**승인:** 자체 승인 2026-11-12, 1회차(더하는 것이라 다섯 번째에 반영한다. 셀프 리뷰가 잡았고 병합 전이라 손상이 아니다), 일지 2026-11-12-1644-core-14-reindex-version-switch.md, ADR 불필요

core 14의 `lock_queued_documents`가 살아 있는 문서 전부의 ID를 `IN (…)` 한 문장으로 보내, 문서가 65,535개를 넘는 지식베이스에서는 재색인 시작이 실패했다. 시험은 문서 두세 개만 쓰므로 초록이었고 셀프 리뷰의 서브에이전트가 짚었다. 린터나 타입체커로 판정할 수 없다(목록의 길이는 실행 때 정해진다). 한도를 넘겨 부르는 어댑터 시험(7만 개 ID)이 이 실수를 잡는 층이고, 같은 실수가 다섯 번 쌓이면 어느 호출 자리에 시험을 요구할지 `CODING_STANDARDS.md`에 적는다.
