# security-review-skipped-on-docs-pr: 문서만 바뀐 PR이라며 내장 `/security-review`를 건너뛰었고, 그 명령은 돌려도 문서의 지적을 제외 목록으로 뺀다

**상태:** 열림
**어디로:** `.claude/agents/bug-perf-review.md`의 보고 끝에 한 줄(보안 축은 본 세션이 이 보고를 받은 턴에 내장 `/security-review`로 본다. 문서만 바뀐 변경도 같고, 그때는 그 문서를 글자 그대로 구현하면 취약점이 되는 공백을 묻는 갈래를 하위 작업의 브리프에 더한다)
**승인:** 자체 승인 2026-11-13, 1회차(이미 있는 지침을 어긴 사건이라 회차를 센다. 더하는 것이라 다섯 번째에 반영한다. 병합 전에 PR 서식의 체크리스트가 잡아 손상이 아니다), 일지 2026-11-13-0453-search-eval-spec.md, ADR 불필요

search-eval 명세 세션이 PR 직전에 `bug-perf-review`만 돌리고 내장 `/security-review`는 돌리지 않았다. 비밀이 없고 실행하는 코드가 로컬 TEI에 붙는 측정 스크립트 둘뿐이라고 보았기 때문이다. PR 서식의 체크리스트와 `docs/constitution/operations.md` 리뷰 파이프라인은 CLI가 돌지 않을 때 보안 축을 그 명령이 본다고 정하고, 서식은 문서만 바뀐 PR도 면제가 아니라고 적는다. PR 본문의 체크리스트를 채우다 알았고, 첫 커밋 뒤에 돌려 반영 커밋이 하나 늘었다.

그 명령은 문서 파일의 지적을 제외 목록으로 뺀다(스킬 본문의 거짓 양성을 거르는 목록에 문서 파일의 지적을 내지 말라는 항이 있다. 손으로 봤다). 그래서 문서만 바뀐 PR에서는 그대로 돌리면 낼 것이 없다. 그 세션은 취약점을 찾는 하위 작업에 갈래를 하나 더 맡겼고(명세를 글자 그대로 구현하면 취약점이 되는 설계의 공백), 그 갈래가 Major 하나(평가 도구가 평가용이 아닌 데이터베이스에 붙는 길)와 Minor 둘을 냈다. 처방을 `docs/constitution/operations.md`에 두려면 헌법 파일이라 ADR과 사용자 승인이 따른다.
