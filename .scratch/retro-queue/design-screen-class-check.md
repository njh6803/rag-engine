# design-screen-class-check: 화면 그림이 디자인 시스템에 없는 배치 클래스와 글자 크기를 덮는 인라인 `font`를 써서, 사람이 깨진 화면을 고치라고 했다

**상태:** 열림
**어디로:** `tools/`의 화면 파일 검사 하나(받은 `.dc.html`의 `class` 값을 디자인 시스템 README의 유틸리티 목록과 번들 CSS의 클래스에 대 보고, 글자 크기 클래스를 단 요소의 인라인 `font` 줄임을 낸다. `.claude/skills/ui-design/SKILL.md` 5의 그리기 끝이나 7의 받기 뒤에 부른다)
**승인:** 자체 승인 2026-11-28, 1회차(더하는 것이라 다섯 번째에 반영한다), 일지 2026-11-26-1938-admin-screens.md, ADR 불필요

admin 화면 그리기의 브리프는 "배치 클래스는 README가 든 유틸리티 목록만 쓴다"였는데, 그림이 `gap-6`, `grid`, `items-end`, `justify-end`를 썼고 넷 다 번들 CSS에도 없어 간격과 정렬이 빠졌다. 또 글자 크기 클래스(`text-body` 등)를 단 요소에 인라인 `font: inherit;`를 써서, 그 줄임이 클래스의 글자 크기를 덮어 글자가 커지고 겹쳤다. 사람이 확정 질문(일지의 호출 10)에서 고칠 것 열 가지를 말한 뒤, 렌더해 보고서야 원인을 찾았다. 디자인 시스템 묶음(`project/ds/agent-os/`)은 저장소로 옮기지 않으므로, 검사는 받은 폴더나 렌더 폴더의 CSS 경로를 인자로 받는다. `text-center`처럼 README 목록에는 없지만 번들 CSS에는 있는 클래스는 지나가야 한다.
