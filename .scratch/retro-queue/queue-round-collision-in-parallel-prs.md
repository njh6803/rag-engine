# queue-round-collision-in-parallel-prs: 나란히 연 두 PR이 같은 대기열 항목의 승인 줄에 같은 회차를 적어, dev를 합칠 때 충돌이 났다

**상태:** 열림
**어디로:** `tools/sibling_overlap.py`(함께 고친 파일이 대기열 항목이면 승인 줄에 더한 회차가 형제와 겹치는지 짚는다)
**승인:** 자체 승인 2026-11-21, 2회차(더하는 것이라 다섯 번째에 반영한다. 충돌은 git이 알렸고 잃은 작업이 없어 손상이 아니다), 일지 2026-11-21-1358-source-sync-spec.md, 2026-11-25-1632-review-report-to-journal-on-receipt.md(2회차: 형제 PR이 같은 항목의 승인 줄을 먼저 병합해 리베이스에서 그 한 줄이 충돌했다. 충돌은 git이 알렸고 잃은 작업이 없어 손상이 아니다), ADR 불필요

PR 89와 나란히 열린 PR이 `docs-only-commit-full-pytest`의 승인 줄에 같은 회차를 적었다. 나중에 병합되는 쪽이 dev를 합치며 충돌을 풀고 회차를 10으로 옮겼다. 항목마다 파일 하나인 모양은 새 항목끼리의 충돌만 막고, 같은 항목에 회차를 더하는 두 브랜치는 막지 못한다. 그때 `tools/sibling_overlap.py`가 그 파일을 함께 고친 파일로 냈는지는 보지 않았다. 경과는 PR 89의 본문 "확인 방법"과 마지막 코멘트에 있다.
