# key-visible-in-user-terminal: 사용자 터미널 화면에 판정기 API 키의 글자가 보여 세션이 그 화면을 읽을 때 키가 대화에 실렸을 수 있다

**상태:** 열림
**어디로:** `docs/agents/`나 `.claude/rules/tools.md`의 한 줄 또는 `tools/search_eval.py judge`가 키를 `.env`에서 받는 길(사용자가 비밀을 터미널에 치지 않고 `.env` 파일이나 보안 입력 프롬프트로 넣게 한다). 자리는 반영하는 chore가 정한다
**승인:** 자체 승인 2026-11-17, 손상 1건(비밀이 밖으로 나간 사건으로 센다. 회차와 상관없이 문턱을 채워 다음 하네스 chore 배치에 고른다. `tools/queue_open_rows.py`는 손상을 세지 않아 chore 계기 목록에 나오지 않는다), 1회차, 일지 2026-11-17-1101-search-eval-13-first-judge-run.md, ADR 불필요

티켓 13에서 이 세션의 `.env` 읽기를 권한 판정이 거부해 사용자가 키를 넣은 환경에서 `judge`를 직접 돌렸다. 이 세션이 터미널 패널을 읽는 도구로 출력을 확인하다가 화면에 키의 글자가 보인 것을 알았다. 그 도구 결과가 대화 기록이나 로그에 남지 않았다는 근거는 없다. 그래서 이 사건은 노출 가능 상태가 아니라 노출된 것으로 세고, 키 교체 여부는 노출된 키를 계속 쓸 수 있는지와 대응 순서에만 쓴다(PR 61의 CodeRabbit 지적을 받아들여 고쳤다).

이 세션은 그 값을 답이나 커밋에 옮기지 않았고(커밋 대상에서 `sk-ant`와 `api03`을 `git grep`으로 찾아 0건이었다) 사용자에게 키를 교체하라고 안내했다. 사용자가 교체했는지는 이 세션이 모른다.
