# post-merge-base-push-ci-unchecked: 병합한 뒤 기준 브랜치의 푸시 CI를 보지 않아 dev의 푸시 실행 둘이 15분 제한에서 취소된 채 지나갔다

**상태:** 열림
**어디로:** `.claude/skills/next-session/merge.md`(병합 직후 단계에 기준 브랜치의 푸시 실행을 `gh run list --branch <기준 브랜치> --event push --limit 1`로 읽어, 끝났는데 초록이 아니면 보고에 적고 이어가기 전에 사용자에게 알리는 줄. 푸시 실행이 아직 돌고 있으면 기다리는 도구(`tools/wait_ci.py`)가 그 길을 지원하는지를 반영할 때 본다)
**승인:** 자체 승인 2026-11-23, 1회차(손상으로 센다. 병합 뒤 `dev`의 푸시 검사가 빨갛기 때문이다. 그래서 다섯 번째를 기다리지 않고 한 번으로 반영한다. 이 PR은 CI의 pytest를 나눠 돌리는 일이라 싣지 않았다), 일지 2026-11-23-1422-ci-pytest-parallel.md, ADR 불필요

source-sync 티켓 10(PR #106)과 08(PR #107)을 `dev`로 잇달아 병합했는데, 두 병합의 `dev` 푸시 CI 실행(`cc807a1`, `6601a7c`)이 모두 `python` 잡이 제한 15분에 걸려 취소됐고 `6601a7c`는 필수 검사 `verify`가 실패했다(`gh run list`와 `gh run view`로 읽었다). 병합 절차(`merge.md`)는 PR의 머리 CI가 초록인지까지만 보고, 병합 뒤 기준 브랜치의 푸시 실행을 보라는 단계가 없다(`merge.md`를 푸시 CI 낱말로 grep해 찾지 못했다). 그래서 병합한 세션은 `dev`가 빨간 것을 보지 못하고 끝났고, 다음 세션이 CI 시간을 살피다 우연히 찾았다. PR의 머리 CI는 같은 코드로 14분 34초에 통과했었다(제한에서 26초). 병합 커밋은 PR 머리와 코드가 같아도 시간이 갈려 다르게 끝날 수 있다.
