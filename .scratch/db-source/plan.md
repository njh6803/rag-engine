# db-source: SQL 커넥터. 운영자가 쓴 질의와 매핑으로 데이터베이스에 든 글과 그 첨부를 문서로 수집한다
**슬라이스:** 3
**Blocked by:** source-sync, release-0-1

킥오프 입력 4절의 "SQL 커넥터: 세 층"대로 짓는다. 연결 문자열로 드라이버를 고르고, 운영자가 적은 질의와 매핑 설정(ID, 본문 템플릿, 메타데이터 칼럼과 형식, 증분의 기준, 삭제, 첨부 칼럼과 자식 질의)으로 데이터베이스에 든 글과 그 첨부를 문서로 가져온다. 원천에는 읽기 전용 계정으로 붙는다. 변환 플러그인의 예시 하나(본문의 HTML 정리)를 함께 낸다. 재배포할 수 없는 드라이버는 설치 환경이 볼륨으로 넣는 절차를 안내에 적는다. 관리자 페이지에 질의 결과 몇 행이 어떤 문서와 첨부가 되는지 미리 보는 화면을 둔다. 구조화 데이터는 이 커넥터로 가져오지 않는다(킥오프 입력 4절). 설계 인터뷰 전에 대상 DBMS별로 드라이버, 재배포 조건, ODBC 대안을 표로 정리한다(킥오프 입력 7절의 4).

source-sync 설계(ADR 0021·0022, 2026-11-20)가 넘긴 것: 둘이다. 첫째는 변환 인터페이스의 메서드 모양과 수집 파이프라인에 변환 단계를 끼우는 일이다. core 명세가 source-sync에 넘겼던 것인데 source-sync는 커넥터 인터페이스만 짓고, 0.1에는 변환 자리가 없다. source-sync의 인터뷰가 고르지 않은 변환의 모양 둘(문서 하나를 받아 하나를 돌려주거나 넣지 않는다고 답하는 모양, 처음부터 하나를 여럿으로 돌려주는 모양)은 ADR 0021 Considered Options에 있다. 둘째는 연결 정보의 암호화 보관과 열쇠 관리다. source-sync는 원천 설정에 비밀 값을 넣는 칸을 두지 않는다. 저장한 뒤에는 다시 보여 주지 않고 진단 묶음과 로그에 싣지 않는다는 킥오프 입력 4절의 규칙도 이 기능이 받는다. 가져오는 원천에 공통인 동기화의 장치(cron 표현식 일정, 겹침 방지, 목록이 비면 지우지 않는 보호, 일시 중지, 동기화 기록)는 source-sync가 지으므로 이 기능은 그 위에 선다(ADR 0022).

source-sync 명세(`.scratch/source-sync/spec.md`, 2026-11-21)가 넘긴 것: 위 문단의 둘에 셋을 더한다. 첫째는 메타데이터 매핑이다. 서버 경로 원천은 제목(파일 이름)과 갱신일(파일의 수정 시각)만 채우고 메타데이터는 빈 객체로 둔다. 작성 부서나 시행일처럼 칼럼에서 가져올 값은 이 기능이 매핑으로 정한다. 커넥터가 `fetch`의 메타데이터에 `title`을 문자열로 실으면 서버가 그것을 문서의 제목으로 쓴다. 둘째는 확장자가 없는 키와 파일이 아닌 본문 글을 문서로 받는 길이다. 명세는 가져오는 원천의 형식을 키의 확장자로만 가르게 했다(`.pdf`, `.docx`, `.hwpx`). 그래서 게시글 번호를 키로 내는 커넥터의 항목은 지금 규칙으로는 문서가 되지 않고 동기화 기록에 `unsupported_type`으로 세어진다. 셋째는 커넥터를 만드는 사람을 위한 안내다(설치처가 만든 커넥터를 이미지에 넣는 절차를 포함한다). source-sync는 커넥터 인터페이스 1.0과 내장 커넥터 하나(`server_path`)만 짓고 안내는 쓰지 않는다. 둘째 커넥터를 짓는 이 기능이 지으며 겪은 것으로 쓴다. 이 기능이 서는 인터페이스의 모양은 그 명세의 "커넥터 인터페이스 1.0" 절이 정했다. 커넥터는 원천의 설정(JSON 객체) 하나를 받아 만들어지고, `list()`는 키와 변경 확인값과 크기를 하나씩 내며, 예외는 닫힌 사유 값 넷을 든 하나뿐이고 서버는 예외의 글을 응답과 동기화 기록과 로그 어디에도 싣지 않는다. 수집 정책(제외 패턴, 형식, 크기)은 커넥터가 아니라 서버가 적용한다. 원천의 설정에 비밀 값을 넣지 않는다는 것은 인터페이스의 설명이 적는 약속일 뿐이고 서버가 막지 못하며, 관리 API의 원천 보기는 설정을 그대로 보여 준다. 연결 정보를 어디에 둘지 정할 때 이것을 함께 본다.

수락: 본문 칼럼 여럿, 메타데이터 칼럼 여럿, 1:N 첨부 표(첨부는 파일 경로)를 가진 표본 게시판을 PostgreSQL과 다른 DBMS 하나에서 원천으로 수집하고, 행과 첨부를 더하고 고치고 지우면 다음 실행 뒤 검색 결과가 따라 바뀌며, 변환 플러그인 예시를 켜면 본문의 HTML이 정리된 채 색인된다.
