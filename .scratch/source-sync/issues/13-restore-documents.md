# 13: 문서 되살리기

**What to build:** 운영자가 업로드나 수집 API로 넣었다가 실수로 지운 문서 하나를 관리 API 호출 하나로 되살린다. 보관해 둔 조각이 되돌아와 다시 임베딩하지 않고 검색에 나오고, 그사이 색인 판이 바뀌었으면 보관해 둔 원본으로 다시 색인한다. 가져오는 원천의 문서는 API로 되살리지 않고, 원천 폴더에 파일을 되돌려 놓으면 다음 동기화가 되살린다(스토리 33).

**Blocked by:** 11 (원천 삭제)

**Status:** done

- [x] `POST /documents/{document_id}/restore`는 작업 단위 하나에서 core 명세의 되살림을 내용이 같은 경우로 한다(명세 "문서 되살리기"). 그룹, 제목, 메타데이터는 문서 행의 것 그대로이고, 대상 판의 보관 조각 가운데 만든 내용 해시가 문서의 내용 해시와 같은 것만 되돌려 색인 상태를 `indexed`로 쓰며, 되돌릴 조각이 없는 대상 판이 있으면 색인 작업을 넣는다. 건너뜀 문서는 조각이 없으므로 대상 판마다 색인 상태만 다시 쓴다(12의 원천 되살리기 작업과 같다). 원천과 함께 지워졌다는 표시가 남아 있던 문서면 그 표시도 지운다. 응답은 200이고 문서와, 넣은 작업이 있으면 그 식별자를 싣는다.
- [x] 거절하는 경우는 넷이다. 없는 문서와 삭제 기록은 404 `document_not_found`, 지워지지 않은 문서는 409 `document_not_deleted`, 가져오는 원천의 문서는 409 `wrong_source_kind`, 지운 원천의 문서는 409 `source_deleted`다. 요청은 원천 행을 공유 잠금으로 잡은 뒤(11의 잠금 순서) 문서 행을 잠그고 이 조건을 본다. 보관 기간이 지났는지는 보지 않는다(명세 "문서 되살리기"가 원천 되살리기와 다르게 정했다). Problem Details의 코드에 `document_not_deleted`를 더하고 코드 수를 적은 머리 설명과 주석을 고친다.
- [x] 시험(주 이음매, 명세 "Testing Decisions"의 장면 표): 밀어 넣는 원천의 지운 문서를 되살리면 검색에 돌아오고, 그사이 색인 판이 그대로였으면 임베딩 호출이 0번이다. 가져오는 원천의 지운 문서를 되살리려 하면 409 `wrong_source_kind`다. 지워지지 않은 문서는 409 `document_not_deleted`, 없는 식별자는 404, 지운 원천의 문서는 409 `source_deleted`다. 재색인으로 색인 판을 바꾼 뒤 그 전에 지운 문서를 되살리면 색인 작업이 들어가고, 작업자를 돌린 뒤 그 문서가 검색에 나온다.
- [x] 검사 넷이 초록이다. 원칙 II는 `tools/check_type_escapes.py`가 판정한다.
