# 03: 밀어 넣는 원천과 수집 API의 원천 이름

**What to build:** 운영자가 관리 API로 문서를 보내는 시스템마다 밀어 넣는 원천(`push`. 다른 시스템이 수집 API로 문서를 보내 넣는 원천)을 만들고, 원천 목록과 원천 하나를 본다. 연동 개발자는 수집 API의 넣기와 지우기 요청에 `source`를 적어 자기 원천에 문서를 넣고, 적지 않은 지금의 요청은 그대로 `default`에 들어간다. 원천이 다르면 같은 키가 서로 다른 문서로 남는다. 관리자 페이지가 파일을 올릴 때 쓸 `upload` 원천을 `migrate`가 만들어 둔다(스토리 1, 2, 3, 4의 없는 원천).

**Blocked by:** 01 (커넥터 인터페이스 1.0과 이 기능의 스키마)

**Status:** done

- [x] `migrate`가 `default`와 함께 `upload`를 밀어 넣는 원천으로 만들어 둔다(명세 "따르는 것과 범위"). 마이그레이션이 아니라 기본 레코드를 만드는 자리에서 하고, 다시 돌려도 둘째가 생기지 않는다.
- [x] 원천 이름의 규칙(1~63자, 영문 소문자·숫자·`-`·`_`, 영문 소문자나 숫자로 시작. 명세 "데이터 모델과 스키마")을 이 티켓에 둔다. 원천 이름을 받는 첫 티켓이기 때문이다(명세 "티켓을 나눌 때 함께 둘 것"). `migrate`가 만드는 `default`와 `upload`가 규칙에 맞는지를 시험으로 본다.
- [x] 관리 API에 `POST /sources`(밀어 넣는 원천만. `kind`가 `push`이고 `name`만 받으며 가져오는 원천만 쓰는 다섯 칸을 적으면 422), `GET /sources`, `GET /sources/{name}`을 더한다(명세 "관리 API"). 가져오는 원천을 만드는 `kind: pull`은 06이 연다. 그 전에는 422로 거절한다.
- [x] 원천 응답의 칸은 명세 "관리 API"의 원천 응답 항목 그대로다. 밀어 넣는 원천에서는 가져오는 원천만 쓰는 칸이 null이다. 문서 수 `documents`는 지워지지 않은 문서를 문서 상태로 센 `total`, `failed`, `skipped`다(`skipped`는 02가 그 상태를 쓰기 전에는 0이다. 건너뜀 문서를 세는 시험은 07이 동기화로 본다). `last_sync`는 동기화 기록이 07에서 생기기 전까지 늘 null이다. 목록과 하나 보기의 모양이 같다. `include_deleted`는 지운 원천이 생기는 11이 연다.
- [x] 수집 API의 넣기 요청 폼에 `source`를, 지우기 요청의 쿼리에 `source`를 더한다. 적지 않으면 `default`다(명세 "수집 API"). 없는 원천은 404 `source_not_found`, 규칙에 어긋나는 이름은 422다. 가져오는 원천의 이름은 409 `wrong_source_kind`이고 그 시험은 가져오는 원천이 생기는 06이, 지운 원천의 409 `source_deleted`는 11이 본다.
- [x] 관리 API의 문서 목록에 원천 이름으로 거르는 `source`를 더한다. `key`만 적으면 모든 원천에서 그 키의 문서를 찾는다(명세 "관리 API").
- [x] 만드는 요청을 거절하는 경우: 이름이 규칙에 어긋나면 422 `validation_error`(오류 목록의 `loc` 마지막 토막이 `name`), 이름이 이미 있으면 409 `source_already_exists`다(명세 "관리 API"). Problem Details의 코드에 이 티켓이 `source_not_found`와 `source_already_exists`를 더하고, 오류 코드를 정의한 자리의 머리 설명과 주석이 적은 코드 수를 고친다(명세 "규약 문서와 낡은 문장").
- [x] 시험(주 이음매): 원천 `a`와 `b`를 만들고 같은 키의 파일을 둘에 넣으면 서로 다른 문서 둘로 남고 문서 목록의 `source`로 갈라 보인다. 수집 API에 `source`를 적지 않거나, `upload`를 적거나, 없는 이름을 적으면 차례로 `default`에 들어가고, `upload`에 들어가고, 404다. 넣은 문서는 작업자를 한 번 돌린 뒤 검색에 나온다. 규칙에 어긋나는 이름(대문자가 든 것, 64자, `-`로 시작하는 것)으로 원천을 만들거나 수집 API의 `source`에 적으면 모두 422다(명세 "Testing Decisions"의 장면 표). 지우기 요청도 `source`로 그 원천의 문서만 지운다.
- [x] 검사 넷이 초록이다. 원칙 II는 `tools/check_type_escapes.py`가 판정한다.
