# 01: 커넥터 인터페이스 1.0과 이 기능의 스키마

**What to build:** 커넥터를 만드는 사람이 구현할 계약(커넥터 인터페이스 1.0)이 `domain`에 서고, 서버와 작업자가 커넥터의 이름과 원천의 설정으로 그 커넥터를 찾아 만들 수 있다. 인터페이스의 major 버전이 다르거나 설치되지 않은 커넥터는 거부된다. `rag-engine --version`이 커넥터 인터페이스의 버전 줄을 찍는다. 이 기능이 쓰는 표와 칸과 제약과 색인은 마이그레이션 하나로 모두 생기므로, 뒤의 티켓은 마이그레이션을 더하지 않고 나란히 돈다(건너뜀으로 옮기는 데이터 마이그레이션만 02가 더한다). 운영자에게 보이는 동작은 아직 없다.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 커넥터 인터페이스 1.0을 `domain`에 둔다(명세 "층과 포트", "커넥터 인터페이스 1.0", ADR 0012). Protocol 하나와 그것이 주고받는 값(목록의 항목: 키, 변경 확인값, 크기. `fetch`의 결과: 바이트, MIME, 갱신 시각, 메타데이터)과 예외 하나다. 커넥터를 만드는 함수는 원천의 설정(JSON 객체) 하나를 받는 보통 함수이고, `fetch`와 `check()`는 비동기 함수이며 `list()`는 비동기 반복이다. 예외는 닫힌 사유 값 다섯(`invalid_config`, `unreadable`, `rejected`, `not_found`, `too_large`)을 든다.
- [ ] 인터페이스의 설명(독스트링)에 명세가 인터페이스의 설명에 적으라고 정한 약속을 적는다. 만드는 함수는 설정의 모양만 보고 원천에 닿지 않는다는 것과 설정이 맞지 않으면 `invalid_config`를 올린다는 것, 설정(`config`)에 비밀 값을 넣지 않는다는 것, 키가 `.pdf`·`.docx`·`.hwpx`로 끝나지 않는 항목은 문서가 되지 않는다는 것, 같은 키를 두 번 내면 동기화가 실패한다는 것, 커넥터는 `fetch`가 한 번에 내는 바이트의 크기를 스스로 지킨다는 것, 서버는 예외의 사유 값만 쓰고 글은 싣지 않는다는 것이다.
- [ ] 새 포트 셋의 Protocol을 `domain`에 둔다. `ConnectorRegistry`(커넥터 이름과 원천의 설정을 받아 커넥터를 만들고 인터페이스 버전을 판정한다), `ScheduleCalculator`(일정 표현식을 확인하고 다음 실행 시각을 낸다), `SyncRecordStore`(동기화 기록을 저장한다)다. 메서드의 이름과 모양은 이 티켓이 정하되, 그 포트를 처음 쓰는 티켓(`ScheduleCalculator`는 10, `SyncRecordStore`는 07)이 바꿀 수 있다고 독스트링에 적는다. 엔티티와 이미 있는 포트(`Catalog`, `DocumentStore`, `VectorIndex`, `JobQueue`, `BlobStore`)에 더할 메서드는 그것을 쓰는 티켓이 더한다.
- [ ] `ConnectorRegistry`의 구현을 `adapters`에 둔다. entry point 그룹 `rag_engine.connectors`에서 이름으로 커넥터를 찾고, `interface_version`의 major가 1이 아니면 거부한다. 설치되지 않은 이름과 major가 다른 커넥터는 같은 거부(뒤 티켓이 422와 `connector_unavailable`로 옮긴다)로 알리고, 만드는 함수가 `invalid_config`를 올리면 그 사유를 그대로 전한다. 시험은 가짜 entry point로 셋(찾았다, 설치되지 않았다, major가 다르다)과 `invalid_config`를 본다.
- [ ] 포트를 정의한 모듈의 머리 설명에서 `Connector`와 `Transform`의 Protocol을 source-sync가 만든다는 문장을 고친다(명세 "규약 문서와 낡은 문장". 변환 인터페이스는 db-source로 넘어갔다, ADR 0021 "이번에 짓지 않는 것"). 작업 단위 안에서 얻는 포트가 넷이라는 문장은 07이 고친다.
- [ ] `rag-engine --version`의 목록에 `커넥터 인터페이스 1.0.0` 줄을 더하고 출력 시험을 넓힌다(명세 "커넥터 인터페이스 1.0"의 마지막 항목, "Testing Decisions"의 검색 도구 형식 항목). 값은 파서 인터페이스처럼 세 자리이고, 04의 서버 경로 커넥터가 같은 상수를 `interface_version`으로 쓴다.
- [ ] 마이그레이션 하나에 명세 "데이터 모델과 스키마"의 스키마를 모두 담는다. 번호는 dev의 마지막 마이그레이션 다음 번호다(티켓을 쓸 때 dev의 마지막은 0003이라 0004였다). 브랜치를 딴 뒤 형제 브랜치나 열린 PR이 같은 번호를 쓰면 그다음 번호로 비켜 간다. 원천 표의 갈래 값 `pull`과 더하는 칸(커넥터 이름, 커넥터 설정, 그룹, 일정 표현식, 다음 실행 시각, 일시 중지, 제외 패턴 목록, 지운 시각, 만든 시각)과 갈래별 칸 제약, 문서 표의 세 칸(변경 확인값, 건너뜀 사유, 원천과 함께 지워졌다는 표시)과 문서 상태 값 `skipped`, 비어 있을 수 있는 원본 경로, 작업 표의 종류 다섯과 원천 칸·옵션 칸, 비어 있을 수 있는 문서 칸, 종류별로 가리키는 것의 제약, 문서를 가리키지 않는 작업의 부분 유일 색인(대기 중이거나 실행 중인 것 가운데 (원천, 종류)가 같은 것은 하나, `NULLS NOT DISTINCT`), 색인 작업이 아닌 작업만 담은 꺼내기용 부분 색인(명세 "작업 대기열"), 동기화 기록 표(`sync_records`, 칸은 명세 "동기화 기록")다. 이미 있는 원천 행의 만든 시각은 마이그레이션이 채운다. 내리기(downgrade)도 쓴다.
- [ ] 표 정의 모듈을 마이그레이션과 맞춘다. 표 정의가 마이그레이션이 만든 표와 어긋나지 않는지 보는 시험(`tests/adapters/test_migrations.py`의 `test_표_정의가_마이그레이션이_만든_표와_어긋나지_않는다`)이 초록이다. 칸 제약과 부분 유일 색인은 어댑터 시험으로 본다(밀어 넣는 원천에 커넥터 이름을 쓰면 거부, 색인 작업이 원천을 가리키면 거부, 같은 원천의 대기 중인 동기화 작업 둘째와 정리 작업 둘째가 거부).
- [ ] 색인 형식의 스키마 판(`SCHEMA_VERSION`)은 0003의 선례대로 올리지 않는다. 이 마이그레이션은 색인 판의 요소가 아닌 표를 고치므로 재색인이 필요 없다. 마이그레이션의 머리 설명에 그 까닭을 적는다.
- [ ] 이 티켓의 PR 제목에는 느낌표를 붙인다(마이그레이션이 든 PR, ADR 0020).
- [ ] 검사 넷이 초록이다. 원칙 II(`Any`, `cast`, `type: ignore`, `pyright: ignore` 금지)는 `tools/check_type_escapes.py`가 판정한다.
