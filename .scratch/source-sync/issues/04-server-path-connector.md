# 04: 서버 경로 커넥터

**What to build:** 내장 커넥터 `server_path`가 부모 폴더(`RAG_SOURCES_DIR`, 기본 `/sources`) 아래의 하위 폴더 하나를 열거하고 파일을 받는다. 부모 폴더 밖의 파일과 심볼릭 링크 너머의 파일은 읽지 않고, 경로를 확인한 뒤 그 사이에 링크로 바꿔치기해도 밖을 읽지 않는다. 보안 담당자는 관리 토큰을 가진 쪽이 검색으로 서버 안의 다른 파일을 읽어 내지 못한다는 것을 이 커넥터의 시험으로 확인한다(스토리 7). 이 티켓은 커넥터만 짓고, 원천을 만드는 API와 동기화는 06과 07이 붙인다.

**Blocked by:** 01 (커넥터 인터페이스 1.0과 이 기능의 스키마)

**Status:** done

- [x] 커넥터 이름은 `server_path`이고 entry point 그룹 `rag_engine.connectors`에 등록한다. `interface_version`은 01이 둔 커넥터 인터페이스 버전 상수(`1.0.0`)다. 01의 `ConnectorRegistry`가 이 이름으로 이 커넥터를 찾는 시험을 둔다.
- [x] 설정은 `folder` 하나이고 부모 폴더 기준의 상대 경로이며 여러 단계를 받는다(명세 "서버 경로 커넥터와 원천 폴더"). 빈 값, `.`, `..` 토막이 든 값, `/`로 시작하는 값, 역슬래시나 NUL이 든 값, `folder`가 없거나 문자열이 아닌 설정은 만드는 함수가 `invalid_config`로 알린다. 끝의 `/`는 뗀다. 만드는 함수는 파일 시스템을 부르지 않는다(명세 "커넥터 인터페이스 1.0"의 만드는 함수 항목). 부모 폴더는 커넥터가 `RAG_SOURCES_DIR`에서 스스로 읽는다.
- [x] 경로 확인은 부모 폴더에서 원천 폴더까지의 토막마다 하고, 어느 토막이든 심볼릭 링크이거나 폴더가 아니면 `rejected`다. `list()`는 첫 항목을 내기 전에, `check()`와 `fetch`는 부를 때마다 확인한다. 원천 폴더가 없으면 `list()`와 `check()`는 `unreadable`이다(명세 "Testing Decisions"의 연결 확인 장면과 폴더를 없앤 동기화 장면이 `source_unreadable`을 기대한다). `fetch`는 원천 폴더에서 그 파일까지의 토막도 같은 방식으로 보고, 마지막 토막이 보통 파일이 아니면 읽지 않는다. 없는 키는 `not_found`다. 키를 `/`로 나눈 토막에 빈 토막, `.`이나 `..` 토막이 있거나, 키에 NUL이 있거나, 키가 `/`로 시작하면 파일 시스템을 부르지 않고 `rejected`다. 역슬래시는 운영체제가 그것을 경로 구분자로 읽을 때(Windows)만 거절하고, 리눅스에서는 보통 글자로 받는다(명세 "서버 경로 커넥터와 원천 폴더"의 경로 확인 항목). 링크를 따르지 않는 열기는 링크가 아닌 `..`을 막지 못하므로, 시험은 원천 폴더 밖에 둔 파일을 `../밖의파일` 같은 키로 읽으려 하면 `rejected`이고 내용이 나오지 않는 것을 본다. 역슬래시는 운영체제마다의 기대를 단언한다. 리눅스에서는 이름에 역슬래시가 든 파일(`annual\2024.pdf`)을 `list()`가 그 이름 그대로 키로 내고 `fetch`가 읽는다. Windows에서는 `a\..\..\밖의파일` 같은 키가 `rejected`이고 내용이 나오지 않는다.
- [x] 확인과 열기를 한 동작으로 한다(명세 "서버 경로 커넥터와 원천 폴더"의 확인과 열기 항목). 부모 폴더를 연 자리에서 시작해 토막마다 링크를 따르지 않는 열기(`O_NOFOLLOW`와 연 폴더 기준의 열기)로 내려가고, 마지막 토막은 막히지 않는 열기(`O_NONBLOCK`)를 더해 연 뒤 그 연 파일로 보통 파일인지 확인하고 읽는다. 목록도 연 폴더에서 그 폴더의 항목을 읽으며 내려간다. 토막이 링크로 바뀌어 열기가 실패하면 확인에 걸린 것과 똑같이 다룬다. 이 열기가 없는 운영체제(개발 기계의 Windows)에서는 확인한 뒤 여는 길로 돈다. 근거는 프로브 `.scratch/source-sync/probes/fifo-open/`의 A, B, C다.
- [x] `list()`는 원천 폴더 아래를 끝까지 걸어 보통 파일을 모두 낸다. 키는 원천 폴더 기준의 상대 경로이고 토막을 `/`로 잇되 디스크에 있는 이름 그대로 정규화하지 않는다(ADR 0008). 크기를 함께 내고, 변경 확인값은 수정 시각(나노초 정수)과 크기를 쌍점으로 이은 글이다. 심볼릭 링크(파일이든 폴더든), 보통 파일이 아닌 것, 이름을 UTF-8로 읽을 수 없는 파일은 내지 않고, 목록을 끝까지 낸 뒤 종류별 개수를 로그 한 줄로 남긴다(명세 "로그"). 걷는 도중에 하위 폴더를 읽지 못하면 그 폴더를 빼고 계속하지 않고 `unreadable`로 목록 전체를 실패시킨다.
- [x] `fetch(key)`는 바이트, 키의 확장자로 정한 MIME, 파일의 수정 시각인 갱신 시각, 빈 메타데이터를 낸다. `RAG_MAX_UPLOAD_MB`를 넘는 파일은 끝까지 읽지 않고 `too_large`로 알린다. `check()`는 원천 폴더를 읽을 수 있는지 보고, 안 되면 사유에 맞는 예외(`unreadable`, `rejected`)를 올린다.
- [x] 커넥터가 파일 시스템을 부르는 일은 호출마다 새로 띄운 daemon 스레드(프로세스가 내려가는 것을 붙잡지 않는 스레드) 하나에서 한다. 이벤트 루프의 기본 스레드 풀도, 원천끼리 나눠 쓰는 풀도 쓰지 않고, 같은 설정의 호출끼리도 스레드를 나눠 쓰지 않는다(명세 "동기화의 차례"의 스레드 항목). 기본 풀을 쓰지 않는 것과 호출 하나에 스레드를 하나만 쓰는 것을 이 커넥터의 시험이 본다.
- [x] 시험은 실제 파일 시스템으로 한다(명세 "Testing Decisions"의 서버 경로 커넥터 항목). 심볼릭 링크 넷(파일, 하위 폴더, 원천 폴더 자체, 부모 폴더에서 원천 폴더까지의 중간 토막)은 실제로 만든다(`tests/test_ingest_command.py`의 선례). 한글 이름의 두 꼴(합쳐 적은 것과 풀어 적은 것)이 디스크 이름 그대로 키가 되는 것, 상한을 넘는 파일의 `too_large`, 읽을 수 없는 하위 폴더가 목록 전체를 `unreadable`로 실패시키는 것을 본다. 읽기 오류는 권한 비트로 만들지 않고 폴더를 여는 호출이 오류를 내게 바꿔 끼운다.
- [x] 확인과 열기가 한 동작인지는 링크로 바꿔치는 경쟁으로 본다. 다른 스레드가 원천 폴더 안의 하위 폴더 하나를 진짜 폴더와 부모 폴더 밖을 가리키는 링크로 번갈아 바꾸는 동안 그 아래 파일을 되풀이해 읽고, 읽은 내용에 밖에 둔 파일의 내용이 한 번도 없는지 본다. 리눅스에서는 밖의 내용이 한 번도 나오지 않아야 하고, 목록을 받은 뒤 FIFO(이름이 붙은 파이프. 쓰는 쪽이 없으면 보통의 여는 호출이 돌아오지 않는다)로 바뀐 키의 `fetch`가 기다리지 않고 거절되어야 한다. 그 열기가 없는 운영체제에서는 커넥터가 확인한 뒤 여는 길로 돈다는 것을 단언한다. 건너뛰지 않고 운영체제마다의 기대를 단언한다(원칙 I, 명세 "Testing Decisions"의 마지막 항목).
- [x] 검사 넷이 초록이다. 원칙 II는 `tools/check_type_escapes.py`가 판정한다.

## 구현 메모 (06이 읽는다)

- **쌍점(`:`).** 명세는 역슬래시만 운영체제에 따라 거절하라고 적었다. 구현은 쌍점도 같은 때(Windows)에 거절한다. `C:밖의파일.pdf`처럼 드라이브 이름이 앞에 붙은 경로는 부모 폴더 밖을 가리킬 수 있기 때문이다. 리눅스에서는 쌍점이 보통 글자라 받는다. 명세의 한 줄을 이에 맞출지는 06이 폴더 확인을 짓는 자리에서 정한다. **06이 정했다:** 폴더 확인(`locate_folder`)이 커넥터와 같은 `_folder_segments`로 설정을 읽으므로 폴더 확인도 Windows에서 쌍점이 든 폴더를 `invalid_config`(422)로 거절한다. 명세(143행)의 거절 목록에는 쌍점을 아직 더하지 않았다(명세는 to-spec의 몫이라 06의 일지에 맞출 것으로 남겼다).
- **설정 `folder`의 빈 토막.** 끝의 `/` 하나는 떼고, `a//`처럼 그 뒤에도 빈 토막이 남는 값과 `a//b`는 `invalid_config`다. 명세는 "끝의 `/`는 뗀다"만 적었고 겹친 `/`는 정하지 않았다.
- **UTF-8로 쓸 수 없는 글자.** `folder`와 `fetch`의 키에 UTF-8로 쓸 수 없는 글자(짝이 없는 대리 문자)가 들면 각각 `invalid_config`와 `rejected`다. `list()`가 이런 이름을 키로 내지 않으므로 키가 될 수 없는 값이다.
- **06이 쓸 것.** 원천을 만들 때의 폴더 확인(인터페이스 밖)은 `server_path.py`의 `_descend`(부모 폴더를 연 자리에서 토막마다 링크를 따르지 않고 내려간다)를 다시 쓰면 같은 규칙으로 확인과 열기가 한 동작이 된다. 지금은 모듈 안의 비공개 이름이라, 공개 이름으로 올릴지 같은 규칙의 함수를 따로 둘지는 06이 정한다. **06이 정했다:** `_descend`는 올리지 않고 같은 모듈에 폴더 확인 전용 `_enter_folder`를 두었다. 폴더 확인은 적은 글자 그대로 찾고 없으면 NFC로 맞춰 찾는데, 커넥터의 `_descend`는 토막을 글자 그대로만 연다. 부모 폴더 열기(`_open_parent`), 폴더 모양(`_Directory`), 설정 읽기(`_folder_segments`)는 같은 모듈이라 그대로 쓴다.
- **상한 값은 환경 변수에서만 읽는다.** `RAG_MAX_UPLOAD_MB`는 `os.environ`에서만 읽고 `.env` 파일은 읽지 않는다. 만드는 함수가 파일 시스템을 부르지 않아야 하기 때문이다. 서버와 작업자가 `.env`로 상한을 정하는 설치에서는 이 커넥터가 기본값 100을 쓸 수 있다.
