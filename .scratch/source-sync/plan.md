# source-sync: 원천(업로드, 서버 경로, 수집 API)과 동기화. 원천에서 더하고 고치고 지운 문서가 다음 동기화 뒤 검색에 반영된다
**슬라이스:** 2
**Blocked by:** core, release-image
**설계:** ADR 0021, 0022, 0023. 일지 `docs/journal/2026-11-20-2034-source-sync-design.md`, `docs/journal/2026-11-21-2139-source-sync-stuck-calls-design.md`

설계(2026-11-20)가 정한 것은 ADR 둘이 원천이다. ADR 0021이 원천의 두 갈래(밀어 넣는 원천, 가져오는 원천)와 문서의 주인, 서버 경로 원천의 폴더를 정하고, ADR 0022가 동기화의 일정과 실행, 건너뜀, 동기화 기록, 정리 작업을 정한다. 명세는 두 ADR과 그 끝의 "명세가 재거나 정하는 것"을 입력으로 읽고, 이 계획에는 범위가 어떻게 달라졌는지만 적는다. 이 기능이 받지 않고 다른 기능에 넘긴 것은 셋이다. 변환 인터페이스와 변환 단계를 끼우는 일(core 명세가 이 기능에 넘겼던 것이다), 그리고 연결 정보의 암호화 보관은 db-source로 넘겼고, 수집 전용 토큰은 admin으로 넘겼다. 범위에서 뺀 것은 원천마다의 실행 시간대와 동시 처리 수다. 그래서 수락의 "수집 API로 보낸 문서가 바로 검색되고"는 대기열에 밀린 작업이 없을 때의 이야기로 읽는다(ADR 0022 "부하를 조절하는 장치는 두지 않는다").

설계의 셀프 리뷰(2026-11-20, 일지 `docs/journal/2026-11-20-2034-source-sync-design.md`의 "셀프 리뷰")가 명세에 넘긴 물음: ADR이 방향을 정하지 않아 명세가 정할 세부다. `default`와 `upload` 원천을 지울 수 있는지와, 지운 뒤 `migrate`가 다시 만드는지(원천의 이름은 겹칠 수 없어서, 보관 기간 동안 `migrate`가 조용히 지나가면 원천 이름을 적지 않은 수집 요청이 지운 원천으로 간다). 수집 API의 삭제 요청에도 원천 이름 칸을 두는지. 정리 작업과 되살림이 같은 문서에서 겹칠 때의 순서. 정리 작업이 `/sources`의 파일(서버 경로 원천의 원본)을 지우지 않게 하는 것. 일시 중지한 순간에 대기 중이거나 돌고 있던 동기화, 일시 중지한 원천의 "지금 동기화", 다시 시작한 직후의 놓친 일정, 일정을 고친 직후의 다음 실행 시각. 빈 목록 판정이 수집 정책을 적용하기 전인지 뒤인지. 수집 정책을 커넥터와 서버 가운데 어디서 적용하는지(커넥터 인터페이스 1.0에 닿는다). 원천 삭제를 작업 단위 하나로 할지 대기열의 작업으로 할지(문서가 수만 건일 때). 겹치는 폴더를 가리키는 원천 둘과, `ingest <경로>`로 `default`에 넣어 둔 폴더를 서버 경로 원천으로 옮길 때 생기는 중복. `.env`에 폴더를 적지 않았을 때의 `/sources`. 설치처가 만든 커넥터의 설정에 든 비밀이 관리 API의 원천 보기, 진단 묶음, 백업에 그대로 남지 않게 하는 것(원칙 V). 초 칸이 든 여섯 칸짜리 일정 표현식을 거부하는 것(일정을 계산하는 라이브러리가 여섯 칸도 받는다는 것은 리뷰어의 웹 요약이고 원문을 대 보지 않았다).

PR 직전 리뷰(2026-11-20, 같은 일지의 "PR 직전 리뷰")가 명세에 넘긴 것: 다섯 가지다. 서버 경로 원천의 폴더로 받는 값의 모양(하위 폴더를 몇 단계까지 받는지, 빈 값이나 `.`처럼 `/sources` 자체를 가리키는 값을 받는지. `/sources` 밖을 가리키는 값과 심볼릭 링크를 받지 않는 것은 ADR 0021이 정했다). 같은 폴더를 글자만 다르게 적은 원천 둘(이름의 대소문자가 다르거나 한글을 합쳐 적은 것과 풀어 적은 것)을 위 문단의 겹치는 폴더로 볼지. 지운 가져오는 원천을 되살렸는데 그사이 폴더가 사라졌거나 비어 있을 때(되살린 뒤의 동기화가 ADR 0022의 "목록이 비면 지우지 않는다"에 걸려 실패로 남고, 이미 없는 파일의 문서가 검색에 남는다. ADR 0022는 "지금 동기화"의 "빈 목록도 반영"을 운영자가 정말로 폴더를 비운 경우의 길로만 적었고, 폴더가 아예 없을 때에도 그 옵션이 통하는지는 정하지 않았다. 명세가 두 경우를 갈라 정한다. 폴더가 없을 때에도 통하게 할지, 통하지 않게 한다면 그때 운영자가 할 일은 무엇인지, 그리고 되살리기의 응답이나 설치 안내가 그 길을 알려 주는지다. 통하게 정하면 ADR 0022의 이력에 그 경우를 적는다). 동기화 기록의 실패 사유와 연결 확인의 응답에 커넥터가 낸 예외의 글이 그대로 실리지 않게 하는 것(원칙 V. 설치처가 만든 커넥터의 예외 글에는 토큰이나 연결 문자열이 섞일 수 있다. 지금 작업자가 알림 듣기의 실패를 로그에 남길 때도 예외의 글은 싣지 않는다고 `src/rag_engine/worker/service.py`의 `_log_listener_failure` 독스트링이 적는다). 원천을 지우는 순간 돌고 있던 색인 작업이 지워진 문서의 조각을 다시 쓰지 못하게 하는 것(문서 하나를 지우는 코드는 문서의 세대(`generation`. 색인 작업이 문서를 잡을 때와 문서를 지울 때 올리는 번호)를 올리고, 색인 작업은 조각을 쓰기 직전에 자기가 잡은 세대와 문서의 세대가 다르면 쓰지 않는다. `src/rag_engine/app/delete_document.py`와 `src/rag_engine/app/index_document.py`를 이 세션이 읽었다. 원천 단위의 삭제가 세대를 올리지 않으면 이 장치가 서지 않는다. ADR 0021이 명세에 넘긴 "원천을 지우는 순간 대기 중이거나 돌고 있던 그 원천의 작업을 거두는 방법"에 드는 조건이다).

PR 봇 리뷰(2026-11-21, 같은 일지의 "PR 봇 리뷰")가 명세에 넘긴 것: 하나다. 변경 확인값(파일의 수정 시각과 크기)이 같아도 원천의 파일을 모두 다시 읽어 내용을 대 보게 하는 길(예: "지금 동기화"에 켜는 옵션)을 둘지다. ADR 0022는 내용이 바뀌었는데 두 값이 같은 파일을 알아보지 못하는 것을 치르는 값으로 적었고, 지금 운영자가 쓸 길은 그 파일의 수정 시각을 바꾸는 것뿐이다. ADR 0022 Consequences가 조건으로 적은 두 길(색인이 실패로 끝난 문서를 파일이 바뀌지 않아도 다시 시도하는 길, 건너뜀으로 남은 문서를 파서가 바뀐 뒤에 다시 보는 길)도 변경 확인값이 같은 파일을 다시 읽어야 하는 일이라, 세 가지를 한 장치로 풀 수 있는지 함께 본다.

core가 지은 수집 파이프라인과 수집 API 위에 서버 경로 커넥터와 업로드 원천, 커넥터의 인터페이스를 짓고(업로드와 수집 API는 커넥터가 아니고, 그 둘로 들어온 문서는 밀어 넣는 원천에 속한다. ADR 0008, 0021), 킥오프 입력 4절의 동기화 규칙 가운데 설계가 남긴 것(손으로 시작하기와 일정에 따른 실행, 증분, 삭제 반영, 겹침 방지, 재시도, 동기화 기록, 수집 정책, 메타데이터 대응)을 넣는다. 메타데이터 대응은 서버 경로 원천의 갱신일을 파일의 수정 시각으로 채우는 것까지가 설계에서 정해졌고, 그 밖의 값(제목, 작성 부서, 시행일)을 어디서 가져올지는 명세가 정한다. 수집 API의 버전(경로의 `v1`)은 core가 붙였다(core 명세 수집 API 절). 서버 경로 원천의 폴더는 읽기 전용 볼륨으로 붙이고, 그 설정을 단독 compose와 설치 안내에 더한다(release-image가 정한 버전 태그와 단독 compose의 규칙으로). 설계 인터뷰의 입력은 킥오프 입력 4절이다.

core 명세(`.scratch/core/spec.md`, 2026-11-10)가 넘긴 것: 커넥터와 변환 인터페이스의 메서드 모양과 수집 파이프라인에 변환 단계를 끼우는 일(core의 파이프라인은 변환 자리를 비워 둔다), 서버 경로 원천, 원천의 생성·수정·삭제 관리 API(core는 밀어 넣는 원천 `default` 하나와 수집 API·`ingest` 명령만 둔다), 보관 기간(`RAG_DELETED_RETENTION_DAYS`)이 지난 임시 삭제 문서의 정리 작업과 그 주기(core는 설정 이름과 삭제 기록 행의 모양만 정한다), 보관 중인 문서를 되살리는 관리 API(core는 같은 (원천, 키)가 다시 들어올 때의 되살림만 한다), 수집 요청이 지우지 못한 고아 원본 파일(작업 단위가 롤백된 뒤의 새 원본, 커밋 뒤에 지울 옛 원본과 문서 행이 가리키지 않는 새 원본)의 정리.

release-image 명세(`.scratch/release-image/spec.md`, 2026-11-18)가 넘긴 것: 서버 경로 원천의 폴더를 단독 compose의 서버와 작업자에 읽기 전용으로 붙이는 자리와 설치 안내의 절을 이 기능이 정한다. 단독 compose의 파일은 `deploy/standalone/` 아래에 있고, 그 아래를 고친 PR은 제품 변경이라 다음 릴리스에 실리며 단독 compose 시험을 지나야 한다. 운영자가 `.env`에 넣을 새 설정(원천 폴더의 호스트 경로 같은 것)은 `deploy/standalone/.env.example`에 주석 처리한 예시 줄로 더한다. 단독 compose의 볼륨을 바꾸는 PR의 제목에 느낌표를 붙일지는 ADR 0020의 기준으로 가른다. 쓰는 곳이 없어 release-image가 `.env.example`에 넣지 않은 `RAG_DELETED_RETENTION_DAYS`는 정리 작업을 짓는 이 기능이 넣는다.

명세(2026-11-21, `.scratch/source-sync/spec.md`. 일지 `docs/journal/2026-11-21-1358-source-sync-spec.md`)가 정한 것은 그 명세가 원천이고, 위 세 문단이 넘긴 물음의 답도 거기에 있다. 이 계획에는 범위가 어떻게 달라졌는지만 적는다. 설계와 달라진 것은 넷이고 ADR에 이력을 더했다. 원천을 지우는 요청은 지움 표시만 세우고 문서는 작업자가 50건씩 옮기며, 그동안 검색이 지운 원천의 조각을 결과에서 뺀다(ADR 0013 이력 2026-11-21). Docker의 전파 설정은 재 보니 나중에 붙인 공유 폴더를 보이게 했으나 compose에 넣지 않고, 설치 안내에 "서버와 작업자를 다시 띄운다"를 적는다(ADR 0021 이력 2026-11-21). "모두 다시 읽기"로 돌린 동기화는 변경 확인값이 같아도 파일을 받는다(ADR 0012 이력 2026-11-21). 포트 열에 `ConnectorRegistry`, `ScheduleCalculator`, `SyncRecordStore`가 든다(ADR 0007 이력 2026-11-21). 사용자가 고른 것은 셋이다. 시험은 core와 같은 방식으로 걸고, "지금 동기화"에 "모두 다시 읽기" 옵션을 두며, 전파 설정은 위와 같다. 다른 기능에 넘긴 것은 받는 기능의 기능 계획(admin, db-source, diag-bundle, backup-upgrade)에 적었다. 메타데이터 대응은 제목(파일 이름)과 갱신일(파일의 수정 시각)까지이고, 그 밖의 값은 db-source가 매핑으로 정한다.

끊긴 공유 폴더와 끝나지 않는 커넥터 호출의 설계(2026-11-21, ADR 0023. 일지 `docs/journal/2026-11-21-2139-source-sync-stuck-calls-design.md`)가 정한 것은 그 ADR과 명세가 원천이다. 명세가 정하지 않은 채 적어 두었던 셋(폴더를 정하는 요청이 멈출 때, 프로세스 전체의 상한, 목록 전체가 끝나는 조건)과, PR 봇 리뷰를 반영하며 승인 없이 더했던 돌아오지 않는 호출의 규칙 여섯을 사용자와 다시 봤다. 사용자가 고른 것은 넷이다. 규칙 여섯 가운데 원천마다 끝나지 않은 호출 수의 상한만 걷고 나머지를 둔다. 동기화는 작업 담당 기록의 기한을 늘릴 때마다 원천의 지움 표시를 봐서, 원천을 지우면 끝나지 않는 동기화가 멈춘다. 원천을 만들거나 폴더를 고치는 요청의 폴더 확인은 10초 뒤 422로 거절하고, 답하지 않는 다른 원천과는 저장해 둔 경로의 글자로 견준다. 이 결정을 ADR 하나로 남긴다. 그 뒤 셀프 리뷰와 SMB와 NFS 공유 폴더를 붙여 잰 프로브(`.scratch/source-sync/probes/stuck-mount/`)를 거쳐, 설치 안내에 적을 것 셋을 더 골랐다. 끝나지 않는 동기화를 멈추려고 지운 원천은 그 동기화의 기록이 닫힌 뒤에 되살린다는 차례, 끊긴 공유 폴더 때문에 원천이 계속 읽히지 않을 때 할 일의 차례(공유 폴더를 되살리고, 안 되면 서버와 작업자를 함께 다시 띄우고, 그 명령이 실패하면 공유 폴더를 되살린 뒤 다시 치거나 서버 기계를 다시 띄운다), SMB 공유 폴더를 `hard` 옵션 없이 붙인다는 것이다. 다른 기능에 넘긴 것은 넷이고 받는 기능의 기능 계획에 적었다. 동기화 한 번이 받는 목록 전체의 상한, 커넥터를 자식 프로세스에서 부르는 방식(한도를 넘긴 호출을 취소할지도 그때 함께 본다), 커넥터를 만드는 사람을 위한 안내에 적을 것은 db-source로, 도는 동기화를 취소하는 요청은 admin으로 넘겼다.

수락: 서버 경로의 파일을 더하고 고치고 지우면 다음 동기화 뒤 검색 결과가 따라 바뀌고(지운 문서의 조각이 나오지 않는다), 같은 원천의 동기화가 겹쳐 돌지 않으며, 수집 API로 보낸 문서가 바로 검색되고, 암호가 걸린 파일이 건너뜀으로 기록되는 테스트가 통과한다.
