GPU 이미지는 띄워 보기만 했다(2026-11-13, 손으로). 이 PC 의 GPU 는 `nvidia-smi` 가 NVIDIA GeForce GTX 1660 Ti(6144MiB), 드라이버 560.94 로 냈다. `ghcr.io/huggingface/text-embeddings-inference:turing-1.9.4` 를 `docker run --gpus all` 로 띄우면 `nvidia-container-cli` 가 `cuda>=12.9` 요구가 맞지 않는다며 드라이버를 올리라고 거부했다. `-e NVIDIA_DISABLE_REQUIRE=1` 로 그 검사를 끄면 뜨지만, 프로세스가 이미지의 `/usr/local/cuda-12.9/compat/libcuda.so.575.57.08` 을 올려(`/proc/1/maps` 를 읽었다) `CUDA_ERROR_NO_DEVICE` 를 내고 CPU 로 돌았다. `--tmpfs /usr/local/cuda-12.9/compat` 으로 그 폴더를 가리면 `Starting Bert model on Cuda` 까지 가고 `CUDA_ERROR_UNSUPPORTED_PTX_VERSION` 으로 끝났다(서버 로그 `tei-cpu/gpu_turing_start_server_log.txt`). 그래서 이 이미지는 드라이버 560.94 에서 돌지 않는 것으로 보고, GPU 의 처리량은 재지 못했다. 드라이버를 올린 뒤 리랭크 기록을 만드는 티켓이 잰다(명세의 "전체 게이트와 리랭커" 절). Git Bash 에서 컨테이너 안의 경로를 인자로 줄 때는 `MSYS_NO_PATHCONV=1` 이 있어야 경로가 Windows 경로로 바뀌지 않는다.

프로브가 아니라 손으로 본 것도 있다(2026-11-12, 이 워크트리의 `.venv`). `uv pip install --dry-run "anthropic>=2.8,<3"` 은 새로 설치할 패키지를 넷(anthropic 2.8.0, docstring-parser 0.18.0, jiter 0.19.0, sniffio 1.3.1)으로 냈다. `uv tree --no-dev --frozen` 의 출력에는 anyio 4.16.0, httpx2 2.16.0, opentelemetry-api 1.45.2, pydantic 2.14.3, typing-extensions 4.16.0 이 이미 있었다. 그래서 운영 의존성에 새로 드는 패키지는 그 넷으로 본다. 어댑터 프로브가 원칙 II(`Any`, `cast`, `type: ignore`, `pyright: ignore` 금지)를 지키는지는 `tools/check_type_escapes.py` 의 `escapes_in` 을 그 파일의 글에 불러 봤고 빈 목록이 나왔다. 명령은 저장소 루트에서 `uv run python -c "import sys; sys.path.insert(0, '.'); from pathlib import Path; from tools.check_type_escapes import escapes_in; print(escapes_in(Path(sys.argv[1]).read_text(encoding='utf-8')))" .scratch/search-eval/probes/llm-sdk/judge_adapter_types.py` 다. 어댑터 프로브에 쓴 임시 pyright 설정이 strict 로 도는지는, 타입 표기가 없는 함수 하나만 둔 대조 파일을 같은 설정과 같은 명령으로 돌려 봤고 오류 넷(`reportUnknownParameterType` 둘, `reportMissingParameterType`, `reportUnknownVariableType`)이 났다.

재지 않은 것. 실제 호출이 도는지는 재지 않았다. 호출에는 키와 비용이 들기 때문이고, 사용자가 비용을 승인한 뒤 첫 구현 티켓이 잰다(`docs/agents/issue-tracker.md` 의 프로브와 근거 절). 그래서 요청과 응답이 실제 API 에서 어댑터 프로브의 꼴대로 도는지는 아직 모른다.
