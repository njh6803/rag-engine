# 13: 첫 판정 실행과 사람 표본의 대조

**What to build:** 공공 문서 묶음의 빠른 실행에 대해 처음으로 `judge`를 돌려 판정 파일을 커밋하고, 판정의 정확도를 사람 표본과 맞춰 본다(ADR 0019 Consequences, 명세 "LLM 관련성 판정"). 그 뒤 CI와 로컬의 `run`이 키 없이 LLM 숫자를 낸다. 같은 자리에서 놓친 질의의 사람 판정 초벌을 쓰고 사용자의 확인을 받아, 색인 시점의 LLM 보강을 더할지 사용자가 정하게 한다(명세 "놓친 까닭"). 이 티켓에는 비용 승인과 사람의 가름을 기다리는 지점이 있다.

**Blocked by:** 06 (`inspect`와 `human_causes`), 10 (질문과 임베딩 기록), 11 (`baseline-fast.json`. 기대 근거를 고치면 함께 갱신한다), 12 (판정기)

**Status:** ready-for-agent

- [ ] `judge --through fused`를 `--yes` 없이 돌려 부를 건수와 비용의 어림을 사용자에게 보이고 **멈춘다**. 승인을 받은 뒤 `--yes`로 돌린다. 승인을 `## Comments`에 사용자의 글 그대로 적는다.
- [ ] `judgments.jsonl`을 커밋한다. 파일에 해시만 있고 글이 없는지 본다. `run`의 보고서에 `llm` 칸이 차는지 본다.
- [ ] 사람 표본: 판정된 쌍 가운데 관련 있음 20개와 관련 없음 20개를 뽑아 `inspect`로 글을 보이고, 사용자가 LLM의 판정을 보지 않은 채 같은 가름을 한다. 일치한 수를 프로브 README(`.scratch/search-eval/probes/`)에 적는다. 일치가 40개 가운데 32개에 못 미치면 지시문을 고칠지 사용자에게 묻는다(표본의 크기와 문턱은 어림이다).
- [ ] 걸린 비용과 시간을 프로브 README에 적는다. 배치 API를 쓸지는 이 비용을 본 뒤 정한다(명세의 `[거절]` 배치 API 항목).
- [ ] 빠진 정답 후보의 목록을 사용자에게 보이고, 사용자가 확인한 것만 기대 근거에 더한다. 기대 근거를 고치면 숫자의 앞뒤 차이를 보이고 승인을 받은 뒤 기준 보고서를 함께 갱신한다(명세 "CI 게이트와 기준 보고서").
- [ ] 놓친 까닭의 사람 판정(명세 "놓친 까닭"): 이 세션(Claude Code)이 공공 문서 묶음의 빠른 실행에서 놓친 질의마다 `inspect`로 글을 보고 `miss-review.jsonl`에 초벌을 `confirmed` 거짓으로 쓴다. 사용자에게 보이고 **멈춘다**. 사용자가 확인한 줄만 `confirmed`를 참으로 바꿔 커밋하고, `run`의 `human_causes`가 그 줄을 세는지 본다.
- [ ] 확인된 까닭 가운데 `no_context`의 비율을 사용자에게 보이고, 색인 시점의 LLM 보강을 더할지 사용자가 정하게 하고 **멈춘다**(명세 "놓친 까닭"의 사람 판정 항목). 답을 `## Comments`에 사용자의 글 그대로 적는다. 더하기로 하면 그 일을 어느 기능이 받을지 사용자와 정해 그 기능의 계획에 적는다(명세는 이 기능의 티켓으로 두지 않았다).
- [ ] 검사 넷이 초록이다.
