# 13: 첫 판정 실행과 사람 표본의 대조

**What to build:** 공공 문서 묶음의 빠른 실행에 대해 처음으로 `judge`를 돌려 판정 파일을 커밋하고, 판정의 정확도를 사람 표본과 맞춰 본다(ADR 0019 Consequences, 명세 "LLM 관련성 판정"). 그 뒤 CI와 로컬의 `run`이 키 없이 LLM 숫자를 낸다. 같은 자리에서 놓친 질의의 사람 판정 초벌을 쓰고 사용자의 확인을 받아, 색인 시점의 LLM 보강을 더할지 사용자가 정하게 한다(명세 "놓친 까닭"). 이 티켓에는 비용 승인과 사람의 가름을 기다리는 지점이 있다.

**Blocked by:** 06 (`inspect`와 `human_causes`), 10 (질문과 임베딩 기록), 11 (`baseline-fast.json`. 기대 근거를 고치면 함께 갱신한다), 12 (판정기)

- 2026-11-17 `run --through fused --records read`의 `llm` 칸이 찼다: 조합 3100, 판정 있는 조합 3095, 관련 있다고 본 비율 0.194, 기대 근거에 닿은 조각을 LLM도 관련 있다고 본 비율 0.994, 판정 없음의 비율 0.0016(5건), 빠진 정답 후보 270건. 판정 없음 5건의 까닭: `judge`는 `--records` 인자가 없어 `off`로 돈다(코드를 읽어 확인했다. `tools/search_eval.py`의 `judge` 인자와 `adapters/eval_assembly.py`의 `prepare_evaluation`의 기본값 `_RECORDS_OFF`). 그래서 질의 임베딩을 `compose.eval.yml`의 CPU TEI로 새로 계산했고, `run --records read`(CI와 같은 방식)는 GPU로 만든 기록을 읽어 상위 10개가 5개 조합에서 달랐다. 이 견줌은 커밋하지 않은 일회용 스크립트를 손으로 돌려 본 것이다(같은 데이터베이스에서 `off`로는 판정 없음 0건, `read`로는 5건. 스크립트는 스크래치패드에 있고 저장소에 없다). 5건의 식별자는 `human/priv-13`(정보공개법시행령.hwpx 4), `human/priv-21`(개인정보보호법.pdf 91), `human/cult-23`(통합문화이용권… .hwpx 290), `keyword/cult-03`(저작권법.pdf 29), `keyword/radi-15`(기술기준영향분석… .pdf 44)다. `judge`에 `--records`를 받게 하는 일은 이 티켓의 수용 기준 밖이다.
- 2026-11-17 사람 표본(수용 기준 셋째): 표본 40쌍(시드 13, 관련 있음 20과 관련 없음 20을 섞음, LLM의 판정을 숨김)을 만들어 사용자에게 보였다. 사용자가 문서 분야를 몰라 판단이 어렵다고 해 10쌍씩 채팅으로 바꿔 1~10번을 보였고, 사용자가 면제했다: "사람 평가는 넘어가자. 내가 답을 몰라." 답을 받은 쌍이 없어 일치 수를 세지 않았고 32/40 문턱의 판정과 지시문 수정 여부의 물음은 하지 않았다. 판정기의 정확도는 사람이 확인하지 않은 채로 남는다. 걸린 시간과 비용의 어림은 프로브 README의 행에 적었다. 비용의 26.85달러는 ADR 0019의 "3,000건 약 26달러"에 건수를 비례시킨 어림이라 새 정보가 아니고 실제 청구액은 보지 못했다. 이 실행이 배치 API 판단에 새로 준 값은 걸린 시간(31분 5초)뿐이다. 배치 API를 쓸지는 이 값을 본 사용자가 정한다.
- 2026-11-17 빠진 정답 후보 270건(다섯째)과 놓친 질의 25건의 사람 판정(여섯째)에 사용자가 `AskUserQuestion`의 선택지로 답했다. 글로 쓴 답이 아니라 고른 선택지다. 다섯째의 질문은 "'빠진 정답 후보 270건'(LLM은 관련 있다고 봤지만 기대 근거에 없는 조각)을 사용자가 확인해 기대 근거에 더하는 단계는 어떻게 할까요? 더하면 기준 보고서 갱신 승인도 필요합니다."였고, 사용자가 고른 선택지는 "면제 (Recommended)"(이 선택지를 권한 것은 이 세션이다)이며 설명은 "사람이 확인하지 못하는 후보는 기대 근거에 더하지 않습니다. 목록은 보고서의 llm 칸에 그대로 남고, 기준 보고서와 기대 근거는 바꾸지 않습니다."다. 여섯째의 선택지는 "면제"이며 설명은 "초벌도 확인도 하지 않습니다. human_causes는 0으로 남고, no_context 비율과 색인 시점 LLM 보강의 결정도 이 티켓에서 하지 않습니다."다. 그래서 기대 근거와 기준 보고서(`baseline-fast.json`)는 바꾸지 않았고 `miss-review.jsonl`은 만들지 않았다(`human_causes`는 모두 0이다). 일곱째(`no_context` 비율을 보고 색인 시점의 LLM 보강을 더할지 정하기)는 여섯째를 면제하며 사용자가 "이 티켓에서 하지 않습니다"를 골랐으므로 이 티켓에서 하지 않았다. `no_context` 비율을 내지 않았고, 색인 시점의 LLM 보강을 더할지는 정하지 않았다. 열린 채다. 빠른 실행에서 놓친 질의는 25건이고 모두 `lost_in_fusion`, 낱말 겹침이 0인 놓친 질의는 11건이다(`baseline-fast.json`의 `miss_counts`와 `run`의 보고서가 같다).
