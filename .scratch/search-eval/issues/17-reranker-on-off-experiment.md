# 17: 리랭커 켬·끔 실험과 리랭커의 기본을 정하는 결정

**What to build:** 리랭크 뒤 줄과 합친 뒤 줄의 차, 리랭크를 넣은 후보 수의 효과를 실험해, core 16이 잰 CPU 리랭커의 지연과 함께 사용자에게 보이고 사용자가 리랭커의 기본을 정하는 길을 고르게 한다(명세 "전체 게이트와 리랭커"의 리랭커의 CPU 속도와 기본의 결정 항목, 스토리 26). 이 티켓에는 사용자의 선택을 기다리는 지점이 있다.

**Blocked by:** 14 (리랭크 기록. 명세는 그 티켓 뒤를 요구한다)

**Status:** ready-for-agent

- [ ] 공공 문서 묶음의 전체 실행 보고서에서 리랭크 뒤 줄과 합친 뒤 줄의 차를 질의 목록마다 정리한다.
- [ ] 리랭크를 넣은 후보 수(예를 들어 20, 50, 100)를 바꾼 실험을 GPU로 돌린다. 실험 구성의 리랭크 점수는 커밋하지 않고, 보고서와 명령은 `.scratch/search-eval/probes/experiments/`에 둔다.
- [ ] 품질의 차와 core 16의 지연(`.scratch/core/probes/search-latency/probe_out.txt`. 리랭커를 켠 후보 50개의 검색 한 번에 130초 등)을 함께 사용자에게 보이고 **멈춘다**. 길은 리랭커를 끄는 기본, ONNX 리랭커나 GPU 이미지, 검색 시간 제한을 늘리는 것이다. 리랭커를 끄는 기본을 고르면 전체 게이트와 최소 점수를 어떻게 둘지를 같은 자리에서 함께 묻는다(ADR 0018과 0017의 전제가 달라진다).
- [ ] 고른 길과 사용자의 글을 `## Comments`에 적는다. 끄는 기본이면 이 기능에서 설정의 기본값과 core 명세를 고친다. 모델을 바꾸는 길이면 `config.json`과 리랭크 기록을 다시 만들고, `baseline-full.json`이 이미 있으면 그것도 이 브랜치의 수동 실행이 올린 보고서로 다시 만들어 숫자의 앞뒤 차이를 보이고 승인을 받는다(ADR 0018 이력 2026-11-13 "모델이 계산한 결과는 로컬에서 만든 추론 기록으로 커밋하고, CI는 그 기록을 읽는다", 16의 같은 항목. 기록의 해시가 바뀌면 `compare`가 승인 없이 지나지 않는다. PR #38 봇 첫 회차의 지적). 그 밖의 길은 받는 곳을 정해 그 기능의 계획에 적는다(명세 Out of Scope). 고른 길이 ADR 0010이나 core 명세의 기본 구성에 닿으면 ADR의 이력과 명세를 고친다.
- [ ] 검사 넷이 초록이다.
