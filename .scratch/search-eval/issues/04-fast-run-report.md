# 04: 빠른 실행: `run --through fused`가 단계별 줄이 든 보고서를 쓴다

**What to build:** 개발자가 색인한 묶음에 `run --through fused --out <폴더>`를 치면, 평가 유스케이스가 질의마다 실제 검색과 같은 준비(현재 판의 모델로 질의 임베딩, 같은 키워드 토크나이저, 설정의 후보 수)를 하고 `diagnose_candidates`를 `scan=CandidateScan.EXACT`로 한 번 불러 벡터만, 키워드만, 합친 뒤 세 단계의 순위를 만든다. 질의 목록과 단계마다 상위 1·3·5·10 적중률, MRR, 재현율, nDCG@10이 든 `report.json`과 `report.md`가 나온다(스토리 2, 3, 4, 5, 10, 11, 40). 채점, 지표, 보고서는 `app`의 유스케이스에 둔다(명세 "자리와 층"). 놓친 까닭의 자세한 칸(탈락 지점, 낱말 겹침, 유형 표지와 필터 줄)은 06, 추론 기록은 07, LLM 숫자는 12가 더한다. 이 티켓의 보고서는 그 칸을 빈 값으로 두거나 아직 싣지 않는다.

**Blocked by:** 01 (진단용 검색), 03 (`index`)

**Status:** ready-for-agent

- [ ] `run`은 `--through fused`와 `--through rerank` 가운데 하나를 반드시 받는다. 이 티켓은 `fused`를 구현하고 `rerank`는 05가 더한다. 빠지거나 둘 다 주면 종료 코드 2다.
- [ ] 단계의 순위(명세 "진단용 검색과 단계"): 벡터만은 `vector_rank` 순, 키워드만은 `keyword_rank` 순, 합친 뒤는 `fused_rank`가 후보 수 이하인 줄의 그 순위다. 후보 수는 `config.json`의 `search_candidates`다. 키워드 토큰이 빈 질의는 키워드만 단계에서 결과가 없는 것으로 센다.
- [ ] 질의를 임베딩하는 끝점은 판에 적힌 것이 아니라 `RAG_EVAL_EMBEDDING_URL`이다. 현재 판의 모델이나 차원이 `config.json`과 다르면 평가하지 않고 종료 코드 1이다. 검색 유스케이스의 시간 제한은 걸지 않는다.
- [ ] 글귀의 적중(명세 "적중의 단위"): 양쪽 글을 NFC로 정규화하고 공백류를 지운 뒤 조각 글(`text`. 절 경로 줄은 넣지 않는다)의 부분 문자열로 본다. 조각의 문서가 기대 근거의 문서(키)일 때만 닿는다. 쪽으로 적은 기대 근거의 적중은 06이 더한다.
- [ ] 지표의 정의(명세 "지표"): 적중률, MRR(상위 10 안의 첫 적중 순위의 역수), 재현율(상위 10이 닿은 기대 근거의 비율), nDCG@10(기대 근거 하나는 처음 닿은 순위에서 한 번만 이득 1, 이상적인 순위는 기대 근거의 수만큼, 1에서 자름)과 줄마다 nDCG가 잘린 질의의 수다. 질의 수가 0인 줄은 내지 않는다.
- [ ] `report.json`의 칸(명세 "보고서"): `format_version` `"1.0.0"`, `eval_set`(이름, 판, 내용 해시, 문서·질문·질의의 수), `config`, `index`(현재 판의 요소 넷과 조각 수), `stages`, `rows`, `meta`(실행 시각과 커밋). 받는 티켓이 정해진 칸(`by_tag`, `filtered`, `misses`, `miss_counts`, `human_causes`, `llm`, `score_distribution`, `records`)은 이 티켓에서 비우거나 빼고, 받는 티켓이 채운다. `report.md`는 같은 값을 표로 옮긴다. 보고서에는 질의의 글과 조각의 글이 없고 식별자(질의 목록 이름, 기대 근거의 `id`, 문서의 키, 조각의 `ordinal`)만 있다.
- [ ] 묶음의 내용 해시는 머리, 구성, 문서 목록, 기대 근거, 질의 목록 파일로 계산한다. 구성은 파일의 바이트가 아니라 `judge_model`과 `judge_prompt_version`을 뺀 칸을 정렬한 JSON으로 넣는다(명세 보고서 절의 `[사용자 선택]` 항목).
- [ ] `run`도 시작할 때 03의 판정(평가 전용 이름, 데이터베이스 이름, 이 묶음의 데이터베이스인지)을 지나야 돈다.
- [ ] 평가 도중 판이 바뀌면(`is_current`가 거짓) 평가를 오류로 끝내고 종료 코드 1이다. 질의 사이에 판을 바꿀 시험의 걸이를 이 티켓이 정한다. 유스케이스가 받는 포트의 가짜나 스텁의 응답 순번처럼 바깥에서 보이는 방법으로 정하고, 정한 방법을 티켓의 `## Comments`에 적는다(명세 "덮는 스토리와 판정").
- [ ] 표면 시험(명세 Testing Decisions): `index` 뒤 `run`이 질의 목록마다 단계별 줄을 낸다, `--through fused`의 보고서에 리랭크 뒤 줄이 없다, 글귀가 조각의 경계에서 갈리면 놓친 것으로 센다, 공백과 줄바꿈이 달라도 글귀가 닿는다, 다른 문서의 같은 글귀는 닿지 않는다, 조각 하나가 기대 근거 둘에 닿아 nDCG가 잘린 질의가 잘린 수에 세어진다, 보고서에 질의의 글과 조각의 글이 없다, `run`이 `RAG_EVAL_EMBEDDING_URL`로 질의를 임베딩한다(판에 적힌 끝점의 스텁에는 요청이 가지 않는다), 작업 폴더의 `.env`에 `RAG_PARSE_MAX_PAGES=1`이 있어도 보고서가 같다, 판이 바뀌면 1이다, 키워드 토큰이 빈 질의가 키워드만 단계에서 놓친 것으로 세어진다, `run`이 묶음 밖의 문서가 든 데이터베이스와 키는 묶음의 것인데 내용 해시가 다른 문서가 든 데이터베이스에서 아무것도 부르지 않고(임베딩 스텁의 요청 횟수가 0이다) 보고서를 쓰지 않으며 1을 낸다. 지표는 스텁의 결정적 벡터로 기대 근거의 순위를 정한 작은 묶음에서 손으로 계산한 값과 견준다.
- [ ] 검사 넷이 초록이다.
