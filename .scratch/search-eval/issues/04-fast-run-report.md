# 04: 빠른 실행: `run --through fused`가 단계별 줄이 든 보고서를 쓴다

**What to build:** 개발자가 색인한 묶음에 `run --through fused --out <폴더>`를 치면, 평가 유스케이스가 질의마다 실제 검색과 같은 준비(현재 판의 모델로 질의 임베딩, 같은 키워드 토크나이저, 설정의 후보 수)를 하고 `diagnose_candidates`를 `scan=CandidateScan.EXACT`로 한 번 불러 벡터만, 키워드만, 합친 뒤 세 단계의 순위를 만든다. 질의 목록과 단계마다 상위 1·3·5·10 적중률, MRR, 재현율, nDCG@10이 든 `report.json`과 `report.md`가 나온다(스토리 2, 3, 4, 5, 10, 11, 40). 채점, 지표, 보고서는 `app`의 유스케이스에 둔다(명세 "자리와 층"). 놓친 까닭의 자세한 칸(탈락 지점, 낱말 겹침, 유형 표지와 필터 줄)은 06, 추론 기록은 07, LLM 숫자는 12가 더한다. 이 티켓의 보고서는 그 칸을 빈 값으로 두거나 아직 싣지 않는다.

**Blocked by:** 01 (진단용 검색), 03 (`index`)

**Status:** done

- [x] `run`은 `--through fused`와 `--through rerank` 가운데 하나를 반드시 받는다. 이 티켓은 `fused`를 구현하고 `rerank`는 05가 더한다. 빠지거나 둘 다 주면 종료 코드 2다.
- [x] 단계의 순위(명세 "진단용 검색과 단계"): 벡터만은 `vector_rank` 순, 키워드만은 `keyword_rank` 순, 합친 뒤는 `fused_rank`가 후보 수 이하인 줄의 그 순위다. 후보 수는 `config.json`의 `search_candidates`다. 키워드 토큰이 빈 질의는 키워드만 단계에서 결과가 없는 것으로 센다.
- [x] 질의를 임베딩하는 끝점은 판에 적힌 것이 아니라 `RAG_EVAL_EMBEDDING_URL`이다. 현재 판의 모델이나 차원이 `config.json`과 다르면 평가하지 않고 종료 코드 1이다. 검색 유스케이스의 시간 제한은 걸지 않는다.
- [x] 글귀의 적중(명세 "적중의 단위"): 양쪽 글을 NFC로 정규화하고 공백류를 지운 뒤 조각 글(`text`. 절 경로 줄은 넣지 않는다)의 부분 문자열로 본다. 조각의 문서가 기대 근거의 문서(키)일 때만 닿는다. 쪽으로 적은 기대 근거의 적중은 06이 더한다.

- [x] `report.json`의 칸(명세 "보고서"): `format_version` `"1.0.0"`, `eval_set`(이름, 판, 내용 해시, 문서·질문·질의의 수), `config`, `index`(현재 판의 요소 넷과 조각 수), `stages`, `rows`, `meta`(실행 시각과 커밋). 받는 티켓이 정해진 칸(`by_tag`, `filtered`, `misses`, `miss_counts`, `human_causes`, `llm`, `score_distribution`, `records`)은 이 티켓에서 비우거나 빼고, 받는 티켓이 채운다. `report.md`는 같은 값을 표로 옮긴다. 보고서에는 질의의 글과 조각의 글이 없고 식별자(질의 목록 이름, 기대 근거의 `id`, 문서의 키, 조각의 `ordinal`)만 있다.
- [x] 묶음의 내용 해시는 머리, 구성, 문서 목록, 기대 근거, 질의 목록 파일로 계산한다. 구성은 파일의 바이트가 아니라 `judge_model`과 `judge_prompt_version`을 뺀 칸을 정렬한 JSON으로 넣는다(명세 보고서 절의 `[사용자 선택]` 항목).

## Comments

- 판 전환 시험의 걸이는 TEI 스텁의 응답 순번이다. `TeiStub.on_embeddings`가 `/v1/embeddings` 요청을 받을 때마다 지금까지 받은 임베딩 요청의 수를 넘겨 부른다. 시험은 `run`이 둘째 질의를 임베딩하는 요청에서 `knowledge_bases.current_index_version_id`를 NULL로 갱신해, 그 질의의 진단용 검색이 `is_current` 거짓을 읽게 한다. 첫 질의는 이미 평가를 마친 뒤이고 보고서는 쓰지 않으며 종료 코드는 1이다.
- `run`은 `app/eval_run.py`의 `run_fast_evaluation`이 단계의 순위를 만들고, 지표는 `app/eval_metrics.py`, 보고서의 모양은 `app/eval_report.py`가 맡는다. 어댑터의 `eval_run.run_fast`는 환경 읽기, 묶음 판정, 03의 `check_database`(스키마가 없는 데이터베이스는 별도로 거부), 평가, 파일 쓰기를 잇는다. 보고서는 평가가 끝난 뒤에만 `--out`에 쓰므로 평가나 판정이 실패한 실행은 폴더를 만들지 않는다(파일 쓰기가 도중에 실패하면 폴더와 `report.json`이 남을 수 있고 종료 코드는 1이다).
- 질의 하나의 진단용 검색은 `CandidateScan.EXACT`로 한 번이다. 키워드 토큰이 빈 질의는 키워드만 단계를 빈 순위로 둔다. 기대 근거 하나가 닿은 자리를 `reach`(순위별 집합)로 들고 있어 지표는 순수 함수다.
- 쪽으로 적은 기대 근거는 이 티켓에서 닿지 않는 것으로 센다(06이 더한다). `--through rerank`는 종료 코드 1과 "티켓 05가 더한다"를 알린다.
- 내용 해시는 `adapters/eval_bundle_hash.py`다. 입력마다 `이름\0길이\0바이트`를 sha256에 넣어 이웃한 입력의 경계가 섞이지 않는다.
- 변이 표 `.scratch/search-eval/probes/eval_run_mutations.toml`의 열한 변이가 모두 기대대로 빨갛다. 시험이 적중률의 경계(순위 1에서 `<`와 `<=`), 이득 중복, 1에서 자르기, 이상적 순위의 열 제한, 판 전환 거부, 문서 일치, 환경 끝점, 스키마 없는 데이터베이스의 거부, 합친 뒤 단계가 후보 수 밖의 줄을 빼는 것, 내용 해시가 판정 칸을 빼고 구성을 정규화하는 것을 겨눈다. 순위 5와 10의 적중률 경계와 `report.md`의 소수 자릿수는 겨누지 않는다. 변이 파일의 `sort_keys=False` 변이는 `config_values`가 칸 순서를 고정해 내므로 보고서에 차이가 나지 않는 동등 변이라 구성의 바이트를 그대로 넣는 변이로 바꿨다.
- 진단용 검색은 합집합을 자르지 않는다(후보 수의 두 배까지 돌려준다). 합친 뒤 단계가 후보 수에서 자르는 곳은 `stage_ranking` 하나이고 `tests/app/test_eval_run.py`가 그 걸러내기를 겨눈다. 시험 구성은 조각이 둘이라 `run`의 표면 시험은 이 걸러내기를 닿지 않는다.
- 03의 Minor 셋((오류, 경고) 쌍의 타입화, 읽기 트랜잭션 안의 토큰 세기, `index_bundle`의 모양)은 이 티켓이 `check_indexed`의 반환을 넓히지 않아 손대지 않았다. 03이 "04가 쌍을 타입으로 모은다"고 적은 일은 06의 `## Comments`로 넘겼다.
- 셀프 리뷰에서 남긴 Minor: `TeiEmbedderPool`을 짓는 람다와 `replace(version, embedding_endpoint=…)`가 `eval_run._evaluate`와 `eval_database.check_indexed`에 되풀이된다. `eval_bundle_hash`가 머리의 두 칸을 `eval_set_reader`와 따로 선언한다(엄격함도 다르다). `run_fast`는 실패 분기마다 출력과 종료 코드를 되풀이한다. 모두 동작을 바꾸지 않는 모양 문제이고, 평가 끝점을 쓰는 셋째 자리(05의 리랭크 호출)가 생길 때 함께 모은다.
