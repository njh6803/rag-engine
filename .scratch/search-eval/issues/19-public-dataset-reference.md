# 19: 공개 데이터셋의 참고 측정

**What to build:** 공개 데이터셋(allganize)을 이 명세의 묶음 형식으로 바꿔 로컬에서 평가를 돌리고, 그 데이터셋의 질문(스토리 19가 말하는 사람이 만든 질문)으로 한 번 더 확인한 숫자를 프로브로 남긴다(스토리 19, ADR 0018). 따로 준비할 질문은 없다. PDF와 질문은 커밋하지 않는다.

**Blocked by:** 06 (쪽으로 적은 기대 근거와 `figure` 유형), 07 (`--records off`)

**Status:** done

- [x] 데이터셋의 이름과 이용 조건을 원문(데이터셋의 카드와 라이선스 파일)으로 확인하고 프로브 README에 확인한 자리와 날짜를 적는다. 명세 세션은 원문으로 확인하지 않았다. 조건이 로컬 측정과 숫자의 커밋을 허락하지 않으면 멈춰 사용자에게 묻는다.
- [x] 데이터셋을 내려받아 묶음 형식으로 바꾸는 스크립트를 `.scratch/search-eval/probes/`에 둔다. 기대 근거는 문서와 쪽 번호(`kind: page`)로 적고, 그림 유형 문항은 `figure`로 표시한다. 내려받은 파일은 저장소 밖의 폴더에 두고 커밋하지 않는다(`.gitignore`로 막히는지 본다).
- [x] 바꾼 묶음이 커밋하는 공공 문서 묶음의 규모에서 온 규칙(문서 파일의 합 30MB 이하)에 걸리면 **멈춰**, 그 규칙을 커밋하지 않는 참고 묶음에도 걸지 사용자에게 묻는다(명세는 정하지 않았다). 답에 따라 `validate`를 고치거나 묶음을 줄인다.
- [x] 바꾼 묶음이 `validate`를 지나고, `rag_eval` 머리의 새 데이터베이스에 `index`와 `run --through fused --records off`가 돈다. 리랭크 기록이 없으므로 전체 실행은 리랭커 끝점이 있을 때만 돌린다.
- [x] 저장소에는 스크립트와 보고서의 숫자(`report.json`과 `report.md`. 글이 없다)만 커밋하고, 돌린 명령과 장치, 걸린 시간을 프로브 README 표에 적는다.
- [x] 검사 넷이 초록이다.

## Comments

- 2026-11-15, 이용 조건. 데이터셋 카드와 API 응답을 `curl`로 받아 읽었다(원문, 해시, 읽은 줄은 프로브 `allganize/README.md`). 라이선스는 `mit`이고 라이선스 파일이 따로 없으며 카드 본문에 제한 문장이 없다. 질문과 정답은 커밋하지 않고 숫자와 식별자만 커밋하므로 멈추지 않았다. PDF는 데이터셋에 없고 출처 기관의 주소만 있다. 그 조건은 확인하지 않았고 PDF는 저장소 밖(`C:\project\eval-data-allganize\`)에만 둬서 `.gitignore`로 막을 일이 없다.
- 용량 규칙에서 멈춰 사용자에게 물었다. 직접 받은 PDF 21개의 합이 41.5MB(십진, 약 39.6MiB)였고 상한은 30MiB(31,457,280바이트)였다. 사용자가 "참고 묶음에는 걸지 않는다"를 골랐다. 그래서 `eval-set.json`의 선택 칸 `local_only`를 더했다(참이면 `check_bundle_files`가 합 상한만 보지 않고 해시와 경로와 목록 판정은 그대로다. 도메인에는 열거형 `BundleScope`로 두었다). 시험을 먼저 쓰고 빨강을 본 뒤 구현했고, 해시와 목록 판정이 `local_only`에도 남는 시험, 커밋하는 공공 문서 묶음이 이 칸을 켜지 않는 시험, 변이 표의 변이 둘을 더했다. 명세에 `[사용자 선택]` 항목과 `validate` 절의 예외를 적었다. 묶음의 판은 올리지 않았다(칸을 더한 것).
- 데이터셋은 PDF를 싣지 않아 사용자가 "너가 받아줘"라고 해서 이 세션이 받았다. 직접 주소 21개는 `allganize_bundle.py fetch`, 게시판 페이지 21개는 `fetch_landing.py`(쪽 수가 같은 파일만 둔다)로 받아 64개 중 42개를 얻었다. 받지 못한 22개와 까닭은 프로브 README에 있다.
- 셀프 리뷰가 게시판에서 받은 문서의 신뢰를 의심해 정답 낱말이 PDF에 드는지 대 보았다(`verify_documents.py`). 5번은 6쪽이라는 쪽 수만 같고 다른 날의 주택시장 보도자료였다. 그 문서를 `--exclude 5`로 빼고 데이터베이스를 새로 만들어 처음부터 다시 색인하고 돌렸다. 22번과 28번은 후보였으나 맞는 문서다(까닭은 프로브 README). 쪽 수를 맞추는 것으로는 그 문서임을 보장하지 못한다.
- 티켓 14 세션의 GPU TEI가 떠 있어(임베딩 18083, 리랭커 18084) 사용자에게 순서를 물었고 "14의 임베딩 끝점을 같이 쓴다"가 답이었다. 이 세션은 새 TEI 컨테이너를 띄우지 않았고 PostgreSQL만 따로 띄웠다(`rag-eval-19-postgres`, 55439). 리랭커 끝점은 그 세션의 작업을 늦출까 봐 부르지 않아 전체 실행은 하지 않았다.
- 결과. 문서 41개, 질문 174개. `index --records off`가 2,074초에, `run --through fused --records off`가 62초에 끝났다. fused @5 0.770, @10 0.822, MRR 0.679이다. 숫자는 프로브 `allganize/report.json`·`report.md`에 있다. 쪽 단위 적중이라 공공 문서 묶음의 글귀 단위 숫자와 견줄 수 없다. 놓친 금융 질의 16개는 모두 `figure`(3·4번 문서의 그림 질문)이고 글층에 닿을 글이 없는 질문이다.
