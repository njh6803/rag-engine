# 16: 리랭커 없는 설정 실험: 조각 크기·겹침과 후보 수의 기본값

**What to build:** 리랭커 없이 할 수 있는 설정 실험을 로컬에서 돌려, 조각 크기와 겹침, 후보 수의 기본값을 바꿀지 사용자가 숫자로 정하게 한다(스토리 18, 26). 실험은 묶음의 `config.json`을 고치지 않고 `--config`로 준 다른 구성 파일과 `--records off`로 돌리고, 결과는 프로브로 커밋한다(명세 "설정 실험과 참고 측정"). 이 티켓에는 기본값의 승인을 기다리는 지점이 있다.

**Blocked by:** 06 (`--config`와 나눠 본 숫자), 11 (첫 기준 보고서. 기본 구성의 값을 대 본다)

**Status:** ready-for-agent

- [ ] 구성: 조각 상한과 겹침 256·32, 512·64(기본), 512·128, 1024·128의 넷, 기본 청킹에서 후보 수 20, 50(기본), 100의 셋이다. 구성마다 `rag_eval` 머리의 새 데이터베이스에 색인해 빠른 실행의 보고서를 낸다. 조각 크기를 바꾼 구성의 임베딩은 로컬에서 새로 계산하고 커밋하지 않는다.
- [ ] 보고서, 구성 파일, 돌린 명령, 장치와 걸린 시간을 `.scratch/search-eval/probes/experiments/`에 두고 프로브 README 표에 행을 더한다.
- [ ] 판단용 숫자도 함께 정리한다. 키워드만 줄(`ts_rank`에 IDF가 없다는 판단과 토큰을 OR로 잇는 동작. 스토리 10), 필터 질의의 적중률과 HNSW 계획의 벡터 후보가 모자란 질의의 비율(좁은 필터의 정확 스캔 분기. 스토리 9)이다. 이 숫자로 무엇을 고칠지는 이 티켓에서 정하지 않는다(명세 Out of Scope).
- [ ] 구성마다의 숫자를 한 표로 사용자에게 보이고 **멈춘다**. 사용자가 기본값을 바꾸기로 승인하면 이 PR에서 설정의 기본값, core 명세의 설정 절, 묶음의 `config.json`, 추론 기록, `baseline-fast.json`을 함께 고치고, 리랭크 기록이나 `baseline-full.json`이 이미 있으면 그것도 다시 만들어 승인을 받는다(명세 "설정 실험과 참고 측정", "CI 게이트와 기준 보고서"). 승인과 고른 값을 `## Comments`에 사용자의 글 그대로 적는다. 바꾸지 않기로 하면 그 판단만 적는다.
- [ ] 검사 넷이 초록이다.
