# 18: 최소 점수: 리랭크 점수의 분포를 보이고 구현을 정한다

**What to build:** 공공 문서 묶음의 전체 실행 보고서의 `score_distribution`을 사용자에게 보이고, 사용자가 `search`의 `min_score`를 구현할지 정한다(스토리 27, ADR 0017). 승인되면 ADR 0017에 측정의 요약과 승인을 이력으로 더하고 같은 PR에서 최소 점수의 구현 티켓을 쓴다. 승인 전에는 구현 티켓이 놓이지 않는다(명세 "최소 점수"). 이 티켓에는 사용자의 판정을 기다리는 지점이 있다.

**Blocked by:** 14 (리랭크 기록)

**Status:** done

- [x] 리랭크 기록으로 `run --through rerank`를 돌려 `score_distribution`(닿은 조각과 그렇지 않은 조각의 구간별 수, 문턱별 상위 5·10 적중률, 결과가 비는 질의의 비율, 남는 조각 수의 평균)을 표로 사용자에게 보이고 **멈춘다**.
- [x] 승인되면 `docs/adr/0017-…`에 이력(측정의 요약과 승인, 사용자의 글)을 더한다. ADR 이력을 쓰기 전에 `domain-modeling` 스킬을 부른다(`.claude/rules/adr.md`). 같은 PR에서 다음 번호의 구현 티켓을 `.scratch/search-eval/issues/`에 to-tickets의 형식으로 쓴다. 그 티켓은 명세 최소 점수 절의 구현 모양(리랭크 뒤·`top_k` 앞에서 거르기, 지식베이스의 기본값보다 요청 인자가 이기는 것, 범위 밖 값의 `invalid_argument`, 숫자가 아닌 값을 MCP SDK의 입력 검증이 기존 인자의 타입 오류와 같은 모양으로 거부하는 것, 리랭커 없는 지식베이스의 `invalid_argument`, 빈 결과, 지식베이스 행의 널 허용 칸과 `RAG_DEFAULT_MIN_SCORE`, `SCHEMA_VERSION`을 올리지 않는 마이그레이션, 리랭커가 빈 채 기본값이 있으면 `migrate` 거부, 그런 행에서 `search_unavailable`)과 스토리 34~38, 계약 시험(inputSchema에 `min_score`, 결과의 `format_version` `1.1.0`)을 수용 기준으로 든다. 그 티켓은 원칙 VII의 판을 올리는 계약 변경이지만 기능의 첫 티켓이 아니다(ADR 0017이 둔 예외).
- [x] 두 분포가 한 문턱으로 잘 갈리지 않으면 그렇다는 것을 표와 함께 보이고 다시 묻는다(ADR 0017). 구현할지는 사용자의 답이 정한다. 사용자가 구현하지 않기로 하면 ADR 0017 이력에 그 결과와 사용자의 판정만 적고 구현 티켓은 쓰지 않는다(분리와 승인의 우선은 PR #38 봇 첫 회차의 지적으로 정했다).
- [x] `uv run python tools/plan_table.py`로 전체 계획을 다시 만든다.
- [x] 검사 넷이 초록이다.

## Comments

- 2026-11-16 첫 측정. 공공 문서 묶음을 GPU 임베딩 TEI로 색인하고(조각 2,193개) `run --through rerank --records read`를 리랭커 끝점 없이 돌렸다. 종료 코드 0, 새로 계산한 수 0, 지표는 티켓 14의 일지와 같았다. `score_distribution`은 후보 15,500개 가운데 닿음 380개, 닿지 않음 15,120개를 센다. 닿지 않은 조각의 78%가 0.05 미만이고 0.95 이상 구간에서는 닿음 181개와 닿지 않음 156개가 섞인다. 문턱별 상위 10 적중률은 문턱 없음 0.987, 0.05에서 0.974, 0.30에서 0.913, 0.50에서 0.884다. 보고서를 `.scratch/search-eval/probes/no-answer-scores/first_measurement_report.md`에 옮겼다. 사용자에게 표로 보이고 멈췄다. 색인에 답이 없는 질의가 없어 효과는 재지 못했고 비용만 보였다. 이 측정은 프로브 스크립트가 아니라 손으로 돌린 명령이다.
- 2026-11-16 사용자의 첫 답은 "3"(답 없는 질의로 더 잰다)이었다. 질문 20개를 만들고(소재가 먼 10개, 가까운 10개) 핵심어를 `chunks.text`에 `LIKE`로 세고 나온 열 곳의 문맥을 읽어 답이 없음을 확인했다(손으로 봤다). 프로브 `.scratch/search-eval/probes/no-answer-scores/`가 두 질의 집단을 같은 길로 돌려 문턱표를 냈다. 사전 기준(답 없는 질의의 빈 결과 비율 0.80 이상, 답 있는 질의가 기대 근거를 잃는 비율 0.10 이하)은 대화에서 정했고(커밋으로는 확인되지 않는다) 문턱 0.10~0.40에서 채워졌으며 결과를 본 뒤 바꾸지 않았다. 0.10의 통과는 정확히 0.80이고 1등 점수 0.099인 질문 하나에 달렸다. `noans-18`(퇴직금)은 일부 답이 있다고 볼 수 있어, 빼고 19개로 세면 문턱 0.30에서 모두 빈 결과다.
