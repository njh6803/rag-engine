# 07: 추론 기록: 모델이 계산한 결과를 저장해 다시 쓰고, 요청 지문으로 어댑터의 변경을 잡는다

**What to build:** 평가 도구의 조립이 `Embedder`와 `Reranker` 포트를 추론 기록 어댑터로 감싸, 기록에 있는 글은 TEI를 부르지 않고 기록의 값을 쓴다(스토리 16). 기록에 없는 글이 많으면 까닭과 다시 돌릴 명령을 알리며 실패한다(스토리 17). `index`와 `run`이 `--records read|write|off`를 받고, 기록 파일은 명령마다 주인이 하나다. 서버와 작업자의 조립은 기록을 쓰지 않는다(명세 "추론 기록").

**Blocked by:** 05 (전체 실행. 리랭크 기록의 주인이 전체 실행의 `run`이다)

**Status:** ready-for-agent

- [ ] 감싸는 어댑터 둘: 감싼 포트를 부르기 전에 기록을 보고, 없으면 감싼 포트를 불러 결과를 쓴다. 토큰 세기(`count_tokens`, `special_token_count`, `token_spans`)는 기록하지 않고 그대로 넘긴다. 열쇠는 임베딩이 `sha256(모델 이름, NUL, 글의 UTF-8 바이트)`, 리랭크가 `sha256(모델 이름, NUL, 질의, NUL, 글)`이고 모델 이름은 `config.json`의 것이다. 모델 이름이 다르면 기록의 값을 쓰지 않는다.
- [ ] 기록 파일(명세 "추론 기록"): `records/chunk-embeddings.keys`·`.f32`(주인 `index`), `records/query-embeddings.keys`·`.f32`(주인 `run`), `records/rerank.jsonl`(주인 전체 실행의 `run`), `records/records.json`(`format_version` `"1.0.0"`, 기록 파일마다 모델 이름, 차원, 수, 만든 TEI의 판과 장치, 요청 지문). 정렬해 쓰므로 같은 내용은 같은 바이트다. 쓰기는 02의 경로 판정을 거친다.
- [ ] `--records read`(기본): 기록 파일을 고치지 않는다. 새로 계산한 임베딩이 100개를 넘으면 계산을 멈추고 종료 코드 1과, 어느 명령을 `--records write`로 다시 돌려 어느 파일을 커밋할지를 알린다. 리랭커의 끝점이 없는 전체 실행은 기록에 없는 쌍 하나에도 같은 방식으로 실패한다(05가 둔 끝점 필수를 이 티켓이 이 동작으로 바꾼다).
- [ ] `--records write`: 그 명령이 주인인 파일만, 명령이 종료 코드 0으로 끝날 때만 이번 실행이 쓴 열쇠 전부로 다시 쓴다. 기록에 이미 있는 열쇠의 값은 옮기고 없는 글만 계산한다. 그 파일에 적힌 요청 지문이 지금 것과 다르면 옛 값을 옮기지 않고 다시 계산한다. `index --records write`는 문서가 하나도 없는 데이터베이스에서만 돌고, 문서가 든 데이터베이스에서는 아무것도 쓰지 않고 1과 데이터베이스를 새로 만들라는 안내를 낸다. 빠른 실행의 `run`은 `rerank.jsonl`을 건드리지 않는다.
- [ ] `--records off`: 기록을 읽지도 쓰지도 않는다(설정 실험용).
- [ ] 요청 지문(명세 "추론 기록"의 어댑터 변경 항목): TEI 어댑터가 추론 요청의 경로와, 본문에서 글·질의·모델 이름을 뺀 칸을 임베딩과 리랭크마다 한 자리에 두고 요청을 그것으로 짓는다. 지문은 경로와 그 칸을 정렬한 JSON의 sha256이다. 어댑터 시험(`tests/adapters/test_tei_embedder.py`, `test_tei_reranker.py`)이 실제로 보낸 요청의 경로와 칸이 그 자리의 값과 같은지 본다.
- [ ] `validate`가 기록을 본다: `records.json`의 판, 기록의 합 20MB 이하, 요청 지문이 이 체크아웃의 어댑터가 내는 것과 같은지(다르면 다시 만들 기록 파일을 알린다), `records.json`의 TEI 판과 `compose.eval.yml`의 이미지 태그(장치 머리를 뗀 것)가 `config.json`의 `tei_version`과 같은지. 요청 지문은 끝점 없이 읽는다.
- [ ] 보고서의 `records` 칸: 기록에서 읽은 수, 새로 계산한 수, 읽은 기록 파일마다의 sha256.
- [ ] 시험(명세 "추론 기록의 시험"): 기록에 있는 글은 스텁을 부르지 않는다(스텁의 요청 횟수), `read`에서 상한을 넘으면 1과 안내가 나오고 기록 파일이 그대로다, 리랭커의 끝점 없는 전체 실행이 기록에 없는 쌍 하나에 실패한다, `write`가 주인 파일만 다시 쓰고 다른 파일은 바이트 그대로다(`index`와 빠른 실행의 `run` 뒤에 `rerank.jsonl`이 그대로다), `write`가 쓰이지 않은 열쇠를 지우고 같은 내용이면 같은 바이트를 쓴다, `index --records write`가 문서가 든 데이터베이스에서 기록 파일을 바이트 그대로 두고 1을 낸다, `index --records write`가 문서 목록과 해시가 다른 문서 파일이 있으면 스키마를 올리지 않고 기록 파일을 바이트 그대로 두며 1을 낸다, `off`가 기록을 읽지도 쓰지도 않는다, 모델 이름이 다르면 기록의 값을 쓰지 않는다, `validate`가 요청 지문이 다르면 실패하고 다시 만들 파일을 알린다, `write`가 요청 지문이 다른 파일의 옛 값을 옮기지 않는다(스텁의 요청 횟수), `write`로 돈 명령이 1로 끝나면 주인 파일이 바이트 그대로다, 보고서가 읽은 기록 파일의 해시를 싣는다, `records/`나 기록 파일이 묶음 밖을 가리키는 링크이면 `index`와 `run`이 쓰지 않고 1을 내며 링크가 가리킨 파일이 그대로다, `validate`가 TEI 판과 compose 태그가 다를 때와 20MB를 넘을 때 실패한다.
- [ ] `compose.eval.yml`의 머리 주석에 TEI의 판을 올리는 PR은 기록을 다시 만든다는 것이 있는지 본다(03이 적었다).
- [ ] 검사 넷이 초록이다.
