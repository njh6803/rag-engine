# 08: `compare`: 기준 보고서와 견줘 하락폭을 넘으면 실패한다

**What to build:** 개발자나 CI가 `compare --gate fast|full <보고서> <묶음 폴더>`를 치면, 도구가 보고서를 기준 보고서(`baseline-fast.json`이나 `baseline-full.json`)와 견줘 질의 목록마다 상위 5 적중률이나 MRR이 하락폭 넘게 떨어졌으면 종료 코드 1로 실패하고, 어느 질의 목록의 어느 숫자가 얼마나 떨어졌는지 표준 오류에 찍는다(스토리 12, 14). 기준 보고서와 견줄 수 없는 보고서(내용 해시, 구성, 기록 해시가 다른 것)는 숫자를 견주지 않고 실패한다. 견줌은 평가 유스케이스에 둔다(명세 "자리와 층").

**Blocked by:** 07 (추론 기록. 기록 파일의 해시를 견준다)

**Status:** ready-for-agent

- [ ] `--gate fast`는 `baseline-fast.json`의 합친 뒤 줄과, `--gate full`은 `baseline-full.json`의 리랭크 뒤 줄과 견준다. 질의 목록마다 상위 5 적중률 2%p, MRR 0.02의 하락폭을 넘을 때만 실패한다(정확히 경계는 통과). 하락폭은 명세 CI 게이트 절의 `[사용자 선택]` 값이고, 11의 흔들림 측정으로 확정된다.
- [ ] 견주지 않고 실패하는 경우(명세 "CI 게이트와 기준 보고서"): 묶음의 내용 해시가 다르다, 구성(`judge_model`과 `judge_prompt_version`을 뺀 칸)이 다르다, 그 게이트가 읽는 기록 파일의 해시(빠른 게이트는 조각과 질의의 임베딩 `.keys`와 `.f32`, 전체 게이트는 거기에 `rerank.jsonl`)가 다르다, 기준 보고서가 없다. 무엇이 달라 기준 보고서를 갱신해야 하는지를 알린다.
- [ ] 실패하면 질의 목록, 지표, 기준값, 새 값, 차를 표준 오류에 표로 찍는다. 새 값이 기준보다 하락폭 넘게 높으면 통과하되 기준 보고서를 갱신하라고 알린다.
- [ ] 보고서의 `meta`는 견줌에서 뺀다. 판정 칸 둘만 다른 기준 보고서와는 견준다.
- [ ] 기준 보고서 파일의 읽기는 02의 경로 판정을 거친다.
- [ ] 표면 시험: 하락폭을 넘는 하락에서만 실패하고 정확히 경계는 통과한다, 묶음의 해시나 구성이 다르거나 기준 보고서가 없으면 견주지 않고 실패한다, `judge_model`만 다른 기준 보고서와는 견준다, 기록 파일의 해시가 다르면 견주지 않고 실패한다, `--gate fast`와 `--gate full`이 각자의 기준 파일과 줄을 본다, 실패의 표준 오류에 질의 목록·지표·기준값·새 값·차가 있다(스토리 14), 하락폭 넘게 오른 보고서는 통과하고 갱신 안내가 나온다.
- [ ] 검사 넷이 초록이다.
