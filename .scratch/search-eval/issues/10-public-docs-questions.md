# 10: 공공 문서 묶음의 질문과 기대 근거, 임베딩 기록

**What to build:** 에이전트가 09의 문서로 질문과 기대 근거, 사람이 묻는 문장과 키워드형의 질의 목록 둘의 초안을 쓰고, 사용자가 검수해 확정한다(스토리 21). 확정한 묶음으로 조각과 질의의 임베딩 기록을 만들어 커밋하고, 커밋된 묶음이 `validate`의 파일 검사를 지나는지를 pytest가 본다. 이 티켓에는 사용자의 검수를 기다리는 지점이 있다.

**Blocked by:** 07 (추론 기록), 09 (문서)

**Status:** ready-for-agent

- [ ] 질문 150개 안팎을 쓴다(명세 "공공 문서 묶음"). 질문은 문서의 문장을 베끼지 않고 표현을 바꿔 묻는다. 유형 표지 `table` 20개 이상, `multi_document` 15개 이상, `no_context` 15개 이상, 문서 하나에 질문 8개 이하다. 필터가 붙은 질의를 사람 질문 목록에 20개 안팎 두고 갱신일 기간만 쓴다. 갱신일(`documents.json`의 `updated_at`)은 법령·행정규칙 32개가 공포일이고 보고서 14개는 대부분 포털의 자료 기준일이라(10개. 한전원자력연료 DOCX 3개가 모두 2017-11-13이다) 발행일이 아니다. 티켓 09 `## Comments`를 읽고 기간을 정한다.
- [ ] 기대 근거의 글귀는 파싱 결과의 본문 블록에서 옮긴 한 문장이나 구절이고 제목에서 옮기지 않으며, 공백을 뺀 길이가 10자 이상 120자 이하다(명세 "적중의 단위").
- [ ] 키워드형 질의 목록은 같은 질문을 명사 중심의 검색어 2~6낱말로 바꾼 것이다.
- [ ] 질문, 글귀, 유형 표지를 한 표로 사용자에게 보이고 **멈춘다**. 사용자가 확정한 뒤 커밋하고, 검수한 날짜를 이 티켓의 `## Comments`에 적는다.
- [ ] 기본 구성의 새 평가 데이터베이스에서 `index --records write`와 `run --through fused --records write`로 조각과 질의의 임베딩 기록을 만들어 `records/`와 함께 커밋한다. `validate --indexed`가 그 데이터베이스에서 통과한다. 만든 장치와 걸린 시간을 `## Comments`에 적는다. CPU TEI(`compose.eval.yml`의 기본)에서는 평가 도구의 TEI 시간 제한(`tei_timeout_seconds` 60초, 이 도구에서 바뀌지 않는다)에 걸려 `index`가 `embedding_unavailable`로 끝나지 않았다. 티켓 09는 TEI GPU 이미지(`turing-1.9.4`)로 색인했다(티켓 09 `## Comments`).
- [ ] 저장소 상태 시험(명세 Testing Decisions): 커밋된 공공 문서 묶음이 `validate`의 파일 검사(형식, 해시, 용량, 기록의 판과 크기와 요청 지문)를 지나는 것을 pytest가 본다. 지금 통과함을 재는 시험과, 묶음을 임시 폴더에 복사해 한 곳을 어긴 뒤 잡히는 것을 보는 변이 시험을 하나씩 둔다(`.claude/rules/tests.md`).
- [ ] 검사 넷이 초록이다.
