# 20: 최소 점수: `search`의 `min_score` 인자와 지식베이스의 기본값

**What to build:** 검색 도구 `search`에 선택 인자 `min_score`(0 이상 1 이하)를 두어 리랭크 점수가 그 값보다 낮은 조각을 결과에서 뺀다. 지식베이스마다 기본값을 둘 수 있고 요청 인자가 이긴다(스토리 34~38, 명세 "최소 점수", ADR 0017). 사용자가 티켓 18의 두 측정을 보고 2026-11-16에 구현을 승인했고 승인은 ADR 0017 이력 2026-11-16에 있다. 이 티켓은 원칙 VII의 판을 올리는 계약 변경이다(`format_version` `1.0.0`에서 `1.1.0`. 입력 인자를 더하는 것도 minor라는 규칙은 ADR 0015 이력 2026-11-12). 기능의 첫 티켓이 아닌 것은 ADR 0017이 둔 예외다. 기본값은 비워 둔다. 측정이 지지하는 범위는 0.10~0.30이지만(근거는 ADR 0017 이력 2026-11-16) 설치의 기본으로 정하지 않고 운영자가 고른다.

시작 전에 티켓 17(리랭커 켬·끔 실험)의 결정을 확인한다. 17이 아직 결정 전이면 ADR 0017 이력의 전제(리랭커가 있는 지식베이스)로 진행한다. 17이 이미 결정됐고 리랭커를 끄는 기본이면 이 인자가 거부되는 지식베이스가 늘어나므로, 구현 전에 사용자에게 이 티켓을 그대로 할지 묻는다.

**Blocked by:** 18 (승인과 ADR 0017 이력)

**Status:** ready-for-agent

- [ ] 거르는 자리는 리랭크 뒤, `top_k`로 자르기 앞이다. `min_score`보다 낮은 점수의 조각이 결과에서 빠지고, 같은 점수는 남는다. 이 판단을 `app`의 검색 유스케이스가 하고 서드파티를 import하지 않는다.
- [ ] 요청 인자가 있으면 그 값이, 없으면 지식베이스의 기본값이, 둘 다 없으면 거르지 않는다(지금 동작). 요청 인자 `0`은 기본값을 덮는다(거르지 않음).
- [ ] 범위 밖의 값(0 미만, 1 초과)과 유한하지 않은 값(`nan`, `inf`)은 `invalid_argument`다. `float | None`으로 선언한 인자는 `"nan"`과 `"inf"`를 SDK의 입력 검증이 통과시키고(pydantic 검증을 이 저장소의 환경에서 손으로 돌려 보았다), `nan`은 `x < 0 or x > 1`도 지나가 아무것도 거르지 않기 때문이다. 숫자로 읽히지 않는 값(`"abc"` 같은 글)은 유스케이스에 닿기 전에 SDK의 입력 검증이 거부하고, 그 모양은 기존 인자의 타입 오류와 같다(프로브 `.scratch/search-eval/probes/mcp-args/probe_unknown_args.py`).
- [ ] 리랭커가 없는 지식베이스에 요청의 `min_score`를 주면(`0`도 포함) `invalid_argument`다(스토리 36). 요청 인자가 없고 `migrate`의 거부(아래)를 지나지 않아 리랭커가 빈 채 기본값이 있는 지식베이스 행이 생긴 경우에만 검색이 `search_unavailable`이다. 두 경우가 겹치면(그런 행에 요청 인자까지 준 경우) 요청 인자 쪽을 먼저 거부해 `invalid_argument`다.
- [ ] 남은 조각이 없으면 오류가 아니라 빈 결과를 정상 응답으로 낸다(스토리 35). 현재 판이 없을 때와 없는 그룹 이름으로 걸렀을 때가 빈 결과인 것과 같은 규칙이다.
- [ ] 지식베이스 행에 널을 허용하는 최소 점수 칸을 더하는 마이그레이션(0003)을 쓴다. `SCHEMA_VERSION`(`src/rag_engine/adapters/index_elements.py`)은 올리지 않는다. 지식베이스 행에 칸을 더하는 것은 색인을 바꾸지 않아서 재색인이 필요 없다. 색인 판의 요소를 바꾸지 않는 마이그레이션이 `SCHEMA_VERSION`을 올리지 않는 선례는 0002다(0002는 `jobs`에 색인을 더했고 이번은 `knowledge_bases`에 널 허용 칸을 더하므로 바꾸는 표는 다르다).
- [ ] 기본 지식베이스의 값은 환경 변수 `RAG_DEFAULT_MIN_SCORE`(기본 비움)로 받아 `migrate`가 쓴다. 리랭커가 빈 채로 기본값이 있으면 `migrate`가 거부한다. 거부 문장은 값이 아니라 환경 변수의 이름만 싣는다(원칙 V).
- [ ] 계약 시험(`tests/contract/`)이 도구 목록의 inputSchema에 `min_score`가 있고, 결과의 `format_version`이 `1.1.0`인 것을 본다(스토리 37). 옛 서버가 모르는 인자를 조용히 버리는 것과 갈리는 신호는 이 판이다.
- [ ] 스토리 34~38을 시험이 덮는다. 검색 도구의 설명(MCP 도구 문서)에 인자의 뜻과 리랭커가 없으면 거부한다는 것을 적는다.
- [ ] 이 티켓이 닫히면 ADR 0017 본문의 "그때까지 판은 `1.0.0`이다"가 지난 이야기가 된다. 그 문장 뒤에 이력을 가리키는 포인터를 달기 위해 ADR 0017에 구현 이력을 더하고(`.claude/rules/adr.md`), 이력 제목과 포인터의 글자가 맞는지 `tools/check_adr_pointers.py`로 본다.
- [ ] `uv run python tools/plan_table.py`로 전체 계획을 다시 만든다.
- [ ] 검사 넷이 초록이다.

관리 API가 최소 점수 기본값이 있는 지식베이스에서 리랭커를 빼는 설정 변경을 422로 거부해야 한다는 규칙은 이 티켓이 아니라 admin이 받는다(명세 Out of Scope).
