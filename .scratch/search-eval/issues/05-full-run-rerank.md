# 05: 전체 실행: `run --through rerank`가 리랭크 뒤 줄과 점수 분포를 낸다

**What to build:** 개발자가 리랭커 TEI를 띄우고 `run --through rerank`를 치면, 평가가 합친 뒤의 후보 전부를 실제 검색과 같은 `Reranker` 포트로 채점해 리랭크 뒤 단계의 줄을 더하고, 최소 점수를 정할 근거인 `score_distribution`을 보고서에 싣는다(스토리 3, 27). 리랭커의 모델 이름은 지식베이스가 아니라 `config.json`의 `reranker_model`에서 읽는다.

**Blocked by:** 04 (빠른 실행)

**Status:** ready-for-agent

- [ ] 리랭크 뒤 단계는 합친 뒤의 후보 전부(`fused_rank`가 후보 수 이하인 줄)를 리랭크한 점수 순이고, 점수가 같으면 합친 순위 순이다(명세 "진단용 검색과 단계"). 리랭커에 보내는 글은 검색과 같다(온전한 절 경로를 붙인 글).
- [ ] 리랭커의 끝점은 `RAG_EVAL_RERANKER_URL`이다. 이 티켓에서 끝점이 없는 전체 실행은 종료 코드 1과 빠진 이름을 낸다. 끝점 없이 리랭크 기록만으로 도는 길은 07이 더한다.
- [ ] 보고서의 마지막 단계는 리랭크 뒤다. 유형 표지와 필터 질의의 줄을 마지막 단계에 대해 내는 규칙(06)이 이 단계를 쓰게 한다.
- [ ] `score_distribution`(명세 "최소 점수"): 합친 뒤의 후보 전부의 리랭크 점수를 기대 근거에 닿은 조각과 그렇지 않은 조각으로 갈라 0.05 폭 구간마다 세고, 문턱 0.05부터 0.95까지 0.05 간격마다 상위 5 적중률, 상위 10 적중률, 결과가 비는 질의의 비율, 질의마다 남는 조각 수의 평균을 낸다. 빠른 실행의 보고서에는 이 칸이 없다. `report.md`에 같은 표를 싣는다.
- [ ] 표면 시험: `--through rerank`의 보고서에 리랭크 뒤 줄이 있다, 리랭크에서 순위가 바뀐 질의의 적중률이 리랭크 뒤 줄에 반영된다(TEI 스텁의 결정적 점수로 순위를 정한다), `score_distribution`의 구간 수와 문턱별 값이 손으로 계산한 값과 같다(스토리 27).
- [ ] 검사 넷이 초록이다.
