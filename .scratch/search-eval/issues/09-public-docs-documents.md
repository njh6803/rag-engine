# 09: 공공 문서 묶음의 문서: 후보 목록을 확정하고 문서와 문서 목록을 커밋한다

**What to build:** 에이전트가 법령·행정규칙과 공공누리 제1유형 문서의 후보 목록을 출처와 이용 조건과 함께 내고, 사용자가 확정한 문서만 `evals/public-docs/documents/`에 커밋한다(스토리 22, 39). 문서 목록 `documents.json`, 묶음의 머리 `eval-set.json`, 구성 `config.json`도 여기서 선다. 질문과 기대 근거는 10이 쓴다. 이 티켓에는 사용자의 확정을 기다리는 지점이 있다.

**Blocked by:** 03 (`index`. 고르는 기준의 조각 수를 기본 구성으로 색인해 센다)

**Status:** ready-for-agent

- [ ] 후보를 내려받아 이용 조건의 표시를 원문으로 확인하고, 제품의 파서로 파싱해 글이 나오는지 본다(스캔본과 HWP 5.0 바이너리는 담지 않는다). 후보 목록(제목, 낸 기관, 주소, 이용 조건, 표시를 확인한 자리, 형식, 표·그림 여부, 짝)을 사용자에게 보이고 **멈춘다**. 사용자가 확정한 문서만 커밋하고, 확정한 날짜와 사용자의 글을 이 티켓의 `## Comments`에 적는다(명세 공공 문서 묶음 절의 `[사용자 선택]` 후보 목록 항목).
- [ ] 고르는 기준(명세 "공공 문서 묶음"): 법령·행정규칙·고시 30개 안팎과 공공누리 제1유형 표시가 있는 공공기관의 보고서·안내서 10개 안팎, 형식 PDF·DOCX·HWPX 셋을 모두 담고 한 형식이 30개를 넘지 않음, 표가 든 문서 10개 이상, 같은 주제를 이어 다루는 짝 5쌍 이상, 기본 구성으로 색인한 조각 3,000개 이하, 문서 파일의 합 30MB 이하.
- [ ] `documents.json`은 문서마다 `key`, `title`, `publisher`, `source_url`, `license`(`법령 등(저작권법 제7조)` 또는 `공공누리 제1유형`), `license_evidence`, `downloaded_at`, `sha256`(16진 소문자), `bytes`, `updated_at`(`YYYY-MM-DD`)을 든다. 이용 조건은 원문의 표시로 확인한 것만 적는다(`docs/agents/issue-tracker.md`의 프로브와 근거 절).
- [ ] `eval-set.json`(`format_version` `"1.0.0"`, 질의 목록 둘의 자리)과 `config.json`(모든 칸. 첫 값은 제품의 기본값과 `tei_version`, `judge_model` `claude-opus-5-5`, `judge_prompt_version` 1)을 커밋한다. 질의 목록과 기대 근거 파일은 10이 채운다. `validate`의 파일 검사가 문서와 목록에 대해 통과한다.
- [ ] 기본 구성으로 `index`를 돌려 조각 수를 세고 그 수를 이 티켓의 `## Comments`에 적는다. 3,000개를 넘으면 문서를 줄인 목록을 다시 사용자에게 보인다.
- [ ] 새 최상위 폴더 `evals/`를 `README.md`의 트리와 `.scratch/plan-head.md`의 목표 배치에 더한다.
- [ ] 검사 넷이 초록이다.
