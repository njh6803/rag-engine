# eval-screen: 검색 평가를 관리자 페이지에서 등록하고 돌리고 결과를 본다
**슬라이스:** 2
**Blocked by:** group-kb

admin 설계 인터뷰(ADR 0024, 2026-11-26)가 admin에서 갈라 낸 기능이다. 설치처의 운영자가 자기 문서로 평가 세트를 등록하고, 검색 평가를 돌리고, 결과를 화면에서 본다. 평가의 핵심(채점, 지표, 보고서)은 search-eval이 `app`의 유스케이스로 지었고 지금 입구는 저장소의 명령줄 도구뿐이다(ADR 0018). 그 도구는 릴리스 이미지에 실리지 않으므로, 제품 이미지 안에서 평가를 부르는 입구는 이 기능이 처음 연다. 그 입구가 열릴 때 LLM 관련성 판정도 함께 열린다. 판정기와 SDK는 이미 이미지에 실려 있고 기본은 꺼짐이다(끝점 주소, 모델, 키 설정이 모두 있어야 조립된다. ADR 0019). admin이 지은 로그인과 화면의 틀, 화면 부품 위에 서고, 세부는 이 기능의 설계 인터뷰가 정한다. 화면이 있는 기능이라 명세 전에 화면을 그린다(ADR 0026 "화면 그림을 명세 앞에 둔다"). 첫 정식 릴리스 0.1.0에 실린다(ADR 0024 "차례와 0.1").

group-kb 뒤에 서는 까닭: 지식베이스마다 두는 설정(LLM으로 내보내기 허용, 최소 점수의 기본값)이 지식베이스를 고치는 화면에 붙는데, 그 화면과 관리 API를 group-kb가 짓는다(ADR 0024).

admin 설계(ADR 0024, 2026-11-26)가 넘긴 것: 셋이다. search-eval의 설계(ADR 0018, 0019)가 admin에 넘겼던 일이고(`.scratch/admin/plan.md`의 "search-eval 설계가 넘긴 것" 문단이 그때의 기록이다), admin 설계가 이 기능으로 옮겼다. 첫째는 평가를 등록하고 돌리고 결과를 보는 화면과 그 관리 API, 평가 세트와 결과를 두는 저장 표다. 둘째는 지식베이스마다 조각과 질문을 LLM 쪽으로 내보내도 되는지 따로 허용하는 장치다. 셋째는 설치처의 평가 세트와 판정 결과를 어디에 얼마나 보관할지다. 설치처의 질문과 문서 내용이라 원칙 V의 대상이다.

설계 인터뷰가 알아 둘 지금의 사실: admin 설계 인터뷰에서 사실을 찾은 서브에이전트가 코드와 문서를 읽었다고 보고한 것이고(일지 `docs/journal/2026-11-26-1534-admin-design.md`의 "확인한 것"에 줄 번호가 있다. 보고가 든 파일은 `src/rag_engine/app/eval_run.py`, `src/rag_engine/adapters/eval_environment.py`, `src/rag_engine/app/check_eval_database.py`, `src/rag_engine/adapters/claude_judge.py`, `.scratch/search-eval/spec.md`, `.scratch/search-eval/issues/`의 14번과 17번 티켓이고 읽은 커밋은 `5d5651c`다), 이 기능의 설계 인터뷰가 다시 대 본다. 평가 유스케이스는 지식베이스의 이름을 받지 않고 기본 지식베이스와 기본 원천의 문서만 본다. 명령줄 입구는 평가 전용 데이터베이스(이름이 `rag_eval`로 시작한다)에만 붙고, 데이터베이스에 평가 묶음 밖의 문서가 한 건이라도 있으면 색인, 실행, 판정을 거부한다. 판정이 조각의 글을 밖으로 보내므로 묶음 밖의 문서가 나가지 않게 막은 것이다. 그래서 운영 중인 지식베이스에 평가를 돌리려면 이 둘을 어떻게 풀지부터 정해야 한다. 판정 파일과 추론 기록에는 글 없이 해시만 남는다. 걸리는 시간도 화면의 설계에 닿는다. 공공 문서 묶음(문서 46개, 질의 310개)에서 리랭크 점수를 처음 계산하는 실행은 개발 PC의 GPU로 3시간 24분이 걸렸고(search-eval 티켓 14의 기록), CPU에서 리랭커를 켠 후보 50개 검색 한 번은 130초였다(search-eval 티켓 17의 기록). 평가 한 번이 요청 하나의 응답 시간 안에 끝나지 않을 수 있으므로, 평가를 어떻게 돌리고 진행을 어떻게 보일지를 설계가 정한다. 판정 비용은 3,000건에 약 26달러로 어림한다(ADR 0019).

이 기능의 티켓이 고칠 주석: `src/rag_engine/app/eval_compare.py`의 머리 주석은 보고서를 견주는 유스케이스를 "admin이 평가를 화면으로 열 때 함께 쓴다"고 적는다. admin 설계가 평가 화면을 이 기능으로 옮겼지만, 설계 PR은 `src/`를 바꿀 수 없어 그 주석을 그대로 두었다. 이 기능이 그 유스케이스를 화면에 잇는 티켓에서 주석을 고친다.

수락(설계 인터뷰가 다듬는다): 브라우저에서 표본 평가 세트를 등록해 평가를 돌리면 진행이 보이고, 끝난 뒤 화면의 지표가 같은 평가 세트를 명령줄 도구로 돌린 보고서의 지표와 같으며, LLM으로 내보내기를 허용하지 않은 지식베이스에서는 판정 요청이 나가지 않는 e2e가 통과한다.
