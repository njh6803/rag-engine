# admin 화면 프롬프트

관리자 페이지 v0의 화면 아홉(로그인, 링크로 비밀번호 정하기, 대시보드, 원천, 문서, 검색 시험, 토큰, 계정, 내 비밀번호 바꾸기)을 그릴 때 그리는 쪽에 주는 시작 프롬프트다. ADR 0026의 "화면 그림을 명세 앞에 둔다"가 이 화면을 명세 전에 그려 사용자에게 확인받기로 했고, 확정한 화면은 명세의 근거가 된다.

프롬프트에 든 것은 세 가지다. **결정**은 ADR 0024(화면 목록, 원천 화면에서 다 한다, 일정, 문서 화면, 토큰 화면, 동기화 취소와 그 이름, 문서 하나 다시 수집, 폴더 목록, 검색 시험, 검색에 걸린 시간), ADR 0025(운영자 계정, 비밀번호 규칙, 잠금, 비밀번호 링크, 관리 포트), ADR 0026, 기능 계획 `.scratch/admin/plan.md`, 그 계획이 입력으로 든 킥오프 입력 5절(`.scratch/kickoff-input.md`의 "제품 0.1에서 화면으로 만들 것")과 source-sync 명세(`.scratch/source-sync/spec.md`의 관리 API 절)가 정한 것이다. 화면 문구의 말은 `GLOSSARY.md`에서 왔다. 화면의 배치는 아래 "참고 디자인"에서 사람이 고른 방향이다(일지 `2026-11-26-1938-admin-screens.md`). **이 프롬프트의 제안**은 그리는 데 필요해서 더한 것이고 명세가 다시 정한다. 화면마다 그릴 상태, 문구, 창과 메뉴의 모양, 상태 배지, 좁은 폭의 위 막대가 여기 든다. **탐색용 가정**은 결정도 제안도 아닌 그리기 위한 값이고 두 프롬프트 끝의 "탐색용 가정"에 모았다.

로그인, 비밀번호 정하기, 계정, 계정 메뉴, 내 비밀번호 바꾸기는 agent-os가 고르고 확정한 화면(그 저장소의 `.scratch/admin-login/design/`)과 그 명세의 문구를 이 제품의 이름, 탐색, 말투로 옮긴다(ADR 0026이 화면 부품과 디자인의 원천을 agent-os로 정했고, ADR 0025가 로그인과 계정의 규칙을 agent-os와 같게 정했다). 토큰 화면은 계정 화면과 같은 표, ⋯ 메뉴, 확인 창의 모양으로 그린다.

이름 셋은 와이어프레임을 그린 뒤 2026-11-27에 사람이 바꿨다(일지 "이름"). 현황 화면은 대시보드다(ADR 0024 이력 2026-11-27). 색인 판 계열은 색인 버전 계열이다. 이 이름은 사람이 2026-11-19에 골랐고(일지 `2026-11-19-0025-glossary-ask-remaining-names.md`), 용어집은 그 이름 바꾸기를 맡은 PR이 고치므로 그때까지 용어집에는 옛 이름이 남는다. 화면에서는 "현재 색인 버전 3"처럼 늘 "색인"을 앞에 붙여, 계약 버전이나 릴리스 번호와 가른다. 원천의 종류 칸은 서버 폴더, 데이터베이스, 수집 API, 파일 올리기 가운데 하나로 적는다(용어집 "원천"). 아래 글은 새 이름으로 고쳤고, 아티팩트의 와이어프레임 열두 장은 바꾸기 전에 그려 옛 이름이 보인다.

## 하는 법

`/ui-design admin`으로 한다. 그 스킬이 순서의 원천이고, 이 파일은 그 스킬의 3단계가 쓰는 시작 프롬프트다(참고와 방향은 이미 골랐으므로 그 단계는 다시 묻지 않는다).

1. **디자인 시스템을 읽는다(스킬 2단계).** 2026-11-26에 이 세션이 디자인 시스템 아티팩트를 읽었다. 머리가 지금 계정을 주인으로 적었고 판은 `1795631875-90df`다. 이 저장소는 디자인 시스템을 올리거나 코드와 맞추지 않는다(ADR 0026).
2. **첫 차례(와이어프레임)를 그린다(스킬 5단계).** 아래 "1. 와이어프레임"이 그릴 것이다. 안을 고를 화면 넷의 안 셋씩, 아트보드 열둘이다. 디자인 시스템의 부품을 쓰지 않고 회색 계열의 쓰임새 토큰만으로 칠한 상자와 글자로 그린다. 정해진 화면은 이 차례에 넣지 않는다(`docs/agents/issue-tracker.md` 화면 디자인 절). 세션은 와이어프레임 없이 완성 화면으로 바로 고르기를 권했고, 사람이 와이어프레임 먼저를 골랐다(일지 "방향"). 아티팩트 하나에 두 차례를 함께 두고 쪽(`pages`)으로 가른다.
3. **안을 고른다(스킬 6단계).** 화면마다 질문 하나로 네 화면을 한 번에 묻는다. 고른 안은 캔버스 메모에도 적는다.
4. **둘째 차례(완성 화면)를 그린다(스킬 5단계).** 같은 아티팩트의 다음 쪽에 "2. 완성 화면"을 그린다. 고른 안 넷의 완성 화면과 그 상태, 그리고 정해진 화면이다. 사람이 그 차례 전체를 질문 하나로 확정한다.
5. **저장소로 옮긴다(스킬 7단계).** 아래 "고른 뒤"가 이 기능의 표 칸이다.

그릴 화면의 나눔은 다음과 같다.

- **안을 고를 화면(안 셋씩).** 대시보드, 원천, 문서, 검색 시험이다. 킥오프가 0.1 화면으로 적은 넷이고, 조사한 제품들의 배치가 이 넷에서 갈렸다(아래 "참고 디자인"의 갈래). 사람이 이 넷을 골랐다.
- **배치가 정해진 화면(한 안).** 로그인, 비밀번호를 정하는 화면, 계정, 지금 계정의 표시와 그 메뉴, 내 비밀번호 바꾸기, 토큰이다. 앞의 다섯은 agent-os에서 확정한 배치이고, 토큰은 계정 화면과 같은 꼴이다. 둘째 차례에 그린다.

## 참고 디자인

`docs/agents/issue-tracker.md` 화면 디자인 절대로 했다. 색·글꼴·간격과 부품은 디자인 시스템 그대로 두고, 참고는 새 화면의 배치와 문구에만 쓴다. 사람은 줄 참고가 없다고 했고, 세션이 맡긴 서브에이전트 둘이 일곱 제품을 읽었다.

- 문서·검색 시험·대시보드 쪽: Dify(공식 저장소 소스와 문서, 갈무리 둘), RAGFlow(공식 저장소 소스와 문서, 갈무리 넷), Algolia(공식 문서, 옛 문서의 갈무리 둘), Meilisearch Cloud(공식 문서, 갈무리 다섯).
- 원천·동기화·토큰 쪽: Airbyte(공식 저장소 소스와 문서), Onyx(공식 저장소 소스와 문서), Fivetran(공식 문서. 소스는 닫혀 있다). 셋 모두 갈무리를 보지 못했다. 토큰은 GitHub 문서도 봤다.

갈무리가 없는 화면은 소스의 배치 속성과 문서 글로 판단했다. 읽은 파일과 출처는 일지 "조사"에 있다.

사람이 고른 방향(일지 "방향"): **공통 규칙을 바탕에 두고, 제품마다 갈린 배치는 안으로 나눠 그린다.** 공통 규칙은 셋 이상의 제품이 함께 쓴 것이다.

1. 목록 화면의 주 동작(원천 만들기, 파일 올리기, 토큰 발급)은 화면 머리 오른쪽 위에 둔다.
2. 원천이나 문서 하나를 누르면 그 하나를 보는 자리(따로 된 화면이나 패널)로 가고, 거기서 기록과 설정을 나눠 보인다.
3. 목록 한 줄에 이름, 종류, 상태, 마지막 동기화(원천)나 갱신(문서)이 있다.
4. 상태는 색만으로 보이지 않는다. 모양이 다른 아이콘과 글자를 함께 쓰고, 도는 중은 그것을 알리는 아이콘과 글자로 보인다.
5. 목록 위 한 줄에 검색칸과 거르기를 둔다.
6. 일시 중지는 지우기와 떨어진, 한 번 누르는 조작이다.
7. 동기화 기록 한 줄에는 계기, 시각, 끝난 모양, 옮긴 양, 걸린 시간이 있고, 실패한 줄에는 사유가 보인다.
8. 일정은 정해 둔 틀(매일, 매주, N분마다)을 먼저 내밀고, 다섯 칸 표현식은 그다음이다.
9. 파일 올리기는 끌어 놓는 칸과 고르기 버튼을 함께 둔다.
10. 검색 결과 위에 결과 수와 걸린 시간을 보이고, 점수는 숫자로 보인다. 긴 조각 글은 줄였다가 펼친다.
11. 토큰 값은 발급 직후 한 번만 보이고 복사 버튼이 있다.

제품마다 갈린 자리(안으로 나눈 것): 대시보드는 숫자 칸과 표(RAGFlow, Onyx의 요약 카드), 살펴볼 것을 먼저 두는 목록(Onyx Service Status의 문제 패널, Fivetran 상태 탭의 머리 줄), 시간 그래프(Meilisearch, Onyx). 원천은 표와 탭이 있는 따로 된 화면(Airbyte, Fivetran), 줄을 펼쳐 최근 동기화를 보는 목록(Onyx), 목록 옆 패널(Meilisearch의 색인 패널, Onyx의 기록 패널). 문서는 원문과 조각을 두 칸 나란히(RAGFlow), 조각 목록과 정보 패널(Dify), 목록 위 오른쪽 패널(Meilisearch). 검색 시험은 입력과 결과의 반반(RAGFlow), 위 검색칸과 왼쪽 좁은 조건 열(Meilisearch, Algolia), 결과 표(Dify의 점수 숫자 줄을 표로 모은 것. 표 모양 자체는 세션의 제안이다).

가져오지 않을 것(사람이 추천 목록대로 골랐다): 질문 기록과 검색 횟수와 검색 비율(질문 내용을 남기지 않는다. 원칙 V, ADR 0004), 조각 고치기·더하기·끄기·보관과 메타데이터 고치기와 파싱 방식 바꾸기, 검색 시험에서 MCP 검색 도구에 없는 칸(가중치, 재순위 끄기 같은 것), 가져오는 원천의 문서를 지우는 메뉴(원천에서 지워야 색인에서 지워진다. 원칙 VI, ADR 0024), 요금제·체험판 표시와 로고·브랜드 색·제품 이름, 그룹 단위 권한(토큰의 역할은 `admin`과 `reader` 둘이다), 화면 문구를 그대로 옮기는 것, 고정된 가짜 비교값, 각 제품에만 있는 기능(스키마·스트림·매핑, 지연 임계값, 권한 동기화, 가지치기, A/B, AI 검색).

참고와 저장소 규칙이 부딪친 자리 하나: 조사는 문서와 동기화의 상태를 배지로 보이라고 권했지만, 디자인 시스템의 상태 배지(`StatusBadge`)는 agent-os의 실행 상태 넷에만 쓰는 부품이다(`components/StatusBadge/README.md`). 그래서 문서·동기화·원천의 상태는 그 배지와 같은 모양(바탕 없이 옅은 테두리, 높이 22px, 상태색의 글자와 아이콘)을 그림 안에 직접 그린다. 계정의 상태는 디자인 시스템의 `AccountStatusBadge`를 쓴다. 이 배지를 부품으로 지을지는 명세가 정한다.

## 1. 와이어프레임

```text
rag-engine 관리자 페이지의 화면 넷(대시보드, 원천, 문서, 검색 시험)을 안 셋씩 와이어프레임으로 그려 줘. rag-engine은 MCP를 쓰는 어떤 클라이언트에서도 쓸 수 있는 설치형 문서 검색 서버다. 여러 원천에서 문서를 모아 조각으로 나누고 색인해 검색까지 맡고, 답을 만들지는 않는다. 관리자 페이지는 문서 담당자와 운영자가 "원천을 붙이고, 문서가 잘 들어갔는지 보고, 잘 찾아지는지 확인하는" 웹 화면이다. 모든 결과는 대화의 답이 아니라 디자인 파일 안의 "와이어프레임" 쪽으로 넣어 줘.

그리는 법: 디자인 시스템의 부품(버튼, 입력, 배지, 알림, 카드, 아이콘)을 쓰지 않는다. 쓰임새 토큰 가운데 회색 계열(--bg, --bg-raised, --text, --text-muted, --border, --border-control, --bg-hover, --bg-active, --bg-selected, --text-disabled, --bg-disabled)로만 칠한 상자와 선과 글자로 그린다. 원색 토큰(--gray-500 같은 것)은 쓰지 않는다. 상자 안에는 그 자리에 들 것을 짧은 글자로 적는다(예: "검색칸", "주 버튼: 파일 올리기", "상태 배지"). 표와 목록은 머리와 두세 줄만 진짜 글자로 채우고 나머지는 회색 막대로 둔다. 글꼴은 --sans, 고정폭은 --mono다. 안마다 아트보드 하나이고, 화면 둘(목록과 하나 보기)을 보여야 하는 안은 한 아트보드 안에 위아래로 놓고 칸마다 위에 흐린 설명 한 줄을 단다. 모두 데스크톱 1280px이다.

틀: 폭 768px 이상은 왼쪽 옆 탐색(폭 256px)과 본문이다. 옆 탐색 맨 위에 "rag-engine" 글자, 그 아래 항목 대시보드, 원천, 문서, 검색 시험, 토큰, 계정(계정은 시스템 관리자에게만 보인다), 맨 아래에 지금 계정의 자리(계정 이름 "ops-lead"와 흐린 "시스템 관리자"). 본문은 화면 머리(제목, 개수, 흐린 설명 한 줄, 오른쪽 위의 동작)와 그 아래 내용이다. 와이어프레임에서는 옆 탐색도 회색 상자와 글자로 그리고, 그 화면의 항목을 고른 표시만 둔다.

예시 데이터(열두 아트보드가 같은 값을 쓴다): 지식베이스는 default 하나이고 현재 색인 버전은 3이다. 원천 다섯:
- upload: 종류 파일 올리기(밀어 넣는 원천). 관리자 페이지에서 올린 파일이 든다. 문서 12.
- groupware-push: 종류 수집 API(밀어 넣는 원천). 그룹웨어가 수집 API로 보낸다. 문서 8.
```
