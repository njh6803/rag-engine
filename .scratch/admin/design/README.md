# admin 화면

관리자 페이지 v0의 화면이다. 시작 프롬프트 [screens-prompt.md](screens-prompt.md)로 Design 아티팩트(https://claude.ai/artifact/DYxhpWUJyyU2qF2d9WMhd2)에 그렸고, 사람이 2026-11-27에 고르고 확정했다. 고르고 옮긴 차례는 `/ui-design`이 원천이고, 표의 칸은 `docs/agents/issue-tracker.md` 화면 디자인 절이 원천이다.

- 옮긴 것은 완성 화면 쪽의 화면 보드 49개, 부품 6개, `canvas.json`이다. 줄은 시작 프롬프트가 적은 화면마다 하나와 부품 파일마다 하나이고, 한 파일에 화면이 둘이면 파일 칸이 같은 줄이 둘이다.
- 기준 커밋 `b6021ee`는 그릴 때 읽은 근거 문서의 커밋이다. 화면이 기대는 ADR 0024의 이력 둘(현황을 대시보드로 바꾼 것, 문서 화면의 원본 보기)과 용어집의 바뀐 항목(대시보드, 원천, 갱신일, 색인 상태, 그리고 되살림에서 이름을 바꾼 복구)은 이 화면 파일과 같은 커밋에 든다.
- `canvas.json`은 옮기지 않은 보드도 가리킨다. 와이어프레임 쪽의 12개(`Main.dc.html`, `wf-*.dc.html`)와 그 가운데 고르지 않은 안이다. 그 보드는 아티팩트에서 본다. 와이어프레임은 이름을 바꾸기 전에 그려 "현황", "색인 판", "반영됨"이 보인다.
- 화면 파일은 형식이 내주는 `./support.js`와 옮기지 않은 `ds/agent-os/`를 불러온다. 그래서 저장소의 사본만으로는 그려지지 않을 것으로 어림한다(열어 보지 않았다). 그림은 아티팩트 링크로 본다.
- 처음 옮긴 뒤 사람이 고침을 두 번 요청해 아티팩트에서 고쳤고, 사람이 2026-11-27에 다시 확정했다. 옮긴 것은 그 확정을 캔버스 메모에 적고 올린 판(`1795779033-a625`)에서 다시 받은 56개이고, sha256이 받은 결과 머리의 값과 모두 같았으며(`sha256sum -c`로 손으로 봤다), CR이 든 파일은 없었다.
- 그림에만 있고 디자인 시스템 부품에는 없는 것이 셋이다. 구현이 따를지는 명세나 web 뼈대 티켓이 정한다.
  - 단추·입력칸·선택칸과 메뉴 항목·탭의 아래 여백 2px. Noto Sans KR이 한글을 줄 상자 안에서 1px 낮게 그려(14px 글자는 위 4px, 아래 2px. 로컬에서 렌더한 화면에서 canvas `measureText`의 글자 상자로 손으로 봤다), 높이가 정해진 칸의 글자를 위아래 가운데에 세우려고 화면마다 머리 스타일에 더했다(사람이 글자의 세로 가운데 정렬을 요청했다).
  - 운영자 계정의 활성 표지. 디자인 시스템의 계정 표지(`AccountStatusBadge`)는 활성을 기본 글자색으로 그려, 다른 성공 표지처럼 초록 체크가 되게 부품 `cmp-badge`의 `active`로 그렸다(사람의 요청이다). 비활성, 잠김, 비밀번호 미설정은 디자인 시스템 표지 그대로다.
  - 디자인 시스템 CSS에 없는 배치 클래스 넷(`gap-6`, `grid`, `items-end`, `justify-end`). 쓴 자리를 인라인 스타일로 옮겨 그렸다. 화면 여섯(`doc-failed`, `doc-original-states`, `doc-skipped`, `doc-upload`, `doc-view`, `try-states`)이 쓰는 `text-center`도 디자인 시스템 README의 유틸리티 목록에는 없지만, 번들 CSS에 있어(`_ds_bundle.css`의 `.text-center{text-align:center}`를 읽었다) 그림에만 있는 것으로 세지 않고 그대로 두었다.
- 비고의 "그림의 제안"은 시작 프롬프트나 근거 문서가 정하지 않은 것을 그림이 채운 자리다. 명세가 결정으로 바꾸거나 다시 묻는다(시작 프롬프트 "고른 뒤" 2).
