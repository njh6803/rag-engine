# glossary-harness-small-names: 일하는 규약의 작은 이름 셋을 agent-os의 결정에 맞춘다(여러 곳에서 나는 같은 결함, 다시 올라온 항목, 추가 기준 횟수)

**What to build:** 사용자가 2026-11-18에 이름을 agent-os에서 고른 이름과 맞추라는 지시문을 냈다(원문 `.scratch/glossary-names-input.md`). 그 일은 PR 여럿으로 차례로 하고, 이 티켓은 지시문 5-2의 차례 1, 작은 하네스 이름 묶음이다. 앞 PR(`glossary-release-names`)이 병합되어 밖에 내놓는 제품의 이름은 끝났다. 이 PR이 바꾸는 이름은 회고(retro 스킬)와 대기열이 쓰는 말 셋이고, 새 이름은 사용자가 2026-11-18에 선택 화면에서 골랐다. 끝이 열린 결함 종류는 "여러 곳에서 나는 같은 결함", 이은 항목은 "다시 올라온 항목", 더하는 문턱(줄여 쓴 "문턱" 포함)은 "추가 기준 횟수"로 바꾼다. 고치는 곳은 살아 있는 글이다. 회고 스킬(`.claude/skills/retro/SKILL.md`), 열린 대기열 항목의 승인 줄과 본문, 도구의 독스트링(`tools/run_checks.py`, `tools/queue_open_rows.py`), 시험의 독스트링(`tests/tools/test_queue_open_rows.py`)이다. 사용자에게 묻고 정한 이름만 바꾸므로 세 이름 모두 선택 화면의 답대로다. 다른 것을 가리키는 "문턱"(세션 컨텍스트의 문턱 20만 토큰, 훅과 검사가 쓰는 값의 문턱, 점수의 문턱)과 코드의 식별자, 도구가 글자 그대로 찾거나 찍는 문구는 바꾸지 않는다. 이 이름들은 용어집에 항목이 없어(앞 PR이 하네스의 말은 운영 문서와 스킬이 정의한다고 보았다) 용어집에 항목을 더하지 않는다. 용어집은 앞 PR의 PR 봇 리뷰가 넘긴 Nit 하나만 고친다. 배포 파일 묶음의 피할 말 "릴리스 자산"을 "GitHub 릴리스 자산"으로 바꿔, 릴리스가 제품 한 벌의 이름이 된 뒤에 GitHub의 게시물은 늘 앞말을 붙인다는 규칙에 맞춘다. 기록(일지, 받은 지시문의 원문, 닫힌 대기열 항목, 끝난 티켓)은 고치지 않는다. 앞 PR의 PR 코멘트에만 있던 사용자의 답(출시 후보의 피할 말에 더한 릴리스 후보를 그대로 둔다)은 이 티켓의 일지에 옮긴다.
