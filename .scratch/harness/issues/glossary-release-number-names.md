# glossary-release-number-names: 릴리스 노트의 "계약의 판" 절과 릴리스 번호를 가리키는 "판"을 "계약 버전"과 "릴리스", "버전"으로 바꾼다

**What to build:** 사용자가 2026-11-18에 용어집의 이름을 agent-os에서 고른 이름과 맞추라는 지시문을 냈고(원문 `.scratch/glossary-names-input.md` 1-2), 그 일은 PR 여럿으로 차례로 한다. 이 티켓은 그 가운데 "릴리스를 가리키는 판" 영역이다. 앞 영역은 헌법 버전(PR 74)과 계약에 붙이는 번호(PR 78, 리뷰 봇 지시문은 PR 79)로 병합되었다. 이 영역의 몫은 PR 78과 PR 79가 "릴리스 영역이 한 번에 맞춘다"고 미뤄 둔 글이다. 지시문 규칙은 번호를 가리키면 "버전", 번호를 붙여 밖에 내놓은 제품 한 벌을 가리키면 "릴리스"다.

**고치는 곳.**
- 릴리스 노트의 절 이름 "계약의 판"이 "계약 버전"이 된다. 노트가 실제로 찍는 제목이 `## 계약의 판`에서 `## 계약 버전`으로 바뀐다. 아직 공개된 릴리스가 없어(릴리스 워크플로는 PR 83으로 막 들어왔고 dev를 main에 올리는 출시 PR 전이다) 이미 나간 노트와 어긋나지 않는다. `tools/release.py`(독스트링, 오류 문구, 도움말, 제목), `tests/tools/test_release.py`(시험 이름 여섯과 문구, 파일 이름 `계약의_판.txt`), `tests/tools/test_release_workflow.py`(시험 이름 하나와 "판 내기"를 쓴 독스트링), `.github/workflows/release.yml` 241행 주석, `src/rag_engine/main.py` 41행 주석.
- 서버가 보이는 번호의 자리 이름. "API 문서의 판 칸"과 "MCP 서버 정보의 판"이 "버전 칸"과 "버전"이 된다. `src/rag_engine/adapters/release_number.py`의 독스트링과 `tests/server/test_release_number.py`의 독스트링과 시험 이름 둘.
- 릴리스 워크플로의 단계 이름 셋. `지난 판의 공개 릴리스 확인`은 `지난 릴리스의 GitHub 릴리스 확인`, `판 없음 알림`은 `릴리스 없음 알림`, `이미 공개된 판`은 `이미 공개된 릴리스`가 된다(`release.yml` 93, 113, 405행). 이 이름들은 `gh run view --json jobs`의 `steps[].name`으로 읽히므로 운영 문서의 표와 설명도 같이 맞춘다. agent-os ADR 0056 결정 이름("판마다 나오는 것", "판 내기의 차례와 실패")은 남의 문서 제목이라 따옴표 인용 그대로 둔다. `release.yml` 442행의 오류 문구가 인용한 결정 이름도 그대로다.
- 번호 도구의 문구. `tools/release_ci.py` 256행 오류 문구 "앞 실행이 번호 태그를 붙인 판일 수 있어"는 "릴리스일 수 있어"가 된다. `tests/tools/test_release_ci.py`의 시험 이름 `test_받은_파일의_판_번호가_다르면_실패한다`는 `…_파일의_릴리스_번호가_…`가 된다(release.json의 `number`가 다른 경우).
- 이 PR 전에 이미 바뀐 줄에 PR 80이 다시 들여온 계약 번호 판. `.github/PULL_REQUEST_TEMPLATE.md` 36행 "계약의 판에서 앞자리를 올렸다"는 "계약 버전에서"로, `tools/check_notes.py` 84행 독스트링의 "계약의 판에서"는 "계약 버전에서"로 바뀐다. 두 줄 모두 PR 78 뒤에 PR 80이 새로 쓴 글이다.
- 운영자가 읽는 글. `README.md`의 "## 판" 제목과 9행("이 서버의 판은 semver다 … 첫 공개 판 0.1 전에는")이 "## 릴리스 번호", "이 서버의 릴리스 번호", "첫 릴리스"로 바뀐다. 용어집이 서버에 붙이는 번호를 "릴리스 번호"로 가르고 릴리스의 피할 말에 "버전"을 적었기 때문이고, "공개 릴리스"는 용어집에 없는 말이라 쓰지 않는다. `docs/release-notes/intro/0.1.0.md` 1행의 "0.1.0은 첫 공개 판이고"는 "첫 정식 릴리스이고"가 된다(0.1.0은 출시 후보 `0.1.0-rc.N`이 아닌 정식 릴리스다).
- 헌법 `docs/constitution/operations.md`(사용자 승인, 아래 `## Comments`). 31행의 노트 절 차례와 절 이름 "계약의 판"(둘), 47·48·60행의 단계 이름 셋, 80행의 "단계 이름 가운데 `판`이 든 것은 agent-os의 이름을 그대로 옮긴 것이다"(단계 이름에 더는 판이 없으므로 "agent-os의 이름에서 판을 릴리스로 바꾼 것"이라는 말로 바뀐다). 66행과 75행의 결정 이름 인용은 그대로다. 규칙은 그대로이고 낱말만 바뀌는 문구 수정이라 헌법 버전은 1.5.5에서 1.5.6(patch)으로 오른다. 올리는 까닭은 ADR 0016의 이력에 쌓고 `docs/constitution/README.md`의 `Version`을 맞춘다. 형제가 쓴 가장 높은 헌법 버전은 `origin/dev`의 1.5.5다(`tools/sibling_overlap.py`).
- 아직 시작하지 않은 계획 `.scratch/diag-bundle/plan.md`(1, 5, 7행). 진단 묶음이 싣는 "판"은 릴리스 번호와 계약 버전이므로 그렇게 고친다.
- ADR 0020의 `## 이력`에 항목 하나를 더해 본문의 "제품 판", "계약의 판", "판 태그" 같은 옛 말을 새 이름으로 읽게 한다. 본문은 고치지 않는다.

**이번에 바꾸지 않는 것.**
- 기록. 일지, ADR 본문, 끝난 기능의 명세·티켓·프로브(`core`, `search-eval`, `dev-branch`와 오늘 2026-11-20에 `끝:` 줄이 선 `release-image`), 병합된 티켓, 닫힌 항목, `.scratch/glossary-names-input.md`, `.scratch/kickoff-input.md`. `release-image`는 PR 78이 이 영역에 맡길 때는 진행 중이었으나 PR 83으로 마지막 티켓이 닫혀 기록이 되었으므로, 같은 규칙으로 명세와 티켓을 고치지 않는다(명세가 적은 절 이름 "계약의 판"은 그 시점의 이름이고 ADR 0020 이력이 새 이름을 알린다).
- 라이브러리·액션·이미지·엔진의 버전을 뜻하는 판(release.yml의 액션 "최신 판", 줄 끝 `# 판` 주석, Grype·Syft·TEI·nginx 판, Docker 엔진 판, 최소 판, 오래된 TLS 판). 번호를 가리키지만 홀로 쓰인 판의 영역이 가른다.
- 평가 묶음과 추론 기록의 `format_version`, 판정 지시문의 판, alembic 개정을 뜻하는 판, 색인 판 계열(색인 판, 현재 판, 스키마 판, 토크나이저 판 따위).
- "판단", "판정" 같은 낱말의 일부.
- 코드의 식별자, 설정 키, API의 칸 이름, 파일 이름. 시험 파일에 쓰는 임시 파일 이름 `계약의_판.txt`는 식별자가 아니라 시험이 만드는 값이라 바꾼다.
- agent-os ADR 0056의 결정 이름 인용.
