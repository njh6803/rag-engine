# glossary-principal-to-requester: 용어집의 "주체"를 agent-os의 결정에 맞춰 "요청자"로 바꾼다

**What to build:** 사용자가 2026-11-18에 이름을 agent-os에서 고른 이름과 맞추라는 지시문을 냈다(원문 `.scratch/glossary-names-input.md`). 그 일은 PR 여럿으로 차례로 하고, 이 티켓은 지시문 5-2의 차례 2다. 앞의 두 PR(`glossary-release-names`, `glossary-harness-small-names`)이 병합되어 밖에 내놓는 제품의 이름과 작은 하네스 이름 셋은 끝났다. 이 PR은 용어집의 "주체"(검색을 요청한 쪽이 누구인지 알리는 신원 정보)를 "요청자"로, "익명 주체"를 "익명 요청자"로 바꾼다. 지시문 1-3이 정한 이름이고 사용자가 agent-os에서 이미 골랐으므로 이름은 다시 묻지 않는다. 용어집의 피할 말(사용자, 유저, 계정)은 그대로 두고 옛 이름 "주체"를 바꾼 날짜와 함께 더한다. 살아 있는 글(용어집, 기능 계획 `doc-permission`, 에이전트와 PR 템플릿과 CodeRabbit 설정의 지침 문장, 열린 대기열 항목)의 같은 말을 맞춘다. "주체"는 헌법 원칙 III과 V의 본문과 `docs/PRD.md`의 1.0 목표 한 줄에도 쓰여 있다. 헌법과 PRD의 문구는 사용자 승인으로만 고치므로 선택 화면으로 물었고, 사용자가 "바꾼다, 헌법 버전 1.3.7"을 골랐다. 그래서 두 곳의 "주체"를 "요청자"로 바꾸고 헌법의 버전을 1.3.6에서 1.3.7로 올린다(문구 수정). 바꾼 까닭은 "주체"가 본문에 든 ADR 0014의 이력에 한 항목으로 남긴다. ADR 0014의 본문과 결정 제목은 그대로다. 코드의 식별자와, 요청자를 실어 보내는 MCP `_meta`의 칸 이름(프로브가 쓴 `principal`이 있고 정식 이름과 모양은 1.0 기능의 설계가 정한다)은 바꾸지 않는다. 기록(일지, 받은 지시문의 원문, 킥오프 입력, 끝난 기능 `core`의 명세, 끝난 티켓, 닫힌 대기열 항목)은 고치지 않는다. 다른 뜻의 "주체"("유지 주체"처럼 보통 낱말로 쓰인 곳, `evals/`의 법령 본문)도 바꾸지 않는다. `.scratch/plan.md`는 생성 파일이라 `uv run python tools/plan_table.py`로 다시 만든다.
