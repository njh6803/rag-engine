# code-review-transition-crossing: 셀프 리뷰 명세 축 브리프에 상태 전이의 교차·잔류 결함을 밟으라는 한 줄을 더한다

**What to build:** `.claude/skills/code-review/SKILL.md`의 "Spec sub-agent prompt" 절에 조건부 한 줄을 더한다. 본 세션이 명세와 diff를 읽고 명세나 이 변경이 상태(문서 상태, 색인 상태, 작업, 임대, 세대, 색인 판처럼 전이하며 값이 바뀌는 것)를 정하거나 바꾼다고 판정하면, 명세 축 브리프 끝에 "전이마다 다른 전이와 동시에 일어나는 교차와, 실패·중단 뒤에 남는 상태를 하나씩 밟아, 지운 것이 되살아나거나 전환이 영영 막히는 자리를 낸다"를 그대로 붙이라고 시킨다. 대기열 항목은 조건을 "명세가 상태를 정하면"으로 적었으나, PR #3은 명세를 쓰는 변경이라 상태를 정한 것이 읽는 명세가 아니라 리뷰 대상 diff였으므로 "명세나 이 변경이"로 넓혔다(셀프 리뷰 표준 축 Major). PR #3의 1회차 봇 지적 열둘 가운데 여덟이 이 꼴(삭제가 커밋된 뒤 실행 중 작업이 조각을 되넣는 길, 판 전환 검사의 경쟁, 영구 실패·재시도 소진·삭제 뒤 `building` 판이 남는 길 등)이었는데, 셀프 리뷰의 명세 축 브리프는 명세와 요구를 대 보는 세 갈래(누락, 범위 넘침, 틀린 구현)뿐이라 전이의 교차를 밟으라는 말이 없었다. 표준 축의 갈래 밟기 문단은 에이전트가 따르는 절차에만 붙으므로 이 꼴을 덮지 못한다. 근거와 회차는 대기열 항목이 든다. 이 티켓은 항목의 내용을 옮기지 않는다. 코드와 시험은 바꾸지 않는다.
