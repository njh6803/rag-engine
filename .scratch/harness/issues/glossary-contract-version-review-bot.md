# glossary-contract-version-review-bot: 리뷰 봇 지시문의 계약 번호 "판" 둘을 "계약 버전"으로 바꾼다

**What to build:** 사용자가 2026-11-18에 용어집의 이름을 agent-os에서 고른 이름과 맞추라는 지시문을 냈고(원문 `.scratch/glossary-names-input.md`), 그 일은 PR 여럿으로 차례로 한다. 이 티켓은 둘째 영역(계약에 붙이는 번호 "판"을 "계약 버전"으로)에서 남은 한 곳이다. 둘째 영역은 PR 78로 병합되었고, `.github/workflows/claude-code-review.yml` 78행의 두 구절만 남았다. 그 파일을 바꾼 PR은 같은 파일의 가드(93행에서 시작하는 `Fail when Claude left no comment` 스텝. 이 파일을 바꾼 PR을 가르는 분기는 114~127행)가 일지·대기열·티켓·하네스 탐침 밖의 파일을 함께 실으면 실패시키므로 따로 PR로 낸다(PR 78이 그 가드 때문에 이 파일을 되돌렸다).

**고치는 곳.** `.github/workflows/claude-code-review.yml` 78행(리뷰 봇에게 주는 지시문의 3번 절차)의 두 구절. 규칙은 그대로이고 낱말만 바뀐다.
- "계약이 바뀌었는데 판, 계약 시험(tests/contract/), ADR, 명세가 같이 바뀌었는지(원칙 VII)" → "계약이 바뀌었는데 계약 버전, 계약 시험(tests/contract/), ADR, 명세가 같이 바뀌었는지(원칙 VII)".
- "재색인이 필요해지는 변경이나 계약의 판에서 앞자리를 올리는 변경처럼" → "재색인이 필요해지는 변경이나 계약 버전에서 앞자리를 올리는 변경처럼". 이 구절은 `docs/constitution/operations.md` 39행의 느낌표 기준 한 줄("계약 버전에서 앞자리를 올리는 변경(원칙 VII)")과 같은 말이어야 한다.

**이번에 바꾸지 않는 것.**
- 같은 파일의 21행("판은 손으로 올린다"), 87행("액션을 올려 판이 바뀌면")의 "판". 외부 액션의 버전이라 계약 번호가 아니다. 앞의 일을 맡은 영역(파일이나 도구의 사본·개정, 라이브러리 판)이 가른다.
- "판단" 안의 글자(이 파일에서 "판"을 찍으면 75, 77, 78행에 나온다).
- 릴리스 노트의 절 이름 "계약의 판"과 릴리스 번호를 가리키는 판, `format_version`, 색인 판 계열. 다음 영역들이 맡는다.
- 이 파일을 설명하는 다른 문서(PR 서식, `operations.md`)는 PR 78이 이미 맞췄다. 이 PR은 허용 경로 밖의 파일을 싣지 않는다.
