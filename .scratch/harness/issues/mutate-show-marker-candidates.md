# mutate-show-marker-candidates: `tools/mutate.py`가 어긋난 변이의 실패 출력 전체를 파일로 남겨 표지를 한 번에 고르게 한다

**What to build:** 변이 표의 `expect_output` 표지는 실제 실패 출력에 있어야 하는데, 출력은 변이를 돌려야 나온다. 어긋난 변이의 출력은 지금 끝 열 줄과 머리 줄 스무 줄만 화면에 나와서, 표지가 될 만한 줄(예: 단언 메시지, 원인 문구)이 가려질 때가 많다. 그러면 세션은 보이지 않는 줄을 보려고 변이를 소스에 손으로 넣어 그 시험만 돌리거나, 임시 표지를 넣어 일부러 어긋나게 해 표를 한 번 더 돌린다(대기열 항목 `mutate-marker-discovery`의 11회차 사건). 이 티켓은 어긋난 변이마다 그 실패 출력의 전체를 파일 하나로 남기고, 화면에는 그 경로를 한 줄로 알린다. 세션이 그 파일을 Grep으로 열면 표지 후보를 모두 보고 한 번에 고른다.

**처방 하나만 고른 까닭.** 항목의 `어디로`는 어긋난 변이의 실패 출력 전체를 스크래치 파일로 남기는 것과, 선택 인자 하나로 표지 후보가 될 단언 풀이 줄을 모두 보여 주는 것 둘 가운데 하나다. 파일로 남기는 쪽을 고른다. 단언 풀이 줄(`E  assert …`)은 pytest만의 모양이고, 파일이면 vitest·playwright·tsc·exit 어느 판정의 출력도 같은 길로 읽힌다. 게다가 새 선택 인자를 더하면 `_parse`의 아는 선택 목록, 사용 줄, 독스트링의 인자 설명이 모두 늘어난다.

**동작.**
- `measure`가 어긋난 변이(`_matched`가 거짓)마다, 기대와 어긋난 마지막 반복의 색 코드를 벗긴 전체 출력(`CommandResult.plain`)을 UTF-8 파일에 쓴다.
- 파일 자리는 그 체크아웃의 git 디렉터리 아래 `mutate-output/<표 파일 이름의 stem>-<번호>.txt`다(`git_dir_of`). git 디렉터리는 추적하지 않는 자리라 `git status`와 편집 훅에 잡히지 않고 `.gitignore`도 필요 없다. 같은 표의 같은 번호는 다시 돌 때 덮어쓴다.
- 화면에는 그 변이의 세부(`_details`) 끝에 `   전체 출력: <경로>` 한 줄을 더한다. 기존 줄(`표지 없음`, 머리 줄, 끝 열 줄)은 그대로다.
- git 디렉터리를 찾지 못하거나 쓰지 못하면(`OSError`) 파일 없이 지금처럼 돈다. 변이를 되돌리는 일과 종료 코드는 달라지지 않는다.
- 표지를 고를 출력이 필요한 변이도 파일을 남긴다. 빨강이나 처리하지 않은 에러를 기대하는데 `expect_output`이 비어 있는 변이는 기대대로 빨개져 어긋나지 않으므로, 어긋난 것만 남기면 세션이 자리표 표지(어느 출력에도 없을 문구)를 넣고 한 바퀴를 더 돌아야 한다. 그래서 이런 변이는 기대대로여도 마지막 반복의 전체 출력을 남기고 같은 `전체 출력:` 줄을 낸다. 표지가 있는 기대대로의 변이와 초록을 기대한 변이는 남기지 않는다.

**고치는 곳.** `tools/mutate.py`(`measure`의 인자 하나, `_run_table`이 그 인자를 넘김, 출력을 쓰는 함수 하나, 모듈 독스트링의 표지 절에 이 동작과 못 보는 것), `tests/tools/test_mutate.py`.

**이번에 바꾸지 않는 것.**
- 표지 후보를 골라 주는 일. 파일 전체를 보여 줄 뿐, 어느 줄이 좋은 표지인지는 가르지 않는다(표지의 품질 검사가 그대로 거른다).
- 새 선택 인자.
- 기준선이 빨갛거나 오류인 출력의 파일. 기준선은 화면에 이미 끝 열 줄과 머리 줄이 나오고, 어긋난 변이의 표지를 고르는 일이 이 티켓의 대상이다.
