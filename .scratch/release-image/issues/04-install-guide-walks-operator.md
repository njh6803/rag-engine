  - 받는 기계의 일: 이미지 다섯을 `docker save`로 한 파일에 담는 데 48초, 파일은 약 1.6GiB였다. 모델 폴더(임베딩과 리랭커 합 8.6GiB)를 `tar`로 묶는 데 압축 없이 57초에 8.5GiB, `z`를 더하면 29분 26초에 5.0GiB였다. 안내에 두 값을 싣고 필요할 때만 `z`를 더하라고 적었다.
  - 싣는 기계 흉내: 시험 설치를 볼륨째 내리고 이미지의 이름을 지운 뒤 새 폴더에 묶음을 풀었다. 모델 풀기 45초, `sha256sum -c`, `docker load -i`, 이미지 ID 대조(`같다`가 찍혔다), `compose.override.yaml`, `docker compose up -d --wait --wait-timeout 1800 --pull never`로 74초에 떴고, 첫 토큰과 문서 넣기와 MCP 검색이 되었다.
  - 명세가 다시 판단하라고 한 것: `docker load` 뒤 digest로 고정한 바깥 이미지가 이름 없이 올라오는 일이 있었다(nginx에서 `RepoTags`와 `RepoDigests`가 비었다. 고전 `overlay2` 저장소). 그래서 digest 참조에 기대지 않고 로컬 이름(`rag-engine-offline/<nginx|pgvector|tei>:<digest 앞 12자>`)을 다시 붙이고 `compose.override.yaml`로 그 이름을 쓰게 하는 길을 안내에 정했다. 이 길은 이름이 사라지든 남든 같은 명령이 든다.
  - 못 흉내 낸 것: 이 PC는 인터넷이 열려 있어 `--pull never`로 받기를 막았을 뿐 바깥으로 나가는 길이 정말 없는 기계가 아니다. 빈 폴더에서 폐쇄망 서버가 모델을 받으러 나가다 멈추는 길(안내는 "재지 않은 어림"이라고 적었다), containerd 이미지 저장소, 리눅스의 파일 소유와 `sudo tar`, TEI·pgvector 이미지의 이름 사라짐(다른 컨테이너가 쥐고 있어 지우지 못했다)은 재지 않았다.
- **Compose 2.20.2(최소 판)와 Engine 28.3.3.** 재지 못했다. 03의 Comments와 같은 까닭이다(2.20.2의 실행 파일은 파일을 받는 일이라 사용자 허락이 있어야 하는데 받지 않았다). 안내 머리는 "최소 판에서는 재지 않았다"를 그대로 둔다.
- **Windows 대체와 경로.** `sudo chown`·`sudo tar`는 이 PC에 없어 건너뛰거나 `sudo` 없이 쳤다. 모델 폴더의 심볼릭 링크를 Docker Desktop 바인드 마운트가 못 만들어, 단독 compose 시험과 폐쇄망 흉내에는 `cp -rL`로 링크를 푼 평평한 복사본을 썼다(03의 Comments와 같은 처치). MSYS 셸에서는 `MSYS_NO_PATHCONV=1`과 `C:/…` 경로를 써야 컨테이너 경로가 바뀌지 않았다.

- **정합 시험(`tests/tools/test_deploy_guide.py`).** 14개 통과(`14 passed in 0.40s`). 저장소 상태 시험(`test_이_저장소의_…`)과 변이 시험(`test_…을_잡는다`)을 짝으로 두었다. 정합 검사 여덟(인증서 이름, 프록시 주 설정, 환경 변수 칸, 소유, 리비전, 폴더 설명, 고치지 말 것, 대응표)은 `묶음_파일` 값 하나를 읽어 대고, 변이 시험이 칸마다 한 군데를 바꾼 사본을 만들어 같은 이름의 검사가 걸리는지 본다. 폐쇄망 `compose.override.yaml`의 서비스와 로컬 이름의 짝맞춤도 변이 사례를 갖는다. 03의 시험이 한 자리에 둔 명령(띄우는 명령, 인증서를 만드는 명령, 모델 폴더의 명령)과 안내의 명령이 같은지 본다. agent-os 배치의 낱말(위젯 설정, IPv4 레코드)은 이 저장소에 없어 뺐고, 시험의 머리 독스트링에 적었다.
- **`/code-review` 두 축(기준 `origin/dev`)과 반영.** 표준 축은 상태 시험에 변이 짝이 없는 것을 Major로, 명세 축은 필수 낱말과 오버라이드 짝맞춤의 시험 틈을 짚었다. 둘 다 고쳤다(위 정합 시험의 모양). 안내의 문장은 지적마다 근거를 열어 고쳤다. 고친 것: 리랭커 프로필을 "빼는" 표현을 "관찰한 것"으로, `docker compose ps`가 migrate를 가리는 것, 메모리 값과 다시 잰 값, 키 권한 종료 코드, 모델 폴더가 끊긴 채 옮겼을 때의 추측, containerd 표현, 단위. 남긴 것은 아래 "남긴 것"에 적는다.
- **PR 직전 리뷰(`coderabbit-review`, CLI 0.7.5, 기준 `origin/dev`를 합친 뒤, 파일 7개).** `Plan: Free`, `Seat: not assigned`였지만 `review_completed`까지 돌았다. 지적 셋이 모두 유효였다. 고쳤다: ① `cp -r proxy proxy.old`는 `proxy.old`가 이미 있으면 그 안으로 들어가므로 복사 전에 `rm -rf proxy.old`를 더했다(에이전트가 임시 폴더에서 재현했다). ② 폐쇄망 설치의 되돌리기가 `compose.override.yaml`을 복원하지 않던 것을 백업(`compose.override.yaml.old`)과 복원 안내로 고쳤다. 이 복원은 개발 PC에서 치지 못했다고 안내에 적었다. ③ `sudo tar`의 만들기와 풀기에 `--numeric-owner`를 더했다. 이 PC의 GNU `tar`에서 `sudo` 없이 만들기와 풀기 모두 도는 것을 보았다. 시험은 훑은 범위가 비면 실패하는 단언(대응표의 서비스 집합, 폐쇄망 override의 서비스 넷)과 변이 사례 셋(임베딩 소유, 키 파일 이름과 `tls/` 마운트, 모델 폴더 설명의 낱말)을 더했고, 필수 낱말에 새 안내 문구 셋을 더했다. 사실 문장 여섯(한 트랜잭션, 프록시를 다시 만들지 않음, 리랭커 프로필, 키 소유, `config --images`, 변이 시험)은 에이전트가 코드와 대 보고 모두 맞다고 했다.
