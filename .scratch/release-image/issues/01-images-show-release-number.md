# 01: 검색 서버와 작업자의 이미지가 `deploy/images/`에서 지어지고 세 자리에 같은 릴리스 번호를 보인다

**What to build:** 검색 서버 이미지와 작업자 이미지를 `deploy/images/`의 Dockerfile 하나와 bake 설정(Docker의 `buildx bake`가 읽는, 이미지 여럿을 한 번에 짓는 목록)으로 짓는다. 두 이미지는 내용물이 같고 시작 명령만 다르며, root가 아닌 사용자로 돈다. 짓는 사람이 넘긴 릴리스 번호(밖에 내놓는 이미지와 배포 파일 묶음에 붙는 번호)가 `rag-engine --version`, 서버가 만드는 API 문서의 판 칸, MCP 클라이언트가 접속할 때 받는 서버 정보(`serverInfo.version`) 세 자리에 똑같이 보인다. `--version`은 그 릴리스에 든 계약의 판도 한 줄씩 찍고, 데이터베이스 주소 같은 설정이 없어도 돈다. `ci.yml`의 `image` 잡은 모든 PR에서 이미지 둘을 bake로 짓고 서버 이미지가 `/health`에 답하는지와 두 이미지의 `--version`을 본다(스토리 1, 29, 30, 38, 39, 46, 53).

근거는 명세 "저장소의 자리"의 이미지 항목, "이미지와 계정"의 bake 설정과 라벨 항목, "이미지의 구성", "번호가 보이는 자리", "ci.yml"의 `image` 잡 항목, "규약 문서와 낡은 문장"의 루트 Dockerfile 항목 둘, Testing Decisions의 번호가 보이는 자리의 시험이다. 시제품은 `.scratch/release-image/probes/standalone/Dockerfile`이고, 그 프로브의 `build`·`checks` 단계가 잰 것을 명세가 든다(같은 폴더 README 표).

**Blocked by:** 06 (헌법을 바꾸는 티켓은 그 기능의 첫 티켓이며 다른 티켓을 막는다. `docs/agents/issue-tracker.md`의 티켓 규약이고, 사용자가 2026-11-18에 이 차례를 골랐다)

- [ ] 루트의 Dockerfile과 `.dockerignore`를 `deploy/images/`로 옮기고 루트에 남기지 않는다. 무시 파일은 BuildKit(Docker가 이미지를 짓는 엔진)이 Dockerfile 이름 뒤에 `.dockerignore`를 붙여 찾는 이름으로 두고, 빌드 컨텍스트는 저장소 루트다. agent-os 커밋 `1aac0cf`의 `deploy/images/serve.Dockerfile`과 `docker-bake.hcl`을 복사해 이 저장소의 값으로 고친다.
- [ ] Dockerfile은 두 단계다. 빌드 단계는 uv로 잠금 파일대로 운영 의존성만 깔고(`--locked --no-dev`), 번호를 넣은 프로젝트를 편집 가능하지 않은 꼴로 깐다. 실행 단계는 빌드 단계의 가상 환경만 복사하고, init 프로세스(컨테이너의 1번 프로세스로 돌며 종료 신호를 앱에 넘기는 작은 프로그램)로 `tini`를 진입점에 두며, uid·gid 10001의 사용자 `rag`로 돌고 `/data`를 그 사용자의 것으로 만든다. 서버는 `rag-engine serve --host 0.0.0.0 --port 8000`, 작업자는 `rag-engine worker`로 시작한다. 헬스체크는 Dockerfile에 두지 않는다(03의 단독 compose가 둔다).
- [ ] 바탕 이미지 `python:3.12-slim`과 uv 이미지 `ghcr.io/astral-sh/uv:0.10.8`은 태그에 digest(이미지 내용에서 계산한 고유 값)를 붙여 고정한다. 값은 이 티켓을 하는 날 받은 digest이고, 읽은 명령과 출력을 `## Comments`에 적는다. 명세를 쓴 세션은 두 digest를 읽지 못했다(명세 "이미지의 구성").
- [ ] 번호는 빌드 인자 `APP_VERSION`으로만 받는다. 빠지거나 꼴(`X.Y.Z`나 `X.Y.Z-rc.N`)이 틀리면 짓기가 실패하고, 빌드 단계 안의 `pyproject.toml` 사본에서만 `version`을 바꾼 뒤 깐다. 깐 뒤 설치된 패키지의 번호가 인자와 같은지 대조한다. 저장소의 `version`은 `0.0.0` 그대로다. 번호 없이, 틀린 꼴로, 맞는 꼴로 지어 본 결과(종료 코드와 문구)를 Comments에 적는다.
- [ ] bake 설정의 대상 이름은 `server`와 `worker`이고, 두 대상은 같은 Dockerfile의 두 단계를 짓는다. 변수는 agent-os와 같은 다섯(`NAMESPACE`, `TAG`, `VERSION`, `REVISION`, `SOURCE`)이고 `VERSION`은 `APP_VERSION`으로 넘긴다. 이미지에는 OCI 라벨(컨테이너 이미지 표준이 정한 이름표) 셋, `org.opencontainers.image.version`·`revision`·`source`를 단다. 이미지 이름은 Docker Hub의 `<이름공간>/rag-engine-server`와 `<이름공간>/rag-engine-worker`다.

- [ ] 실패하는 시험을 먼저 쓴다. `rag-engine --version`이 필수 설정(데이터베이스 주소, 허용 호스트, 임베딩 서버 주소) 없이 종료 코드 0으로 끝나고, 첫 줄이 설치된 패키지의 번호(`importlib.metadata`)로 된 `rag-engine <번호>`이며, 이어서 계약마다 `<계약의 이름> <판>`을 한 줄씩 찍는지 본다. 계약은 검색 도구의 형식(지금 `1.1.0`), 수집 API와 관리 API의 경로에 든 판(`v1`), 파서 인터페이스(`1.0.0`), 색인 형식의 스키마 판(`1`)이다. 줄의 꼴은 08이 릴리스 노트의 "계약의 판" 절로 그대로 옮기는 사람이 읽는 글이다. 판의 값은 그 계약을 정한 코드의 값을 읽는다. 같은 판을 두 자리에 적으면 계약의 판을 올릴 때 한쪽이 남는다. 선례는 `tests/test_serve_command.py`다.
