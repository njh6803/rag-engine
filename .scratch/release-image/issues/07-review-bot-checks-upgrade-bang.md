# 07: 리뷰 봇이 PR의 변경과 제목의 느낌표가 맞는지 본다

**What to build:** 티켓 PR이 열리면 리뷰 봇(claude-review)이, 변경이 운영자가 업그레이드할 때 손댈 것을 만드는데 PR 제목의 접두에 느낌표가 없거나 그 반대이면 그것을 짚는다. 노트 검사(05)는 느낌표와 업그레이드 원고의 짝과 마이그레이션 파일만 보고, 재색인이 필요해지는 변경이나 계약의 앞자리를 올리는 변경처럼 기계가 알아보지 못하는 것은 보지 못한다(스토리 47, 48의 빈틈). 판단의 기준은 06이 운영 문서에 적은 느낌표의 기준이다.

리뷰 봇의 워크플로(`.github/workflows/claude-code-review.yml`)를 고친 PR은 리뷰가 건너뛰어지고, 그 워크플로의 가드 스텝이 기록(일지, 대기열, 티켓 파일, harness 프로브) 밖의 파일을 함께 싣는 것을 거부한다. 그래서 프롬프트 줄을 따로 티켓 하나로 낸다(명세 "PR 서식, 노트 검사, 검사 러너"의 리뷰 봇 프롬프트 항목, ADR 0016 "전환의 차례" 2). agent-os 커밋 `1aac0cf`의 release-image 티켓 06과 같은 일이다.

근거는 명세 "PR 서식, 노트 검사, 검사 러너"의 리뷰 봇 항목, "번호와 느낌표"의 재색인과 계약의 앞자리 항목, "티켓을 나눌 때 함께 둘 것"의 리뷰 봇 프롬프트 줄이다.

**Blocked by:** 06 (운영 문서의 느낌표의 기준)

**Status:** ready-for-agent

- [ ] 리뷰 봇의 프롬프트에, 변경과 PR 제목 접두의 느낌표가 맞는지 운영 문서(`docs/constitution/operations.md`)의 느낌표의 기준으로 보라는 줄을 더한다. 기준을 프롬프트에 다시 적지 않고 그 문서의 절을 가리킨다(같은 사실은 한 곳에만 둔다). 출시 PR과 운영에서 개발로 합치기 PR은 이 판단에서 면제된다는 것도 같은 문서를 따른다.
- [ ] 이 PR은 그 워크플로 파일, 이 티켓 파일, 일지만 싣는다. 티켓의 상태를 바꿔도 전체 계획 표(`.scratch/plan.md`)가 바뀌지 않는지 `uv run python tools/plan_table.py` 뒤의 diff로 본다. 바뀌면 가드가 거부하므로 멈추고 보고한다.
- [ ] 워크플로의 보안 약점을 찾는 감사 도구(zizmor)를 지난다.
- [ ] 이 PR에서는 리뷰가 건너뛰어지므로 셀프 리뷰와 PR 직전 리뷰가 이 변경의 유일한 리뷰다. 병합한 세션은, 다음으로 열리는 티켓 PR에서 리뷰 봇이 느낌표를 판정하는 줄을 내는지 그 PR의 세션이 일지에 적도록 다음 지시문에 넘긴다.
- [ ] 검사 넷이 초록이다.
